18  The Chain Rule and Backpropagation

NoteKey ideas
  • A model is a composition of simple functions. The chain rule gives the derivative of a composition.
  • A computational graph records the composition. Each node has a simple local derivative.
  • Backpropagation applies the chain rule from the loss backward through the graph. It reuses each partial result.
  • One forward pass and one backward pass give the gradient for all parameters. The cost is about three forward passes, not one per parameter.
  • Backpropagation can fail in a predictable way: gradients shrink (vanish) or grow (explode) with depth.

18.1 The system problem

In Chapter 1, a model had two parameters. We computed two derivatives by hand. A modern model has billions of parameters. We cannot write each derivative by hand. We also cannot afford to measure each one by trial.

The learning loop needs one thing from this chapter:

How can we compute \(\partial L / \partial \theta_i\) for every parameter \(\theta_i\), quickly and exactly?

The answer is the chain rule applied in a clever order. This algorithm is called backpropagation. It is the computational engine of almost all modern AI.

NoteRecall from Chapters 16 and 17
  • The derivative \(f'(x)\) is the slope of \(f\). Near \(x\), \(f(x+h)\approx f(x)+f'(x)h\) (Equation 16.2 of Chapter 16).
  • A partial derivative \(\partial L/\partial\theta_i\) is the sensitivity of the loss to one parameter, with the others held fixed.
  • The gradient \(\nabla_\theta L\) collects all partial derivatives. It points in the direction of steepest increase (Chapter 17).
  • The Jacobian of a vector function is the matrix of its partial derivatives. The Jacobian of a composition is the product of Jacobians.

This chapter shows how to compute \(\nabla_\theta L\) for a deep network in one backward pass.

18.2 Intuition: sensitivity flows backward

Think of a row of three gears. Turn the first gear by a small amount. The second gear turns by a fixed multiple of that. The third gear turns by a fixed multiple of the second. The total effect is the product of the multiples.

This is the chain rule. If \(y\) depends on \(u\), and \(u\) depends on \(x\):

\[ \frac{dy}{dx} = \frac{dy}{du} \cdot \frac{du}{dx} \tag{18.1}\]

Each factor is a local quantity. It depends only on one step. The global derivative is the product of local ones.

A model is a long chain of such steps. To find how the last output depends on a parameter early in the chain, multiply the local factors along the way. The efficient method starts at the output and moves backward. At each step it keeps the running product.

18.3 The mathematical object

18.3.1 Single variable

Take \(f(x) = (3x + 1)^2\). Write it as a chain: \(u = 3x + 1\), then \(y = u^2\).

\[ \frac{du}{dx} = 3, \qquad \frac{dy}{du} = 2u \quad\Rightarrow\quad \frac{dy}{dx} = 2u \cdot 3 = 6(3x+1). \]

18.3.2 Many variables

A parameter can affect the loss through more than one path. The multivariable chain rule says: add the contributions of all paths.

If \(L\) depends on \(x\) through intermediate values \(u_1, \dots, u_m\):

\[ \frac{\partial L}{\partial x} = \sum_{j=1}^{m} \frac{\partial L}{\partial u_j} \, \frac{\partial u_j}{\partial x} \tag{18.2}\]

Two rules summarize it.

  1. Along a path: multiply the local derivatives.
  2. Across paths: add the path results.

18.3.3 The computational graph

A computational graph writes a calculation as nodes and arrows. Each node is one simple operation. Each arrow shows which values feed which operation.

Take the squared error of a one-weight model:

\[ L = (w x + b - y)^2 \tag{18.3}\]

We split it into four simple steps:

Step Operation Value for \(w{=}2,\ x{=}3,\ b{=}1,\ y{=}5\)
\(p = w x\) multiply 6
\(s = p + b\) add 7
\(e = s - y\) subtract 2
\(L = e^2\) square 4

We run the graph forward to get the values. Then we run it backward to get the gradients. The backward pass starts with \(\partial L / \partial L = 1\) and applies one local rule per node.

18.4 Operations: local derivatives

A graph needs only a small table of local rules. Each rule says how the node output changes when one input changes. Everything in a neural network is built from this table.

Operation Forward Local derivative(s)
Add \(c = a + b\) \(\partial c/\partial a = 1,\ \partial c/\partial b = 1\)
Subtract \(c = a - b\) \(1,\ -1\)
Multiply \(c = a\,b\) \(\partial c/\partial a = b,\ \partial c/\partial b = a\)
Square \(c = a^2\) \(2a\)
Tanh \(c = \tanh a\) \(1 - c^2\)
Sigmoid \(c = \sigma(a)\) \(c\,(1 - c)\)
ReLU \(c = \max(0, a)\) \(1\) if \(a > 0\), else \(0\)

In backpropagation, each node receives the gradient of the loss with respect to its output, called the upstream gradient. It multiplies by its local derivative to give the gradient with respect to its input.

\[ \underbrace{\frac{\partial L}{\partial a}}_{\text{gradient for input}} = \underbrace{\frac{\partial L}{\partial c}}_{\text{upstream}} \cdot \underbrace{\frac{\partial c}{\partial a}}_{\text{local}} \tag{18.4}\]

18.5 Derivation: backpropagation through a network

Scalars show the idea. Real networks use vectors and matrices. We now derive the rules for a stack of layers. The result is only four lines.

18.5.1 Setup

A network with \(L_n\) layers computes, for layer \(l = 1, \dots, L_n\):

\[ \mathbf{z}_l = \mathbf{W}_l \,\mathbf{a}_{l-1} + \mathbf{b}_l, \qquad \mathbf{a}_l = \sigma(\mathbf{z}_l), \qquad \mathbf{a}_0 = \mathbf{x}. \tag{18.5}\]

The last layer has no activation in this chapter: \(\mathbf{a}_{L_n} = \mathbf{z}_{L_n}\), the output. The loss is a scalar \(L\) of the output.

We define the error signal of layer \(l\) as the gradient of the loss with respect to its pre-activation:

\[ \boldsymbol{\delta}_l \;=\; \frac{\partial L}{\partial \mathbf{z}_l}. \tag{18.6}\]

18.5.2 Step 1: the output layer

The signal at the output is the derivative of the loss with respect to the output. For the squared error \(L = \lVert \mathbf{z}_{L_n} - \mathbf{y} \rVert^2\) it is \(\boldsymbol{\delta}_{L_n} = 2(\mathbf{z}_{L_n} - \mathbf{y})\).

18.5.3 Step 2: from one layer back to the previous one

Take \(\mathbf{z}_l = \mathbf{W}_l \mathbf{a}_{l-1} + \mathbf{b}_l\). A small change of \(\mathbf{a}_{l-1}\) changes \(\mathbf{z}_l\) through \(\mathbf{W}_l\). By the multivariable chain rule (Equation 18.2):

\[ \frac{\partial L}{\partial a_{l-1,i}} = \sum_j \frac{\partial L}{\partial z_{l,j}} \frac{\partial z_{l,j}}{\partial a_{l-1,i}} = \sum_j \delta_{l,j}\, W_{l,ji}. \]

The sum over \(j\) is a product with the transpose of \(\mathbf{W}_l\):

\[ \frac{\partial L}{\partial \mathbf{a}_{l-1}} = \mathbf{W}_l^{\intercal} \boldsymbol{\delta}_l. \tag{18.7}\]

Next we pass the signal through the activation. It acts element by element, so its Jacobian is diagonal. We get an element-wise product, written \(\odot\):

\[ \boldsymbol{\delta}_{l-1} = \bigl(\mathbf{W}_l^{\intercal} \boldsymbol{\delta}_{l}\bigr) \odot \sigma'(\mathbf{z}_{l-1}). \tag{18.8}\]

18.5.4 Step 3: the parameter gradients

The pre-activation \(z_{l,j} = \sum_i W_{l,ji}\, a_{l-1,i} + b_{l,j}\) depends on \(W_{l,ji}\) only through one term. Therefore:

\[ \frac{\partial L}{\partial W_{l,ji}} = \delta_{l,j}\, a_{l-1,i}, \qquad \frac{\partial L}{\partial b_{l,j}} = \delta_{l,j}. \]

In matrix form, the weight gradient is an outer product:

\[ \frac{\partial L}{\partial \mathbf{W}_l} = \boldsymbol{\delta}_l \, \mathbf{a}_{l-1}^{\intercal}, \qquad \frac{\partial L}{\partial \mathbf{b}_l} = \boldsymbol{\delta}_l. \tag{18.9}\]

18.5.5 The algorithm

ImportantBackpropagation

Forward. For \(l = 1 \dots L_n\): compute and store \(\mathbf{z}_l\) and \(\mathbf{a}_l\).

Backward. Start with \(\boldsymbol{\delta}_{L_n}\). For \(l = L_n \dots 1\):

  1. \(\partial L/\partial \mathbf{W}_l = \boldsymbol{\delta}_l \mathbf{a}_{l-1}^{\intercal}\), \(\ \partial L/\partial \mathbf{b}_l = \boldsymbol{\delta}_l\)
  2. \(\boldsymbol{\delta}_{l-1} = (\mathbf{W}_l^{\intercal} \boldsymbol{\delta}_l) \odot \sigma'(\mathbf{z}_{l-1})\)

Two observations explain why this is fast.

  1. The signal \(\boldsymbol{\delta}_l\) is computed once and used for both the parameter gradient and the next signal. Nothing is recomputed.
  2. Each layer needs two matrix products in the backward pass (\(\mathbf{W}^{\intercal}\boldsymbol{\delta}\) and \(\boldsymbol{\delta}\mathbf{a}^{\intercal}\)). The forward pass needs one. So the backward pass costs about twice the forward pass.

18.5.6 Special case: logistic output with cross-entropy

For binary classification, the output \(z\) is a logit. The probability is \(p = \sigma(z)\). The loss for label \(y \in \{0, 1\}\) is \(\ell = -y \ln p - (1-y)\ln(1-p)\).

TipDerivation: the error signal is prediction minus target

Use \(\sigma'(z) = p(1-p)\). Then

\[ \frac{\partial \ell}{\partial z} = \frac{\partial \ell}{\partial p}\,\frac{\partial p}{\partial z} = \left( -\frac{y}{p} + \frac{1-y}{1-p} \right) p(1-p) = -y(1-p) + (1-y)p = p - y. \]

The factors \(p\) and \(1-p\) cancel. The signal is simply prediction minus target. This is the same simple form as for squared error with a linear output. It is not a coincidence. We explain it in Chapter 25.

18.7 Computation: from first principles

We now build backpropagation twice. First as a tiny engine on scalars. Then as a matrix implementation.

18.7.1 A scalar engine in plain Python

The engine stores a value, a gradient, the nodes it came from, and a function that applies its local rule. This is about 45 lines. It is the design idea behind every autodiff library.

import math

class Value:
    def __init__(self, data, parents=()):
        self.data = data
        self.grad = 0.0
        self._parents = parents
        self._backward = lambda: None

    def __add__(self, o):
        o = o if isinstance(o, Value) else Value(o)
        out = Value(self.data + o.data, (self, o))
        def _backward():                       # local rule: 1 and 1
            self.grad += out.grad
            o.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, o):
        o = o if isinstance(o, Value) else Value(o)
        out = Value(self.data * o.data, (self, o))
        def _backward():                       # local rule: other input
            self.grad += o.data * out.grad
            o.grad += self.data * out.grad
        out._backward = _backward
        return out

    def __pow__(self, k):
        out = Value(self.data ** k, (self,))
        def _backward():                       # local rule: k * a^(k-1)
            self.grad += k * self.data ** (k - 1) * out.grad
        out._backward = _backward
        return out

    def tanh(self):
        t = math.tanh(self.data)
        out = Value(t, (self,))
        def _backward():                       # local rule: 1 - t^2
            self.grad += (1 - t ** 2) * out.grad
        out._backward = _backward
        return out

    __radd__ = __add__
    __rmul__ = __mul__
    def __neg__(self): return self * -1
    def __sub__(self, o): return self + (-o)
    def __rsub__(self, o): return (-self) + o

    def backward(self):
        order, seen = [], set()
        def visit(v):                          # topological order
            if v not in seen:
                seen.add(v)
                for p in v._parents:
                    visit(p)
                order.append(v)
        visit(self)
        self.grad = 1.0                        # dL/dL = 1
        for v in reversed(order):              # outputs before inputs
            v._backward()

Note the += in every rule. It implements the “add across paths” rule. A value used twice receives two contributions.

We test the engine on Equation 18.3 and on the fan-out example.

w, x, b, y = Value(2.0), Value(3.0), Value(1.0), Value(5.0)

The values match the hand calculation. The engine knows nothing about this example. It only knows the local rules.

18.7.2 A tiny neural network on the engine

We build a one-neuron “network” and fit it by gradient descent. This is Chapter 1’s loop with backpropagation inside.

rng = np.random.default_rng(0)
xs = rng.uniform(-1, 1, 20)
ys = np.tanh(1.5 * xs - 0.3)                     # target rule

w, b = Value(0.1), Value(0.0)                    # parameters
for step in range(200):
    loss = Value(0.0)
    for xi, yi in zip(xs, ys):
        loss = loss + (( w * xi + b).tanh() - yi) ** 2
    loss = loss * (1 / len(xs))
    w.grad = b.grad = 0.0                        # reset accumulated gradients
    loss.backward()
    w.data -= 0.5 * w.grad                       # update rule
    b.data -= 0.5 * b.grad
print(f"learned w = {w.data:.3f}, b = {b.data:.3f}   (true 1.5, -0.3)")
learned w = 1.500, b = -0.300   (true 1.5, -0.3)
WarningReset the gradients

Because every rule uses +=, gradients accumulate across calls. We must set them to zero before each backward(). Forgetting this is a common bug. PyTorch has the same behavior: you call optimizer.zero_grad().

18.7.3 Matrix backpropagation in NumPy

The scalar engine is clear but slow. Real code uses the matrix rules of Section 18.5. We write the forward and backward pass for a network of any depth. The shape convention follows the book: a batch has shape (N, d), a weight has shape (d_out, d_in).

ACT = {   # name -> (f, derivative expressed with z and a = f(z))
    "tanh":    (np.tanh,                          lambda z, a: 1 - a ** 2),
    "sigmoid": (lambda z: 1 / (1 + np.exp(-z)),   lambda z, a: a * (1 - a)),
    "relu":    (lambda z: np.maximum(0, z),       lambda z, a: (z > 0) * 1.0),
}

def init(sizes, act, rng):
    """Weights ~ N(0, 1/fan_in); He scaling (2/fan_in) for ReLU."""
    gain = 2.0 if act == "relu" else 1.0
    return [(rng.normal(0, np.sqrt(gain / n_in), (n_out, n_in)), np.zeros(n_out))
            for n_in, n_out in zip(sizes[:-1], sizes[1:])]

def forward(params, X, act):
    f, _ = ACT[act]
    cache, a = [], X                                # a: (N, d_in)
    for l, (W, b) in enumerate(params):
        z = a @ W.T + b                             # (N, d_out)
        out = z if l == len(params) - 1 else f(z)   # no activation at the end
        cache.append((a, z, out))
        a = out
    return a, cache

def loss_and_signal(out, y, kind):
    """Return the loss and dL/d(output), averaged over the batch."""
    N = len(y)
    if kind == "mse":
        return np.mean((out - y) ** 2), 2 * (out - y) / N
    p = 1 / (1 + np.exp(-out))                      # "bce": out is a logit
    loss = np.mean(np.logaddexp(0, out) - y * out)  # stable cross-entropy
    return loss, (p - y) / N

def backward(params, cache, delta, act):
    _, df = ACT[act]
    grads = [None] * len(params)
    for l in reversed(range(len(params))):
        a_in, z, a = cache[l]
        if l < len(params) - 1:
            delta = delta * df(z, a)                # through the activation
        grads[l] = (delta.T @ a_in, delta.sum(axis=0))   # dW, db
        delta = delta @ params[l][0]                # through W^T (row form)
    return grads

Check the shapes of delta.T @ a_in: delta is (N, d_out), so delta.T is (d_out, N). With a_in of shape (N, d_in) the result has shape (d_out, d_in), the same as W. The sum over the batch is built into the matrix product.

18.7.4 Gradient checking

We now apply the habit from Chapter 1. We compare backpropagation with finite differences for every parameter.

def flatten(params):
    return np.concatenate([np.concatenate([W.ravel(), b]) for W, b in params])

def loss_at(params, X, y, act, kind):
    out, _ = forward(params, X, act)
    return loss_and_signal(out, y, kind)[0]

def numeric_gradient(params, X, y, act, kind, eps=1e-5):
    g = []
    for W, b in params:
        for arr in (W, b):
            gk = np.zeros_like(arr)
            for idx in np.ndindex(arr.shape):
                old = arr[idx]
                arr[idx] = old + eps; up = loss_at(params, X, y, act, kind)
                arr[idx] = old - eps; dn = loss_at(params, X, y, act, kind)
                arr[idx] = old
                gk[idx] = (up - dn) / (2 * eps)
            g.append(gk.ravel())
    return np.concatenate(g)

rng = np.random.default_rng(0)
X = rng.normal(size=(8, 3))
y = rng.normal(size=(8, 1))
params = init([3, 5, 4, 1], "tanh", rng)

out, cache = forward(params, X, "tanh")
_, delta = loss_and_signal(out, y, "mse")
g_bp = flatten(backward(params, cache, delta, "tanh"))
g_num = numeric_gradient(params, X, y, "tanh", "mse")

rel = np.abs(g_bp - g_num) / (np.abs(g_bp) + np.abs(g_num) + 1e-12)
print("parameters checked:", g_bp.size)
print(f"largest relative error: {rel.max():.2e}")
assert rel.max() < 1e-6
parameters checked: 49
largest relative error: 7.09e-08

Every gradient from backpropagation agrees with the finite-difference estimate. This check is slow, so we use it only for testing. A good habit is to run it on a small network whenever we write new backward code.

18.8 Why backpropagation matters: cost

Finite differences need two forward passes per parameter. Backpropagation needs one forward pass and one backward pass, in total. We measure the difference.

rng = np.random.default_rng(0)
X = rng.normal(size=(64, 10)); y = rng.normal(size=(64, 1))

sizes_P, t_fd, t_bp = [], [], []
for h in [2, 4, 8, 16, 32]:
    params = init([10, h, h, 1], "tanh", rng)
    P = sum(W.size + b.size for W, b in params)

    t0 = time.perf_counter()
    numeric_gradient(params, X, y, "tanh", "mse")
    t_fd.append(time.perf_counter() - t0)

    t0 = time.perf_counter()
    for _ in range(20):                         # repeat: one call is too fast
        out, cache = forward(params, X, "tanh")
        _, delta = loss_and_signal(out, y, "mse")
        backward(params, cache, delta, "tanh")
    t_bp.append((time.perf_counter() - t0) / 20)
    sizes_P.append(P)

fig, ax = plt.subplots()
ax.loglog(sizes_P, t_fd, "o-", color=PALETTE["loss"], label="finite differences")
ax.loglog(sizes_P, t_bp, "o-", color=PALETTE["grad"], label="backpropagation")
ax.set_xlabel("number of parameters $P$"); ax.set_ylabel("seconds per gradient")
ax.legend()
plt.show()
print("speed-up at largest size:", round(t_fd[-1] / t_bp[-1]), "x")
speed-up at largest size: 1564 x

The exact times depend on the computer. The trend does not. Finite differences cost \(O(P)\) forward passes. Backpropagation costs \(O(1)\) passes, a small constant. The speed-up is about \(P\).

18.9 Training a network

We now use the engine for a real task: separate two interleaved half-circles. A straight line cannot do this. A network with a hidden layer can.

from sklearn.datasets import make_moons
Xm, ym = make_moons(n_samples=300, noise=0.15, random_state=0)
ym = ym.reshape(-1, 1).astype(float)                  # (300, 1)

rng = np.random.default_rng(1)
params = init([2, 16, 16, 1], "tanh", rng)
history, lr = [], 0.5
for step in range(1500):
    out, cache = forward(params, Xm, "tanh")
    loss, delta = loss_and_signal(out, ym, "bce")
    grads = backward(params, cache, delta, "tanh")
    params = [(W - lr * dW, b - lr * db)
              for (W, b), (dW, db) in zip(params, grads)]
    history.append(loss)

pred = (forward(params, Xm, "tanh")[0] > 0).astype(float)
acc = np.mean(pred == ym)
print(f"final loss {history[-1]:.3f}, training accuracy {acc:.3f}")

gx, gy = np.meshgrid(np.linspace(-1.8, 2.8, 200), np.linspace(-1.2, 1.7, 200))
grid = np.column_stack([gx.ravel(), gy.ravel()])
zz = forward(params, grid, "tanh")[0].reshape(gx.shape)

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10, 3.8))
ax1.plot(history, color=PALETTE["loss"])
ax1.set_xlabel("step"); ax1.set_ylabel("cross-entropy loss")
ax2.contourf(gx, gy, zz > 0, alpha=0.18, levels=[-0.5, 0.5, 1.5],
             colors=[PALETTE["data"], PALETTE["model"]])
ax2.scatter(*Xm[ym[:, 0] == 0].T, color=PALETTE["data"], s=14)
ax2.scatter(*Xm[ym[:, 0] == 1].T, color=PALETTE["model"], s=14)
ax2.set_xlabel("$x_1$"); ax2.set_ylabel("$x_2$")
plt.tight_layout(); plt.show()
final loss 0.018, training accuracy 0.993

18.10 Production: PyTorch autograd

PyTorch does the same work with a general engine. It records each operation on tensors during the forward pass. Then loss.backward() walks the recorded graph in reverse order. This is reverse-mode automatic differentiation.

We check that PyTorch and our NumPy code give the same gradients.

import torch
import torch.nn as nn
import torch.nn.functional as F

rng = np.random.default_rng(3)
Xs = rng.normal(size=(8, 3)); ys = (rng.uniform(size=(8, 1)) > 0.5) * 1.0
params = init([3, 5, 4, 1], "tanh", rng)

# NumPy gradients
out, cache = forward(params, Xs, "tanh")
_, delta = loss_and_signal(out, ys, "bce")
g_np = flatten(backward(params, cache, delta, "tanh"))

# PyTorch gradients, same weights
net = nn.Sequential(nn.Linear(3, 5), nn.Tanh(), nn.Linear(5, 4), nn.Tanh(),
                    nn.Linear(4, 1)).double()
with torch.no_grad():
    for lin, (W, b) in zip([net[0], net[2], net[4]], params):
        lin.weight.copy_(torch.tensor(W)); lin.bias.copy_(torch.tensor(b))

loss = F.binary_cross_entropy_with_logits(net(torch.tensor(Xs)),
                                          torch.tensor(ys))
loss.backward()                                   # reverse-mode autodiff
g_torch = np.concatenate([torch.cat([lin.weight.grad.flatten(),
                                     lin.bias.grad]).numpy()
                          for lin in [net[0], net[2], net[4]]])
print("max |NumPy - PyTorch| gradient difference:",
      f"{np.abs(g_np - g_torch).max():.2e}")
assert np.allclose(g_np, g_torch)
max |NumPy - PyTorch| gradient difference: 1.39e-17

The two results agree. In real work, we never write backward code by hand. We still need to understand it. It tells us what the training step costs, where memory goes, and why training fails.

18.10.1 What autograd stores

Look at cache in our code. The backward pass needs \(\mathbf{a}_{l-1}\) and \(\mathbf{z}_l\) for every layer. These activations must stay in memory until the backward pass uses them.

For large models this is the main memory cost. It grows with batch size, sequence length, and depth. Two common remedies are:

  • Activation checkpointing. Store only some layers. Recompute the others during the backward pass. This trades extra compute for less memory.
  • Lower precision. Store activations in 16-bit numbers.

18.11 Failure modes

18.11.1 Vanishing gradients

Look at Equation 18.8. Each layer multiplies the signal by \(\mathbf{W}^{\intercal}\) and by \(\sigma'(\mathbf{z})\). In a deep network, the signal is a product of many factors. If the typical factor is below 1, the product shrinks exponentially with depth.

The sigmoid has a maximum derivative of only \(0.25\):

zs = np.linspace(-8, 8, 400)
sig = 1 / (1 + np.exp(-zs))
fig, ax = plt.subplots()
ax.plot(zs, sig, color=PALETTE["data"], label="σ(z)")
ax.plot(zs, sig * (1 - sig), color=PALETTE["loss"], label="σ′(z)")
ax.axhline(0.25, ls="--", color=PALETTE["neutral"], lw=1)
ax.legend(); ax.set_xlabel("z")
plt.show()

We measure the effect in a 30-layer network. For each layer we record the norm of the weight gradient.

rng = np.random.default_rng(0)
depth, width = 30, 32
X = rng.normal(size=(64, width)); y = rng.normal(size=(64, 1))

fig, ax = plt.subplots()
for act, color in [("sigmoid", PALETTE["loss"]), ("relu", PALETTE["grad"])]:
    params = init([width] * depth + [1], act, rng)
    out, cache = forward(params, X, act)
    _, delta = loss_and_signal(out, y, "mse")
    grads = backward(params, cache, delta, act)
    norms = [np.linalg.norm(dW) for dW, _ in grads]
    ax.semilogy(range(1, depth + 1), norms, "o-", ms=4,
                color=color, label=act)
    print(f"{act:8s}  first layer / last layer gradient norm = "
          f"{norms[0] / norms[-1]:.1e}")
ax.set_xlabel("layer (1 = nearest the input)")
ax.set_ylabel("‖∂L/∂W‖  (log scale)"); ax.legend()
plt.show()
sigmoid   first layer / last layer gradient norm = 2.7e-19
relu      first layer / last layer gradient norm = 9.0e-01

This is why deep networks needed new ideas: ReLU-type activations, careful initialization (Chapter 20), normalization (Chapter 20), and residual connections (Chapter 31). Each of these keeps the backward signal at a usable size.

18.11.2 Exploding gradients

If the typical factor is above 1, the signal grows exponentially instead. The weights receive huge updates and the loss becomes nan. The standard remedy is gradient clipping: if \(\lVert \nabla L \rVert > c\), rescale the gradient to norm \(c\).

18.11.3 Dead ReLUs

If \(z \le 0\) for all inputs, then \(\sigma'(z) = 0\). The backward signal through the unit is exactly zero. The unit’s weights never change. It stays “dead”.

18.11.4 Numerical issues

  • Overflow. exp of a large number overflows. We used np.logaddexp for the cross-entropy to avoid it.
  • Not differentiable at a point. ReLU has no derivative at \(z = 0\). Libraries pick 0. This almost never matters in practice.
  • Wrong gradient code. A wrong backward function does not raise an error. Use gradient checking.

18.13 System connection

NoteWhat the system gained in this chapter

The system can now compute \(\nabla_\theta L\) for any model that is a composition of differentiable operations, at about the cost of three forward passes.

With the loss from Part IV, this completes the pipeline

\[ x \;\to\; f_\theta(x) \;\to\; L \;\to\; \nabla_\theta L. \]

The gradient is known. We still need rules for how to use it. Chapter 19 develops the optimizer, and Chapter 20 studies why some training runs fail.

Chapter summary

  • The chain rule: multiply local derivatives along a path, add across paths.
  • A computational graph splits a function into simple operations with known local derivatives.
  • Backpropagation runs the graph backward. It reuses the upstream gradient at each node.
  • For a layer \(\mathbf{z} = \mathbf{W}\mathbf{a} + \mathbf{b}\): \(\ \partial L/\partial\mathbf{W} = \boldsymbol{\delta}\,\mathbf{a}^{\intercal}\), \(\ \partial L/\partial\mathbf{a} = \mathbf{W}^{\intercal}\boldsymbol{\delta}\).
  • For a logit with cross-entropy, the error signal is \(p - y\).
  • One forward and one backward pass give all gradients. The cost does not grow with the number of parameters.
  • Deep networks can have vanishing or exploding gradients. Activation, initialization, and architecture control this.
  • Always verify new backward code with a finite-difference check.
