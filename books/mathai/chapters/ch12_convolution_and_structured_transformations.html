12  Convolution and Structured Transformations

NoteKey ideas
  • A convolution slides a small kernel over an image and computes a dot product at each position.
  • Parameter sharing: the same few weights are used at every position. The layer has far fewer parameters than a dense layer.
  • Convolution is translation equivariant: shifting the input shifts the output by the same amount.
  • Equivariance is not invariance. A shifted image can still confuse a classifier.
  • A convolution is a dense matrix product with a special, sparse, repeated structure.

12.1 The system problem

A dense layer from a \(64\times64\) image to 64 hidden units needs \(4096\times64\) weights. For a \(1000\times1000\) photo it would need a billion. A dense layer also treats every pixel as unrelated to its neighbours. It must learn “an edge here” again for every position.

Images have two properties that a dense layer ignores:

  1. Locality. Useful patterns (edges, corners) are made of nearby pixels.
  2. Translation. A pattern means the same thing wherever it appears.

How can a layer use locality and translation, so that it needs few parameters and finds a pattern anywhere?

12.2 Intuition: a sliding pattern detector

Take a small grid of weights, the kernel, for example \(3\times3\). Place it on the image. Multiply each weight with the pixel below it and add the nine products. This number says how well the patch matches the kernel pattern. Slide the kernel one step. Repeat. The grid of results is a feature map.

12.3 The mathematical object

For an image \(I\) and a kernel \(K\) of size \(k\times k\), the output at position \((i,j)\) is

\[ (I\star K)_{ij}=\sum_{u=0}^{k-1}\sum_{v=0}^{k-1}I_{i+u,\,j+v}\;K_{uv}. \tag{12.1}\]

NoteConvolution or correlation?

Equation 12.1 is strictly cross-correlation. True mathematical convolution flips the kernel first. Deep learning libraries compute Equation 12.1 and call it “convolution”. Since the kernel is learned, the flip makes no difference to what the network can represent.

12.3.1 Size, stride, and padding

With input size \(n\), kernel size \(k\), padding \(p\) (zeros added at each border), and stride \(s\) (step between positions), the output size is

\[ n_{\text{out}}=\left\lfloor\frac{n+2p-k}{s}\right\rfloor+1. \tag{12.2}\]

\(n\) \(k\) \(p\) \(s\) \(n_{\text{out}}\) Name
8 3 0 1 6 valid
8 3 1 1 8 same
8 3 1 2 4 downsample

12.3.2 Channels

Images have \(C_{\text{in}}\) channels. A layer has \(C_{\text{out}}\) kernels, each of shape \((C_{\text{in}},k,k)\). The weight tensor has shape \((C_{\text{out}},C_{\text{in}},k,k)\), and

\[ \#\text{params}=C_{\text{out}}\,(C_{\text{in}}k^2+1). \tag{12.3}\]

The count does not depend on the image size. A \(3\times3\) layer with 64 input and 64 output channels always has \(64\cdot(64\cdot9+1)=36{,}928\) parameters, for any image.

12.4 Derivation: translation equivariance

Let \(T_\tau\) shift an image by \(\tau\) pixels: \((T_\tau I)_{i}=I_{i-\tau}\). Ignoring borders (1D for clarity):

\[ (T_\tau I\star K)_i=\sum_uI_{i+u-\tau}K_u=(I\star K)_{i-\tau}=T_\tau(I\star K)_i. \tag{12.4}\]

Shifting the input and then convolving gives the same result as convolving and then shifting. The operation is translation equivariant.

The reason is that the same kernel is used at every position. A dense layer has a separate weight for every pair of positions. It has no such property.

12.5 Computation: from first principles

We write the definition with loops. It is slow and exact.

def conv2d_loops(img, K, stride=1, pad=0):
    img = np.pad(img, pad)
    k = K.shape[0]
    n_h = (img.shape[0] - k) // stride + 1
    n_w = (img.shape[1] - k) // stride + 1
    out = np.zeros((n_h, n_w))
    for i in range(n_h):
        for j in range(n_w):
            patch = img[i * stride:i * stride + k, j * stride:j * stride + k]
            out[i, j] = np.sum(patch * K)              # dot product of patch and kernel
    return out

img = np.arange(64.0).reshape(8, 8)
K = np.array([[1.0, 0.0, -1.0]] * 3)                  # a vertical-edge kernel
for pad, stride in [(0, 1), (1, 1), (1, 2)]:
    print(f"pad={pad} stride={stride}: output shape",
          conv2d_loops(img, K, stride, pad).shape)
pad=0 stride=1: output shape (6, 6)
pad=1 stride=1: output shape (8, 8)
pad=1 stride=2: output shape (4, 4)

The shapes match Equation 12.2.

12.5.1 Convolution as a matrix product (im2col)

Chapter 6 introduced strided views. A sliding window view gives all patches as one array. Then convolution is one contraction. This is the “im2col” idea behind fast implementations.

from numpy.lib.stride_tricks import sliding_window_view

def conv2d_fast(img, K):
    k = K.shape[0]
    windows = sliding_window_view(img, (k, k))          # (H-k+1, W-k+1, k, k), a view
    return np.einsum("ijuv,uv->ij", windows, K)

rng = np.random.default_rng(0)
test_img = rng.normal(size=(20, 20)); test_K = rng.normal(size=(5, 5))
print("fast == loops:", np.allclose(conv2d_fast(test_img, test_K),
                                    conv2d_loops(test_img, test_K)))
fast == loops: True

To see the matrix, we build it. For a 1D signal of length 8 and a kernel of length 3, the convolution is a \(6\times8\) matrix. Each row is the kernel, shifted by one:

n, k = 8, 3
kern = np.array([1.0, 2.0, -1.0])
M = np.zeros((n - k + 1, n))
for i in range(n - k + 1):
    M[i, i:i + k] = kern                                 # same kernel, shifted

sig = rng.normal(size=n)
print("matrix product == sliding window:",
      np.allclose(M @ sig, np.correlate(sig, kern, mode="valid")))

fig, ax = plt.subplots(figsize=(5, 3.2))
ax.imshow(M, cmap="RdBu_r", vmin=-2, vmax=2)
for (i, j), v in np.ndenumerate(M):
    ax.text(j, i, f"{v:g}", ha="center", va="center", fontsize=9)
ax.set_xlabel("input position"); ax.set_ylabel("output position"); ax.grid(False)
plt.show()
matrix product == sliding window: True

12.6 Kernels as feature detectors

Different kernels detect different patterns. We apply five classic ones to a photograph.

from sklearn.datasets import load_sample_image
photo = load_sample_image("china.jpg").astype(float).mean(axis=2)[:300, 150:550]

kernels = {

12.7 Equivariance, tested

We check Equation 12.4 numerically. We shift the image, convolve, and compare with the shifted feature map. Borders break the symmetry, so we compare only the interior.

img = photo[:120, :160]
Kx = kernels["Sobel x"]
shift = 7

shifted_input = np.roll(img, shift, axis=1)                       # shift right by 7
out_of_shifted = conv2d_fast(shifted_input, Kx)
shifted_out = np.roll(conv2d_fast(img, Kx), shift, axis=1)

inner = (slice(None), slice(shift + 2, -2))                       # skip wrapped columns
diff = np.max(np.abs(out_of_shifted[inner] - shifted_out[inner]))
print(f"conv(shift(x)) vs shift(conv(x)), interior max difference: {diff:.1e}")
conv(shift(x)) vs shift(conv(x)), interior max difference: 0.0e+00

The difference is exactly zero in the interior. Convolution commutes with translation.

12.8 Pooling

Max pooling replaces each \(p\times p\) block by its maximum. It halves the resolution (for \(p=2\)) and gives some tolerance to small shifts: a feature that moves by one pixel inside a block gives the same pooled value.

\[ \text{pool}(F)_{ij}=\max_{0\le u,v<p}F_{pi+u,\,pj+v}. \tag{12.5}\]

def max_pool(F, p=2):
    H, W = (F.shape[0] // p) * p, (F.shape[1] // p) * p
    return F[:H, :W].reshape(H // p, p, W // p, p).max(axis=(1, 3))

F = np.zeros((6, 6)); F[2, 2] = 1.0          # one active feature
F_shift = np.roll(F, 1, axis=1)              # moved by one pixel, still in its block
print("same block -> pooled maps equal:",
      np.array_equal(max_pool(F), max_pool(F_shift)))
F_far = np.roll(F, 2, axis=1)                # moved to the next block
print("next block -> pooled maps equal:",
      np.array_equal(max_pool(F), max_pool(F_far)))
same block -> pooled maps equal: True
next block -> pooled maps equal: False

Pooling gives tolerance only for shifts that stay inside a block. Larger or different shifts change the result. This will matter below.

12.9 A CNN for digits

We build a small CNN: \(8\times8\) image \(\to\) 8 kernels of size \(3\times3\) \(\to\) ReLU \(\to\) \(2\times2\) max pool \(\to\) linear layer to 10 classes. We train it with the same tools as in Chapter 11, and compare it with the MLP.

import torch
import torch.nn as nn
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

D = load_digits()
Xtr, Xte, ytr, yte = train_test_split(D.data / 16.0, D.target, test_size=0.25,
                                      random_state=0, stratify=D.target)
Xtr_t, Xte_t = (torch.tensor(a, dtype=torch.float32) for a in (Xtr, Xte))
ytr_t, yte_t = torch.tensor(ytr), torch.tensor(yte)

class SmallCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv = nn.Conv2d(1, 8, kernel_size=3)       # (1, 8, 8) -> (8, 6, 6)
        self.fc = nn.Linear(8 * 3 * 3, 10)               # after 2x2 pooling: (8, 3, 3)
    def forward(self, x):
        x = torch.relu(self.conv(x.view(-1, 1, 8, 8)))
        x = torch.max_pool2d(x, 2)
        return self.fc(x.flatten(1))

def train(model, steps, lr=0.5):
    opt = torch.optim.SGD(model.parameters(), lr=lr)
    ce = nn.CrossEntropyLoss()
    for _ in range(steps):
        opt.zero_grad(); ce(model(Xtr_t), ytr_t).backward(); opt.step()
    return model

def acc(model, X, y):
    with torch.no_grad():
        return (model(X).argmax(1) == y).float().mean().item()

torch.manual_seed(0)
mlp = train(nn.Sequential(nn.Linear(64, 32), nn.ReLU(), nn.Linear(32, 10)), 600)
torch.manual_seed(0)
cnn = train(SmallCNN(), 800)

n_params = lambda m: sum(p.numel() for p in m.parameters())
print(f"MLP 64-32-10 : {n_params(mlp):5d} parameters, test accuracy {acc(mlp, Xte_t, yte_t):.3f}")
print(f"CNN          : {n_params(cnn):5d} parameters, test accuracy {acc(cnn, Xte_t, yte_t):.3f}")
MLP 64-32-10 :  2410 parameters, test accuracy 0.973
CNN          :   810 parameters, test accuracy 0.973

The CNN reaches the same accuracy with about a third of the parameters. On this tiny dataset that is the whole benefit. On large images the saving is far greater.

Kl = cnn.conv.weight.detach().numpy()[:, 0]               # (8, 3, 3)
fig, axes = plt.subplots(1, 8, figsize=(10, 1.6))
for ax, kk in zip(axes, Kl):
    lim = np.abs(kk).max()
    ax.imshow(kk, cmap="RdBu_r", vmin=-lim, vmax=lim)
    ax.set_xticks([]); ax.set_yticks([]); ax.grid(False)

12.9.1 Equivariance is not invariance

A classifier should give the same label for a shifted digit. This is invariance. Convolution gives equivariance: the feature map moves with the input. Only the later layers and pooling can turn this into invariance, and they do so only partly.

We test it. We shift every test image by one pixel to the right and measure accuracy.

def shift_images(X, dx):
    im = X.reshape(-1, 8, 8)
    out = np.roll(im, dx, axis=2)
    out[:, :, :dx] = 0.0                               # clear wrapped column
    return torch.tensor(out.reshape(len(X), -1), dtype=torch.float32)

Xshift = shift_images(Xte, 1)
print(f"{'':6s} {'original':>9s} {'shifted by 1 px':>16s}")
for name, m in [("MLP", mlp), ("CNN", cnn)]:
    print(f"{name:6s} {acc(m, Xte_t, yte_t):9.3f} {acc(m, Xshift, yte_t):16.3f}")
        original  shifted by 1 px
MLP        0.973            0.429
CNN        0.973            0.498

Both models lose much of their accuracy under a one-pixel shift. The CNN is not much better than the MLP here. In an \(8\times8\) image, one pixel is a large move, and the model has seen no shifted examples. What helps in practice is data augmentation (training on shifted copies), more pooling, and depth (Chapter 35).

12.11 Failure modes

Border effects. A “valid” convolution shrinks the image. Zero padding adds artificial edges at the border. Equivariance holds exactly only away from the borders.

Aliasing from stride. A stride larger than 1 samples the signal sparsely. A fast oscillation can turn into a slow one or a constant. Blur before subsampling.

signal = np.array([1.0, -1.0] * 8)                         # fastest possible oscillation
strided = signal[::2]                                      # stride-2 sampling
blurred = np.convolve(signal, [0.5, 0.5], mode="valid")[::2]
print("stride 2 without blur:", strided[:6], " <- looks like a constant")
print("stride 2 after blur  :", blurred[:6])
stride 2 without blur: [1. 1. 1. 1. 1. 1.]  <- looks like a constant
stride 2 after blur  : [0. 0. 0. 0. 0. 0.]

Invariance is not given for free. See the shift test above.

Flip versus no flip. SciPy’s convolve2d flips the kernel. PyTorch does not. For a non-symmetric kernel, the two give different (mirrored) results. Check the library.

from scipy.signal import convolve2d, correlate2d
a = rng.normal(size=(6, 6)); kk = np.array([[1.0, 2.0], [0.0, -1.0]])
print("correlate2d == our conv:", np.allclose(correlate2d(a, kk, mode="valid"),
                                              conv2d_fast(a, kk)))
print("convolve2d  == our conv:", np.allclose(convolve2d(a, kk, mode="valid"),
                                              conv2d_fast(a, kk)))
correlate2d == our conv: True
convolve2d  == our conv: False

Receptive field too small. A single \(3\times3\) layer sees only 9 pixels. To recognise a large object, the network must stack layers or pool. We compute receptive fields in Chapter 35.

12.13 System connection

NoteWhat the system gained in this chapter

The system has a transformation that uses the structure of the data: few shared parameters, local patterns, and equivariance to translation. System A now has a proper image classifier, and the same kernels can be viewed as feature detectors or as a structured matrix.

This closes Part III. The system can transform: linear layers, nonlinearities, composition, and structured layers. In Part IV, we ask how it can measure: how similar two things are and how wrong a prediction is.

Chapter summary

  • A convolution slides a kernel and takes a dot product at each position: \((I\star K)_{ij}=\sum I_{i+u,j+v}K_{uv}\).
  • Output size: \(\lfloor(n+2p-k)/s\rfloor+1\). Parameters: \(C_{\text{out}}(C_{\text{in}}k^2+1)\).
  • It is translation equivariant. The proof is one line because the kernel is shared.
  • It equals a matrix product with a banded, repeated matrix.
  • Pooling gives limited shift tolerance. Equivariance is not invariance.
  • A small CNN matches an MLP on digits with fewer parameters.
  • Watch for borders, aliasing, and the flip convention.
