50  A Characterisation Protocol: Experimental Design and Reporting

NoteKey ideas
  • A characterisation is an experiment. It has a design (which conditions, which parameters), a protocol (which data tune, which data report) and a report.
  • Tune parameters on one data set. Report on a different one. The tuned score on the tuning data is biased high (Chapter 27).
  • Test the model of the world on purpose: change the noise type, the noise level, the condition. The result tells where the characterisation stops being valid.
  • A parameter that adapts to a measured condition (such as the noise level) holds the false alarm rate where a fixed parameter does not.
  • The report states conditions, definitions, parameters, numbers with intervals, and the limits of validity.

50.1 The system problem

Chapters 45 to 49 gave the parts: a system view, loops, a paradigm, error propagation, operating curves with confidence. Each can be done well and the whole can still be wrong, if the experiment is badly planned. We close the book with the plan.

We must deliver a detector that meets a requirement. Which experiments do we run, in which order, on which data, and what do we write down?

We use the edge detector of Chapter 47 as a running example, because every step can be checked against known truth. The same protocol applies to a vision model, a language model or a sensor chain.

50.2 Step 1: the requirement

A requirement in the form of Chapter 45 for our detector:

For a step edge of height 2 in additive noise of standard deviation 1, in a signal of 200 samples, find the edge within \(\pm2\) samples in as many cases as possible, with at most 5% of noise-only signals raising any false alarm.

The constraint is on a per-signal false alarm rate of \(5\%\). The objective is the detection probability. The condition is \((h,\sigma)=(2,1)\). We now know what the experiment must measure.

50.3 Step 2: the design of conditions

Performance depends on several factors: noise level \(\sigma\), edge height \(h\), window \(w\), and possibly the noise type. A design chooses which combinations to run. A full factorial design runs every combination. It is the right choice when the number of factors is small. It costs \(\prod_k L_k\) runs for \(L_k\) levels of factor \(k\).

rng = np.random.default_rng(50)
Ls, s0 = 200, 100

def dfilt(x, w):
    c = np.concatenate([[0.0], np.cumsum(x)]); i = np.arange(w, len(x) - w + 1)
    return i, (c[i + w] - c[i]) / w - (c[i] - c[i - w]) / w

def noise(kind, sigma, size):
    if kind == "gauss":   return rng.normal(0, sigma, size)
    if kind == "laplace": return rng.laplace(0, sigma / np.sqrt(2), size)     # same variance
    if kind == "t3":      return student.rvs(3, size=size, random_state=rng) * sigma / np.sqrt(3)

def max_noise_response(sigma, w, n, kind="gauss"):
    return np.array([np.abs(dfilt(noise(kind, sigma, Ls), w)[1]).max() for _ in range(n)])

def detect_prob(h, sigma, w, tau, n, kind="gauss"):
    ok = 0
    for _ in range(n):
        x = noise(kind, sigma, Ls); x[s0:] += h
        i, d = dfilt(x, w); a = np.abs(d); k = a.argmax()
        ok += (a[k] > tau) and abs(i[k] - s0) <= 2
    return ok / n

levels = {"sigma": [0.5, 1.0, 2.0], "h": [2.0, 4.0], "w": [3, 5, 9, 15, 25]}
runs = int(np.prod([len(v) for v in levels.values()]))
print("factors and levels:", levels)
print("full factorial runs:", runs, "  with 1000 noise-only + 1000 edge trials each:", runs * 2000, "signals")
factors and levels: {'sigma': [0.5, 1.0, 2.0], 'h': [2.0, 4.0], 'w': [3, 5, 9, 15, 25]}
full factorial runs: 30   with 1000 noise-only + 1000 edge trials each: 60000 signals

Thirty conditions are practical. If we added six more factors with three levels each, the design would need \(30\times3^6=21{,}870\) runs. A fractional design or a random sample of conditions (Latin hypercube) then replaces the full grid, at the cost of ignoring some interactions.

50.4 Step 3: tune on tuning data

The window \(w\) is a tuning parameter. For each candidate \(w\), the threshold \(\tau\) is set from the noise-only data so that the requirement on false alarms is met: \(\tau\) is the 95th percentile of the largest absolute response in noise-only signals. Then the detection probability is measured. We choose the \(w\) with the highest detection probability.

sigma, h = 1.0, 2.0
rows = []
for w in (3, 5, 9, 15, 25):
    tau = np.quantile(max_noise_response(sigma, w, 1000), 0.95)
    rows.append((w, tau, detect_prob(h, sigma, w, tau, 600)))
print(" w    tau    P_detect (tuning data)")
for w, tau, p in rows:
    print(f"{w:2d}  {tau:6.3f}   {p:.3f}")
w_best, tau_best, p_tune = max(rows, key=lambda r: r[2])
print("chosen: w =", w_best, "  tau =", round(tau_best, 3))
 w    tau    P_detect (tuning data)
 3   2.945   0.138
 5   2.292   0.380
 9   1.622   0.807
15   1.256   0.885
25   0.955   0.875
chosen: w = 15   tau = 1.256

The detection probability rises with \(w\) up to \(15\) and then flattens. The values for \(w=15\) and \(w=25\) differ by \(0.01\), which is within sampling noise for 600 trials (about \(\pm0.013\)). The choice between them is not supported by the data. A characterisation should say so, and pick the smaller window if resolution matters (Chapter 47).

50.5 Step 4: measure on fresh data

The score on the tuning data was used to select. It carries the optimiser’s curse (Chapter 27). We generate new signals and measure again.

n = 4000
fa_hits = int((max_noise_response(sigma, w_best, n) > tau_best).sum())
det_hits = int(round(detect_prob(h, sigma, w_best, tau_best, n) * n))

def clopper_pearson(k, n, a=0.05):
    return (0.0 if k == 0 else beta.ppf(a / 2, k, n - k + 1),
            1.0 if k == n else beta.ppf(1 - a / 2, k + 1, n - k))

print(f"false alarm per signal : {fa_hits/n:.3f}   95% CI {np.round(clopper_pearson(fa_hits, n), 3)}   (requirement 0.05)")
print(f"detection probability  : {det_hits/n:.3f}   95% CI {np.round(clopper_pearson(det_hits, n), 3)}   (tuning data: {p_tune:.3f})")
false alarm per signal : 0.057   95% CI [0.05  0.064]   (requirement 0.05)
detection probability  : 0.875   95% CI [0.865 0.886]   (tuning data: 0.885)

On fresh data the false alarm rate is \(0.057\), with an interval from \(0.050\) to \(0.064\). The requirement was \(0.05\). The requirement is not shown to be met: the whole interval is at or above the limit. The threshold was set from only 1,000 noise-only signals, so the threshold itself carries sampling error, and the realised rate landed above the target. Two remedies exist: more tuning data, or a margin (aim at \(0.04\) so that the interval falls below \(0.05\)). The detection probability on fresh data, \(0.875\), is slightly below the tuning value \(0.885\), as the optimiser’s curse predicts.

50.6 Step 5: stress the model

So far the test noise came from the same family as the tuning noise. A characterisation is only as good as the model of the world. We now violate the model on purpose, in two ways.

Noise type. The threshold was derived for Gaussian noise. Real noise can have heavier tails. We keep the variance and change the shape. We use the Gaussian design of Chapter 47: \(\tau=\sigma_D\,Q^{-1}(0.0005)\).

sD = sigma * np.sqrt(2 / w_best)
tau_g = sD * norm.isf(1e-3 / 2)
print("noise shape (same variance)   per-sample false alarm   design value 0.001")
for kind in ("gauss", "laplace", "t3"):
    fa = np.mean([(np.abs(dfilt(noise(kind, sigma, Ls), w_best)[1]) > tau_g).mean() for _ in range(1500)])
    print(f"  {kind:8s}                    {fa:.5f}")
print()
print("error in the noise estimate:   per-sample false alarm")
for f in (0.8, 1.0, 1.2):
    fa = np.mean([(np.abs(dfilt(noise('gauss', sigma, Ls), w_best)[1]) > f * tau_g).mean() for _ in range(1500)])
    print(f"  threshold from sigma x {f:3.1f}   {fa:.5f}")
noise shape (same variance)   per-sample false alarm   design value 0.001
  gauss                       0.00094
  laplace                     0.00140
  t3                          0.00529

error in the noise estimate:   per-sample false alarm
  threshold from sigma x 0.8   0.00784
  threshold from sigma x 1.0   0.00102
  threshold from sigma x 1.2   0.00009

Heavy tails (Student \(t\) with 3 degrees of freedom) raise the false alarm rate by a factor of about \(5\) at the same variance. An error of \(20\%\) in the noise level moves the false alarm rate up by a factor of about \(8\) (noise underestimated) or down by a factor of about \(11\) (overestimated). The threshold is sensitive to the noise level, because it lives on the tail of the distribution. A small error in the model becomes a large error in a rare-event rate. This is the most important practical lesson of the paradigm: tail rates are fragile.

Noise level. The threshold was tuned at \(\sigma=1\). In the field, the noise level may differ. We compare two policies over a range of \(\sigma\): a fixed threshold (tuned at \(\sigma=1\)) and an adaptive threshold that scales with an estimate of \(\sigma\) from the data. The estimate uses the median absolute deviation (MAD) of first differences, which is hardly affected by a single edge.

def sigma_hat(x):
    d = np.diff(x)
    return np.median(np.abs(d - np.median(d))) / 0.6745 / np.sqrt(2)

# adaptive threshold factor: percentile of max response / estimated sigma, calibrated once at sigma = 1
ratio = []
for _ in range(1500):
    x = noise("gauss", 1.0, Ls)
    ratio.append(np.abs(dfilt(x, w_best)[1]).max() / sigma_hat(x))
c_adapt = np.quantile(ratio, 0.95)

sig_grid = [0.5, 0.75, 1.0, 1.5, 2.0]
fixed, adapt = [], []
for sg in sig_grid:
    fx = ad = 0
    for _ in range(1500):
        x = noise("gauss", sg, Ls)
        m = np.abs(dfilt(x, w_best)[1]).max()
        fx += m > tau_best
        ad += m > c_adapt * sigma_hat(x)
    fixed.append(fx / 1500); adapt.append(ad / 1500)
fig, ax = plt.subplots(figsize=(6.2, 3.4))
ax.plot(sig_grid, fixed, "o-", color=PALETTE["loss"], label="fixed threshold")
ax.plot(sig_grid, adapt, "s-", color=PALETTE["grad"], label="adaptive threshold")
ax.axhline(0.05, color="gray", ls="--", lw=1)
ax.set_xlabel("true noise σ"); ax.set_ylabel("false alarm per signal"); ax.legend()
plt.show()
for sg, f, a in zip(sig_grid, fixed, adapt):
    print(f"sigma {sg:4.2f}:  fixed {f:.3f}   adaptive {a:.3f}")
sigma 0.50:  fixed 0.000   adaptive 0.040
sigma 0.75:  fixed 0.001   adaptive 0.053
sigma 1.00:  fixed 0.057   adaptive 0.053
sigma 1.50:  fixed 0.702   adaptive 0.049
sigma 2.00:  fixed 0.987   adaptive 0.044

The fixed threshold holds the requirement only at the noise level where it was tuned: its false alarm rate is \(0.70\) at \(\sigma=1.5\) and \(0.99\) at \(\sigma=2\). The adaptive threshold stays between \(0.040\) and \(0.053\) over the whole range. The cost of adaptation is the estimation step, which is itself a component to characterise (it assumes that most differences contain only noise). This is the closing of the loop that Haralick and Ramesh described: the characterisation shows what the parameter must depend on, and the algorithm is redesigned so that it does.

50.7 Step 6: the report

The result is a short document. The table below is the format. The numbers come from the runs above.

lo_fa, hi_fa = clopper_pearson(fa_hits, n); lo_d, hi_d = clopper_pearson(det_hits, n)
report = [
    ("Requirement",     "P(false alarm per 200-sample signal) ≤ 0.05; maximise P(detect within ±2)"),
    ("Input domain",    "step edge, h = 2, additive noise σ = 1 (also tested σ in 0.5–2.0)"),
    ("Algorithm",       f"window mean difference, w = {w_best}, threshold from noise-only data"),
    ("Tuning data",     "1,000 noise-only and 600 edge signals per candidate w"),
    ("Test data",       f"{n} noise-only and {n} edge signals, fresh"),
    ("False alarm",     f"{fa_hits/n:.3f}  [95% CI {lo_fa:.3f}, {hi_fa:.3f}]  (requirement not shown met)"),
    ("Detection",       f"{det_hits/n:.3f}  [95% CI {lo_d:.3f}, {hi_d:.3f}]"),
    ("Limit of validity","Gaussian noise; fixed threshold valid only near σ = 1; heavy tails raise false alarms about 5×"),
]
for k, v in report:
    print(f"{k:17s} {v}")
Requirement       P(false alarm per 200-sample signal) ≤ 0.05; maximise P(detect within ±2)
Input domain      step edge, h = 2, additive noise σ = 1 (also tested σ in 0.5–2.0)

A reader should be able to repeat the experiment from this report and to see where the claim stops.

50.8 Failure modes

Tuning and reporting on one set. The reported score is the best of many (Chapter 27).

One condition. A requirement for a range of conditions is tested at one point.

No stress. The model is never violated, so its limits are never found.

Tail rate from a small sample. A rate of \(10^{-3}\) cannot be measured with 500 samples (Chapter 49).

Silent re-tuning. A parameter changes after the report. The report no longer describes the system.

No version. Algorithm, data and parameters are not recorded, so the result cannot be reproduced.

50.10 System connection

NoteWhat the system gained in this chapter, and in the book

Part IX gave the system a method for knowing itself. A system is described as components, interfaces and loops (Chapters 45 and 46). Each component is characterised against its input conditions and parameters (Chapter 47). Uncertainty flows through the chain by propagation (Chapter 48). Decisions are summarised by operating curves with confidence (Chapter 49). The whole is tested by a protocol that separates tuning from reporting, stresses the model and states the limits (this chapter).

Chapter 51 applies the whole method to large models. Parts I to VIII built the mathematics that makes the system work. Part IX makes the claim that the system works into something another person can check.

Chapter summary

  • A characterisation has a requirement, a design, a tuning step, a fresh measurement, a stress step and a report.
  • Tune on one set and report on another.
  • Tail rates are fragile: a 20% error in noise level changed the false alarm rate by a factor of 8 to 11 here.
  • A requirement is met only when the interval, not the point value, lies on the right side. Here \(0.057\ [0.050,\,0.064]\) did not meet \(0.05\).
  • Make parameters depend on the measured condition if the characterisation says they must.
  • State the limits of validity.
