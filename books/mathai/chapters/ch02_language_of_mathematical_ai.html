2  The Language of Mathematical AI

NoteKey ideas
  • An equation, a diagram, and a program can describe the same system. This chapter gives the rules to move between them.
  • Every mathematical object has a shape. Shapes are the type system of AI mathematics.
  • Index notation (W[i, j], \(\sum_j\)) is a short way to write loops.
  • A computational graph is a drawing of a formula. It shows what depends on what.
  • Variables come from the data. Parameters are changed by learning. Keep them apart.

2.1 The system problem

Open any AI paper. You will see an equation like this one:

\[ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{Q K^{\intercal}}{\sqrt{d_k}}\right) V \tag{2.1}\]

You may not know what every symbol means yet. That is fine. This chapter does not explain attention. It teaches you to read such an equation: what each symbol is, what shape it has, and what operation connects them.

How do we write an AI system exactly, so that a paper, an equation, and a program all say the same thing?

The answer has four parts: sets and functions, the four kinds of array, index notation, and shapes.

2.2 Sets and functions

A set is a collection of objects. We write \(x \in S\) for “\(x\) is in \(S\)”.

Set Meaning Example
\(\mathbb{R}\) all real numbers \(3.14\)
\(\mathbb{R}^d\) all lists of \(d\) real numbers \((1.0, -2.0, 0.5) \in \mathbb{R}^3\)
\(\{0, 1\}\) two values a binary label
\(\{1, \dots, K\}\) \(K\) classes digit labels \(\{0,\dots,9\}\)

A function \(f: \mathcal{X} \to \mathcal{Y}\) takes each input in \(\mathcal{X}\) and gives one output in \(\mathcal{Y}\). The set \(\mathcal{X}\) is the domain. The set \(\mathcal{Y}\) is the codomain.

An AI model is a function with this signature:

\[ f_\theta : \mathbb{R}^{d_{\text{in}}} \to \mathbb{R}^{d_{\text{out}}} \tag{2.2}\]

Here, an image classifier for \(8\times8\) digits has \(d_{\text{in}} = 64\) and \(d_{\text{out}} = 10\). The signature already tells us a lot: it states the input size and the output size. It is a contract.

2.3 The four kinds of array

Four kinds of object appear in all AI mathematics. They differ in the number of axes.

Object Axes Notation Shape NumPy AI example
Scalar 0 \(a\) () np.float64 loss, learning rate
Vector 1 \(\mathbf{x}\) (d,) a.shape == (d,) embedding, bias
Matrix 2 \(\mathbf{W}\) (m, n) a.shape == (m, n) weights, batch of vectors
Tensor \(\ge 3\) \(\mathcal{X}\) (B, T, d) a.ndim >= 3 images, token sequences 
a = np.float64(0.1)                         # scalar
x = np.array([1.0, 2.0, 3.0])               # vector, (3,)
W = np.arange(6.0).reshape(2, 3)            # matrix, (2, 3)
X = np.zeros((4, 5, 3))                     # tensor, (4, 5, 3)
for name, v in [("a", a), ("x", x), ("W", W), ("X", X)]:
    print(f"{name}: ndim = {np.ndim(v)}, shape = {np.shape(v)}")
a: ndim = 0, shape = ()
x: ndim = 1, shape = (3,)
W: ndim = 2, shape = (2, 3)
X: ndim = 3, shape = (4, 5, 3)
NoteRule for this book

Mathematics uses column vectors. Code usually stores a batch of vectors as rows: shape (B, d). We write the batched layer as \(\mathbf{Y} = \mathbf{X}\mathbf{W}^{\intercal} + \mathbf{b}\), so the code and the equation match.

2.4 Index notation and summation

A matrix–vector product has a short form and a long form.

\[ \mathbf{y} = \mathbf{W}\mathbf{x} \qquad\Longleftrightarrow\qquad y_i = \sum_{j=1}^{n} W_{ij}\, x_j \quad (i = 1, \dots, m) \tag{2.3}\]

The long form is a loop. Read it as: “for each output index \(i\), sum over the input index \(j\).”

m, n = 2, 3
W = np.array([[1.0, 0.0, -1.0],
              [2.0, 1.0,  0.5]])             # (m, n)
x = np.array([3.0, 2.0, 1.0])                # (n,)

y = np.zeros(m)
for i in range(m):                           # for each output index i
    for j in range(n):                       # sum over j
        y[i] += W[i, j] * x[j]

print("loop :", y)
print("W @ x:", W @ x)
assert np.allclose(y, W @ x)
loop : [2.  8.5]
W @ x: [2.  8.5]

Index notation scales to any number of axes. NumPy’s einsum uses the same idea. The string lists the axes of each input, then ->, then the axes of the output. Any axis that is missing from the output is summed.

rng = np.random.default_rng(0)
u, v = rng.normal(size=4), rng.normal(size=4)
A, B = rng.normal(size=(3, 4)), rng.normal(size=(4, 5))
Ab, Bb = rng.normal(size=(2, 3, 4)), rng.normal(size=(2, 4, 5))

E = np.einsum
cases = [   # (name, einsum string, inputs, reference result)
    ("dot product      Σ_i u_i v_i",    "i,i->",        (u, v),   u @ v),
    ("matrix-vector    y_i = Σ_j A_ij v_j", "ij,j->i",  (A, v),   A @ v),
    ("matrix product   C_ik = Σ_j A_ij B_jk", "ij,jk->ik", (A, B), A @ B),
    ("outer product    M_ij = u_i v_j", "i,j->ij",      (u, v),   np.outer(u, v)),
    ("batched matmul",                  "bij,bjk->bik", (Ab, Bb), Ab @ Bb),
]
for name, spec, args, ref in cases:
    print(f"{name:42s} {spec:14s} same: {np.allclose(E(spec, *args), ref)}")
dot product      Σ_i u_i v_i               i,i->          same: True
matrix-vector    y_i = Σ_j A_ij v_j        ij,j->i        same: True
matrix product   C_ik = Σ_j A_ij B_jk      ij,jk->ik      same: True
outer product    M_ij = u_i v_j            i,j->ij        same: True
batched matmul                             bij,bjk->bik   same: True

We use einsum in later chapters, where tensors have three or four axes and plain @ becomes unclear.

2.5 Shapes are a type system

In a typed programming language, the type checker rejects "hello" + 3. Arrays have an equivalent check: the shape. Most mistakes in AI code are shape mistakes.

The rules we need are few.

Operation Shape rule Result
\(\mathbf{A} + \mathbf{B}\) (element-wise) same shape, or broadcast same shape
\(\mathbf{A}\mathbf{B}\) (matrix product) \((m, n)\,(n, p)\): inner sizes match \((m, p)\)
\(\mathbf{A}^{\intercal}\) swap the axes \((n, m)\)
\(\sum\) over an axis the axis disappears one axis fewer

Writing the shape next to each quantity is the most useful habit in this book. We apply it to a two-layer classifier for the digits of Chapter 3:

\[ \underbrace{\mathbf{X}}_{(B,\,64)} \;\xrightarrow{\;\mathbf{W}_1^{\intercal},\ \mathbf{b}_1\;}\; \underbrace{\mathbf{H}}_{(B,\,32)} \;\xrightarrow{\;\sigma\;}\; \underbrace{\mathbf{A}}_{(B,\,32)} \;\xrightarrow{\;\mathbf{W}_2^{\intercal},\ \mathbf{b}_2\;}\; \underbrace{\mathbf{Z}}_{(B,\,10)} \tag{2.4}\]

labels = ["X\n(B, 64)", "H = XW₁ᵀ + b₁\n(B, 32)", "A = σ(H)\n(B, 32)",
          "Z = AW₂ᵀ + b₂\n(B, 10)"]
fig = box_flow(labels, colors=[PALETTE["data"], PALETTE["model"],
                               PALETTE["model"], PALETTE["prob"]],
               figsize=(10, 1.8), fontsize=8.5)
ax = fig.axes[0]
ax.text(1.0, 0.04, "W₁: (32, 64)", ha="center", fontsize=8, color="#374151")
ax.text(3.0, 0.04, "W₂: (10, 32)", ha="center", fontsize=8, color="#374151")
plt.show()

We turn this into a shape tracer. It runs the forward pass and prints the shape after each step. A mismatch shows up at once.

def show(name, arr):
    print(f"{name:10s} shape = {arr.shape}")
    return arr

rng = np.random.default_rng(0)
B = 5
X  = show("X",  rng.normal(size=(B, 64)))
W1 = show("W1", rng.normal(size=(32, 64)));  b1 = show("b1", np.zeros(32))
W2 = show("W2", rng.normal(size=(10, 32)));  b2 = show("b2", np.zeros(10))

H = show("H", X @ W1.T + b1)          # (B,64)(64,32) -> (B,32); bias broadcasts
A = show("A", np.maximum(0, H))       # element-wise
Z = show("Z", A @ W2.T + b2)          # (B, 32)(32, 10) -> (B, 10)
assert Z.shape == (B, 10)
X          shape = (5, 64)
W1         shape = (32, 64)
b1         shape = (32,)
W2         shape = (10, 32)
b2         shape = (10,)
H          shape = (5, 32)
A          shape = (5, 32)
Z          shape = (5, 10)

When a shape is wrong, NumPy raises an error with both shapes. Read the error message. It is exact.

try:
    X @ W1          # (B, 64) @ (32, 64): inner sizes 64 and 32 differ
except ValueError as e:
    print("ValueError:", e)
ValueError: matmul: Input operand 1 has a mismatch in its core dimension 0, with gufunc signature (n?,k),(k,m?)->(n?,m?) (size 32 is different from 64)

2.6 Variables and parameters

Chapter 1 separated data from parameters. Notation must keep them apart.

Variable (data) Parameter
Symbol \(\mathbf{x},\ y\) \(\theta\) (all), \(\mathbf{W}_l,\ \mathbf{b}_l\)
Source The world Learning
In a function argument: \(f(\mathbf{x})\) subscript or after a semicolon: \(f_\theta(\mathbf{x})\), \(f(\mathbf{x};\theta)\)
Gradient taken with respect to it rarely always: \(\nabla_\theta L\)

Count parameters from the shapes. This is a fast way to check a design.

params = {"W1": (32, 64), "b1": (32,), "W2": (10, 32), "b2": (10,)}
total = 0
for name, shape in params.items():
    count = int(np.prod(shape))
    total += count
    print(f"{name}: {str(shape):10s} -> {count:5d}")
print("total parameters:", total)
W1: (32, 64)   ->  2048
b1: (32,)      ->    32
W2: (10, 32)   ->   320
b2: (10,)      ->    10
total parameters: 2410

2.7 Computational graphs

A computational graph draws a formula as nodes and arrows. Each node is a value or one operation. Each arrow says “this value feeds that operation”.

Graphs make dependencies explicit. They answer: “if this input changes, which outputs change?” In Chapter 18, we use them to compute gradients.

nodes = {"X": (0, 1.0, "X"), "W1": (0, 2.2, "W₁"), "b1": (0, -0.2, "b₁"),
         "lin1": (1.6, 1.0, "lin"), "act": (3.0, 1.0, "σ"),
         "W2": (3.0, 2.4, "W₂"), "b2": (3.0, -0.4, "b₂"),
         "lin2": (4.5, 1.0, "lin"), "L": (6.0, 1.0, "L"), "y": (6.0, 2.4, "y")}
edges = [("X", "lin1"), ("W1", "lin1"), ("b1", "lin1"), ("lin1", "act"),
         ("act", "lin2"), ("W2", "lin2"), ("b2", "lin2"),
         ("lin2", "L"), ("y", "L")]
fig, ax = plt.subplots(figsize=(9, 3.4))
draw_graph(ax, nodes, edges)
plt.show()

2.8 How to read an equation

We now apply the language to Equation 2.1. The method has four steps.

  1. List the symbols. Name each one and give its kind (scalar, vector, matrix).
  2. Write the shapes. Use the context to find them.
  3. Check the operations. Do the shapes allow each operation?
  4. State what it does in one sentence.
Symbol Kind Shape Role
\(Q\) matrix \((T, d_k)\) one query row per token
\(K\) matrix \((T, d_k)\) one key row per token
\(V\) matrix \((T, d_v)\) one value row per token
\(QK^{\intercal}\) matrix \((T, d_k)(d_k, T)=(T, T)\) similarity of every query with every key
\(\sqrt{d_k}\) scalar \(()\) a scale factor
softmax operation \((T,T)\to(T,T)\) each row becomes a probability distribution
result matrix \((T,T)(T,d_v)=(T, d_v)\) one output row per token

One sentence: “Each token gets a new vector that is a weighted average of all value vectors. The weights come from query–key similarity.”

You did not need to know what attention is. The shapes and operations already tell most of the story. Chapter 30 derives the equation from first principles.

2.9 Failure modes

Same symbol, different meaning. Papers reuse letters. \(\mathbf{W}\) may be a weight matrix in one and a window in another. Always check the definition near the equation.

Row versus column. Some papers write \(\mathbf{y} = \mathbf{x}\mathbf{W}\) (row vector). Others write \(\mathbf{y}=\mathbf{W}\mathbf{x}\). The results differ by a transpose. Check the shapes.

A transposed product that still runs. For a square matrix, \(\mathbf{W}\mathbf{x}\) and \(\mathbf{W}^{\intercal}\mathbf{x}\) have the same shape. Code runs without error. The numbers are wrong.

W = rng.normal(size=(3, 3)); x = rng.normal(size=3)
print("shapes equal:", (W @ x).shape == (W.T @ x).shape)
print("values equal:", np.allclose(W @ x, W.T @ x))
shapes equal: True
values equal: False

Silent broadcasting. Chapter 3 showed that (3,) + (3, 1) has shape (3, 3). Assert shapes at the places where a mistake is likely.

2.10 System connection

NoteWhat the system gained in this chapter

The system now has a language. We can write a model as a function with a signature, check every step by its shape, count its parameters, and draw its dependencies. We can also read an equation from a paper symbol by symbol.

Part II uses this language to study the objects themselves. Chapter 3 studied vectors. Chapter 4 adds geometry to them.

Chapter summary

  • A model is a function \(f_\theta:\mathbb{R}^{d_{\text{in}}}\to\mathbb{R}^{d_{\text{out}}}\). The signature is a contract.
  • Scalars, vectors, matrices, and tensors differ in the number of axes.
  • Index notation \(y_i=\sum_jW_{ij}x_j\) is a loop. einsum writes it directly.
  • Shapes are a type system. Write the shape next to every quantity.
  • Parameters are counted from shapes.
  • A computational graph shows dependencies.
  • To read an equation: list symbols, write shapes, check operations, state it in one sentence.

Exercises

  1. Translate. Write \(y_i = \sum_{j} W_{ij}x_j + b_i\) as nested loops. Then write it as one NumPy expression.
  2. Shapes. \(\mathbf{X}\) has shape \((B, T, d)\) and \(\mathbf{W}\) has shape \((d, d')\). What is the shape of X @ W? What does the product mean?
  3. Count. A network has layer sizes 784 → 256 → 128 → 10. Count the parameters, with biases.
  4. einsum. Write einsum strings for: the trace of a matrix, the sum of all entries, the row sums, and the Frobenius norm squared.
  5. Read. For the loss \(L = \frac{1}{N}\sum_i (\mathbf{w}^{\intercal}\mathbf{x}_i + b - y_i)^2\), list the symbols and give the shape of each.
  6. Diagnose. A function returns (X @ W1 + b1).T @ W2. For \(\mathbf{X}:(B,64)\), \(\mathbf{W}_1:(64,32)\), \(\mathbf{W}_2:(32,10)\), find the error.
  7. Diagnose. Explain why W @ x and W.T @ x both run for a square \(\mathbf{W}\). How would you catch a wrong choice?
  8. Draw. Draw the computational graph of \(L = (\mathbf{w}^{\intercal}\mathbf{x}+b-y)^2\).
  9. Design. Choose layer sizes for a classifier from \(32\times32\) RGB images to 100 classes. Give every shape and the parameter count.
  10. Compare. A paper writes \(\mathbf{h} = \mathbf{x}\mathbf{W} + \mathbf{b}\) with \(\mathbf{x}\) a row vector. Rewrite it with column vectors.
