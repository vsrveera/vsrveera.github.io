6  Tensors and High-Dimensional Data

NoteKey ideas
  • A tensor is an array with any number of axes. Its shape lists the size of each axis.
  • Data has standard layouts: image \((H,W,C)\), batch of images \((B,C,H,W)\), sequence batch \((B,T,d)\).
  • Broadcasting lets arrays of different shapes combine. It is powerful and silent.
  • einsum writes any tensor contraction in one line.
  • Reshape changes how we read the numbers, not the numbers. A view shares memory. A copy does not.

6.1 The system problem

So far, one example was one vector. Real systems process many examples at once. They also process data that has more structure than a flat list: images have rows and columns, colours, and frames over time. Text has positions.

How do batches of images, sequences, and activations fit in one array, and how do operations act on them?

The answer is the tensor. Almost every number inside a neural network lives in a tensor.

6.2 Intuition: a ladder of orders

We already know three objects. A tensor continues the pattern: each new object adds one axis.

Order Object Shape Picture Example
0 scalar () a point loss value
1 vector (d,) a row of cells embedding
2 matrix (m, n) a grid grayscale image, weights
3 3-tensor (H, W, C) a stack of grids RGB image
4 4-tensor (B, C, H, W) a stack of stacks batch of images
5 5-tensor (B, T, C, H, W) a batch of videos video clips 
col = PALETTE["data"]

def cells(ax, nr, nc, dx=0.0, dy=0.0, alpha=0.9):
    for i in range(nr):
        for j in range(nc):
            ax.add_patch(Rectangle((j + dx, -i + dy), 0.9, 0.9,
                                   fc=col, ec="white", alpha=alpha))

titles = ["scalar ()", "vector (d,)", "matrix (m, n)", "tensor (C, m, n)"]
sizes = [(1, 1), (1, 5), (4, 5), (4, 5)]
fig, axes = plt.subplots(1, 4, figsize=(10, 2.8))
for ax, title, (nr, nc) in zip(axes, titles, sizes):

plt.tight_layout(); plt.show()

The ladder has no top. A tensor of any order is a table of numbers with one index per axis.

6.3 The mathematical object

A tensor of order \(k\) is a function that assigns one real number to each tuple of \(k\) indices. We write \(\mathcal{X}\in\mathbb{R}^{n_{1}\times n_{2}\times\cdots\times n_k}\) and \(\mathcal{X}_{i_1 i_{2}\cdots i_k}\) for one entry.

The shape \((n_1,\dots,n_k)\) is the key. The number of entries is the product of the sizes:

\[ \text{size}(\mathcal{X}) = n_1\, n_{2}\cdots n_k. \tag{6.1}\]

6.3.1 Standard layouts

Data Layout Axis meaning
Greyscale image \((H, W)\) row, column
Colour image \((H, W, C)\) or \((C, H, W)\) row, column, channel
Image batch \((B, C, H, W)\) example, channel, row, column
Token sequence batch \((B, T)\) of ids example, position
Hidden states \((B, T, d)\) example, position, feature
Attention scores \((B, h, T, T)\) example, head, query position, key position
NoteChannels first or last

Image libraries store colour images as \((H,W,C)\). PyTorch convolutions expect \((B,C,H,W)\). Converting is a permutation of axes. This is a common source of bugs.

We load a real photograph and look at its axes.

6.4 Operations

6.4.1 Reshape and permute

Reshape changes the shape but keeps the order of the numbers in memory. The total size must stay the same. Permute (transpose) reorders the axes and so changes which numbers sit next to each other.

x = np.arange(24)                       # (24,)
a = x.reshape(2, 3, 4)                  # (2, 3, 4)
b = a.transpose(1, 0, 2)                # (3, 2, 4)  axes permuted
print("a[0, 1, 2] =", a[0, 1, 2], "   b[1, 0, 2] =", b[1, 0, 2])   # same entry
print("a.reshape(6, 4) rows 0-1:\n", a.reshape(6, 4)[:2])
a[0, 1, 2] = 6    b[1, 0, 2] = 6
a.reshape(6, 4) rows 0-1:
 [[0 1 2 3]
 [4 5 6 7]]

Converting an image batch from the library layout to the network layout is one permute:

crops = [img[:100, :100], img[100:200, 100:200]]
batch_hwc = np.stack(crops)                    # (2, 100, 100, 3)
batch_chw = batch_hwc.transpose(0, 3, 1, 2)    # (2, 3, 100, 100)
print(batch_hwc.shape, "->", batch_chw.shape)
(2, 100, 100, 3) -> (2, 3, 100, 100)

6.4.2 Broadcasting

Broadcasting lets an operation combine arrays of different shapes. The rule has two steps.

  1. Align the shapes at the right end. Pad on the left with size 1.
  2. For each axis, the sizes must be equal, or one of them must be \(1\). A size-1 axis is stretched to match.
Left Right Result Valid?
(3, 4) (4,) (3, 4) yes
(3, 1) (1, 4) (3, 4) yes
(B, T, d) (d,) (B, T, d) yes (bias)
(3, 4) (3,) — no: 4 vs 3 
col_v = np.array([[10], [20], [30]])        # (3, 1)
row_v = np.array([[1, 2, 3, 4]])            # (1, 4)
out = col_v + row_v                         # (3, 4)

fig, axes = plt.subplots(1, 3, figsize=(8.5, 2.6),
                         gridspec_kw={"width_ratios": [1, 4, 4]})
titles = ["(3, 1)", "(1, 4)", "sum  (3, 4)"]
for ax, arr, title in zip(axes, [col_v, row_v, out], titles):
    ax.imshow(np.ones_like(arr), cmap="Blues", vmin=0, vmax=2)
    for (i, j), v in np.ndenumerate(arr):
        ax.text(j, i, str(v), ha="center", va="center", fontsize=11)
    ax.set_title(title)
    ax.set_xticks([]); ax.set_yticks([]); ax.grid(False)
plt.tight_layout(); plt.show()

Broadcasting is the reason X @ W.T + b works in a layer: the bias of shape (d_out,) is stretched over the batch axis.

One practical use is to normalise each colour channel of an image. We compute a mean per channel and subtract it from every pixel.

x = img.astype(np.float64) / 255.0                  # (H, W, 3)
mean = x.mean(axis=(0, 1), keepdims=True)           # (1, 1, 3)
std = x.std(axis=(0, 1), keepdims=True)             # (1, 1, 3)
z = (x - mean) / std                                # broadcast over H and W
print("mean shape:", mean.shape)
print("z mean per channel:", np.round(z.mean(axis=(0, 1)), 6))
print("z std  per channel:", np.round(z.std(axis=(0, 1)), 3))
mean shape: (1, 1, 3)
z mean per channel: [0. 0. 0.]
z std  per channel: [1. 1. 1.]

The option keepdims=True keeps the reduced axes with size 1. This is what makes the result broadcast correctly.

6.4.3 Reductions

A reduction removes an axis by summing, averaging, or taking a max over it. The axis argument names the axis that disappears.

6.4.4 Contraction and einsum

Matrix product sums over one shared index. A general contraction sums over any shared indices. einsum writes this directly (Chapter 2). A key example is the attention score of Chapter 30:

\[ S_{b,h,t,s}=\sum_{k}Q_{b,t,h,k}\,K_{b,s,h,k}. \tag{6.2}\]

rng = np.random.default_rng(0)
B_, T, h, dk = 2, 5, 4, 8
Q = rng.normal(size=(B_, T, h, dk))         # (B, T, h, d_k)
K = rng.normal(size=(B_, T, h, dk))

S = np.einsum("bthd,bshd->bhts", Q, K)      # (B, h, T, T)
S_mm = Q.transpose(0, 2, 1, 3) @ K.transpose(0, 2, 3, 1)   # (B,h,T,dk)@(B,h,dk,T)
print("scores shape:", S.shape, "  equals batched matmul:", np.allclose(S, S_mm))
scores shape: (2, 4, 5, 5)   equals batched matmul: True

6.5 Memory: strides, views, and copies

A tensor is stored as one flat block of numbers. The strides say how many bytes to skip to move one step along each axis.

a = np.arange(24, dtype=np.float64).reshape(2, 3, 4)
print("a.strides   :", a.strides, " (bytes per step along each axis)")
t = a.transpose(1, 0, 2)
print("t.strides   :", t.strides, " same memory, permuted strides")
print("t shares memory with a   :", np.shares_memory(a, t))
print("t is C-contiguous        :", t.flags["C_CONTIGUOUS"])
r = t.reshape(6, 4)                  # needs a copy: not contiguous
print("t.reshape shares memory  :", np.shares_memory(t, r))
a.strides   : (96, 32, 8)  (bytes per step along each axis)
t.strides   : (32, 96, 8)  same memory, permuted strides
t shares memory with a   : True
t is C-contiguous        : False
t.reshape shares memory  : False
  • A view (slice, transpose) shares memory. It is free but changing it changes the original.
  • A copy has its own memory. It is safe but costs time and space.
  • Some operations need contiguous memory and make a copy silently.

6.5.1 Memory of activations

The size of a tensor in bytes is its entry count times the bytes per entry. For attention scores, the entry count grows with \(T^2\):

\[ \text{bytes}=B\cdot h\cdot T^{2}\cdot(\text{bytes per number}). \tag{6.3}\]

Ts = np.array([512, 1024, 2048, 4096, 8192, 16384, 32768, 65536])
bytes_ = 1 * 16 * Ts.astype(float) ** 2 * 2        # B * h * T^2 * 2 bytes (fp16)
fig, ax = plt.subplots()
ax.loglog(Ts, bytes_, "o-", color=PALETTE["loss"])
ax.axhline(80e9, ls="--", color=PALETTE["neutral"]); ax.text(600, 95e9, "80 GB")
ax.set_xlabel("sequence length T"); ax.set_ylabel("bytes (one layer)")
plt.show()
print(f"T = 65,536: {bytes_[-1] / 1e9:.0f} GB")
T = 65,536: 137 GB

This is why long-context models need special attention kernels that never form the full \(T\times T\) tensor (Chapter 34).

6.6 Patches: reshaping an image into tokens

Reshape and permute can cut an image into square patches. This is the first step of a Vision Transformer (Chapter 36). We do it with two lines.

P = 16
H, W = 416, 640
crop = img[:H, :W]                                           # (416, 640, 3)
patches = (crop.reshape(H // P, P, W // P, P, 3)    # split rows, columns
               .transpose(0, 2, 1, 3, 4)             # (26, 40, P, P, 3)
               .reshape(-1, P, P, 3))                # (1040, P, P, 3)
print("patches:", patches.shape, "  per patch values:", P * P * 3)

fig = plt.figure(figsize=(9, 5))
ax = fig.add_axes([0.05, 0.28, 0.9, 0.7]); ax.imshow(crop)
for i in range(0, H + 1, P): ax.axhline(i - 0.5, color="white", lw=0.4)
for j in range(0, W + 1, P): ax.axvline(j - 0.5, color="white", lw=0.4)
ax.axis("off")
for k, idx in enumerate([0, 300, 520, 800, 1030]):
    pa = fig.add_axes([0.1 + k * 0.17, 0.03, 0.12, 0.2])
    pa.imshow(patches[idx])
    pa.set_xticks([]); pa.set_yticks([]); pa.grid(False)
    pa.set_title(f"patch {idx}", fontsize=8)
plt.show()
patches: (1040, 16, 16, 3)   per patch values: 768

Each patch contains \(16\times16\times3=768\) numbers. A linear layer maps it to a token embedding. The whole image becomes a sequence of \(26\times40=1040\) tokens, each a vector.

6.7 From first principles to production

PyTorch tensors follow the same rules. Two differences matter in practice: view fails on non-contiguous data, and tensors can live on a GPU and track gradients.

import torch

xt = torch.arange(24.0).reshape(2, 3, 4)
tt = xt.permute(1, 0, 2)                               # view with new strides
print("permute is contiguous:", tt.is_contiguous())
try:
    tt.view(6, 4)                                      # needs contiguous memory
except RuntimeError as e:
    print("view failed:", str(e)[:60], "...")
print("reshape works:", tuple(tt.reshape(6, 4).shape))
print("contiguous().view:", tuple(tt.contiguous().view(6, 4).shape))

S_t = torch.einsum("bthd,bshd->bhts", torch.tensor(Q), torch.tensor(K))
print("einsum matches NumPy:", np.allclose(S_t.numpy(), S))
permute is contiguous: False
view failed: view size is not compatible with input tensor's size and str ...
reshape works: (6, 4)
contiguous().view: (6, 4)
einsum matches NumPy: True

6.8 Failure modes

6.8.1 Silent broadcasting in a loss

Predictions of shape (B, 1) and targets of shape (B,) look compatible. They are not what we want:

B_ = 4
y_pred = np.array([[1.0], [2.0], [3.0], [4.0]])        # (B, 1)
y_true = np.array([1.0, 2.0, 3.0, 4.0])      # (B,)  predictions perfect

wrong = np.mean((y_pred - y_true) ** 2)                # broadcast to (B, B)!
right = np.mean((y_pred[:, 0] - y_true) ** 2)
print("(y_pred - y_true).shape =", (y_pred - y_true).shape)
print(f"wrong loss = {wrong:.3f}    correct loss = {right:.3f}")
(y_pred - y_true).shape = (4, 4)
wrong loss = 2.500    correct loss = 0.000

A perfect model reports a non-zero loss. The code runs without any error. Always check the shape of the loss inputs.

6.8.2 Integer overflow in image data

Images are stored as 8-bit unsigned integers. Arithmetic wraps around:

a = np.array([200], dtype=np.uint8)
b = np.array([100], dtype=np.uint8)
print("uint8: 200 + 100 =", (a + b)[0], "   float: ", float(a[0]) + float(b[0]))
uint8: 200 + 100 = 44    float:  300.0

Convert to float before arithmetic.

6.8.3 Other failures

  • Wrong axis in a reduction. mean(axis=0) and mean(axis=1) give different shapes. State the shape you expect.
  • View modified in place. Changing a slice changes the original array.
  • Out of memory. Activation memory grows with \(B\), \(T\), depth, and (for attention) \(T^2\).
  • Layout mismatch. Passing \((H,W,C)\) where \((C,H,W)\) is expected can run and give nonsense.

Place Tensor

6.10 System connection

NoteWhat the system gained in this chapter

The system can now hold batches and structured data: images with rows, columns, and channels, sequences with positions, and the hidden states of a deep network. It has the tools to reshape them, combine them by broadcasting, and contract them with einsum.

The data is still treated as raw numbers. Chapter 7 looks inside these arrays for structure that allows a smaller description.

Chapter summary

  • A tensor is an array with \(k\) axes. The shape lists the sizes.
  • Standard layouts: image \((H,W,C)\) or \((B,C,H,W)\), sequences \((B,T,d)\), attention \((B,h,T,T)\).
  • Reshape keeps the memory order. Permute reorders axes.
  • Broadcasting: align at the right, sizes equal or 1.
  • einsum expresses any contraction.
  • Views share memory. Copies do not. Strides describe the layout.
  • Attention-score memory grows as \(T^2\).
  • Typical failures: silent broadcasting, integer overflow, wrong layout, out of memory.
