3  Vectors: Representing Information

NoteKey ideas
  • A vector is an ordered list of numbers. It is also a point, and also an arrow.
  • Each number in a vector is a feature: one measured property of an object.
  • Vectors can be added and scaled. These two operations define a vector space.
  • A basis is a set of vectors that gives each point a unique set of coordinates. The coordinates depend on the basis. The vector does not.
  • An image is a vector. A word is a vector. An embedding is a vector that a model learns for an object.

3.1 The system problem

A model computes with numbers. The world does not give numbers. The world gives photos, sentences, sounds, and records.

Before a model can learn anything, we must answer one question:

How can an image, a word, or a customer exist inside a computer so that a model can work with it?

The answer is a vector. This chapter shows what a vector is, which operations it supports, and why this one object is the starting point of every AI system in this book.

Two running systems start here.

  • System A, Image Classifier: image → vector → class.
  • System B, Semantic Search: text → vector → similarity → retrieval.

3.2 Intuition: three views of one object

Take a house. We measure three properties: area in square meters, number of rooms, and age in years.

\[ \text{house} \;\longrightarrow\; (120,\; 4,\; 15) \]

This list of numbers is a vector. It can be read in three ways. All three are useful.

View Meaning Useful for
List An ordered collection of numbers Storage, code
Point A location in a space with one axis per number Geometry, distance
Arrow A movement from the origin to the point Direction, change

The order matters. \((120, 4, 15)\) and \((15, 4, 120)\) are different houses.

Each number is a feature. Choosing features is the first act of representation. A different choice of features gives a different space and a different problem.

v = np.array([3.0, 2.0])
fig, ax = plt.subplots(figsize=(4.8, 3.8))

ax.plot([0, v[0]], [v[1], v[1]], "--", color=PALETTE["neutral"])
ax.scatter(*v, color=PALETTE["model"], zorder=3)
draw_arrow(ax, v, label="$\\mathbf{x} = (3, 2)$")
ax.text(v[0], -0.35, "$x_1 = 3$", ha="center", color=PALETTE["neutral"])
ax.text(-0.45, v[1], "$x_2 = 2$", va="center", color=PALETTE["neutral"])
plt.show()

3.3 The mathematical object

A vector with \(d\) components is an ordered list of \(d\) real numbers. We write

\[ \mathbf{x} = \begin{pmatrix} x_1 \\ x_2 \\ \vdots \\ x_d \end{pmatrix} \in \mathbb{R}^d. \tag{3.1}\]

Read \(\mathbb{R}^d\) as “the set of all lists of \(d\) real numbers”. The number \(d\) is the dimension. We write vectors in bold lowercase. The \(i\)-th component is \(x_i\), a plain scalar.

NoteNotation reminder

Chapter 2 fixes the full notation. For now, remember three rules.

  • A scalar is a single number: \(a\), \(\lambda\).
  • A vector is a bold lowercase letter: \(\mathbf{x}\). By default it is a column.
  • \(\mathbb{R}^d\) is the space of all vectors with \(d\) components.

In NumPy, a vector is a one-dimensional array. Its shape is (d,).

x = np.array([120.0, 4.0, 15.0])   # (3,)   area, rooms, age
print("shape:", x.shape)
print("dimension:", x.shape[0])
print("first component:", x[0])
shape: (3,)
dimension: 3
first component: 120.0

3.4 Operations

Two operations make a set of vectors into a vector space.

Addition. Add two vectors component by component.

\[ \mathbf{u} + \mathbf{v} = (u_1 + v_1,\; u_2 + v_2,\; \dots,\; u_d + v_d) \tag{3.2}\]

Scaling. Multiply every component by one scalar \(c\).

\[ c\,\mathbf{v} = (c\,v_1,\; c\,v_2,\; \dots,\; c\,v_d) \tag{3.3}\]

Both operations must give a vector in the same space. This property is called closure. A vector space also needs a zero vector, and each vector needs a negative. In \(\mathbb{R}^d\) all these rules hold.

u, w = np.array([2.0, 1.0]), np.array([1.0, 2.0])
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(9, 3.8))

setup_2d(ax1, xlim=(-0.5, 4.5), ylim=(-0.5, 4.0))
draw_arrow(ax1, u, color=PALETTE["data"], label="u")
draw_arrow(ax1, w, color=PALETTE["prob"], label="v")
draw_arrow(ax1, w, origin=u, color=PALETTE["prob"], ls="--", lw=1)
draw_arrow(ax1, u, origin=w, color=PALETTE["data"], ls="--", lw=1)
draw_arrow(ax1, u + w, color=PALETTE["model"], label="u + v", lw=2.5)

setup_2d(ax2, xlim=(-2, 5), ylim=(-2, 4.5))
scales = [(2, PALETTE["model"]), (1, PALETTE["prob"]), (-0.5, PALETTE["loss"])]
for c, col in scales:
    draw_arrow(ax2, c * w, color=col, label=f"{c}v")
plt.tight_layout(); plt.show()

3.4.1 Linear combination

Addition and scaling together give the most important idea of linear algebra. A linear combination of vectors \(\mathbf{b}_1, \dots, \mathbf{b}_k\) is

\[ \mathbf{v} = c_1 \mathbf{b}_1 + c_2 \mathbf{b}_2 + \dots + c_k \mathbf{b}_k. \tag{3.4}\]

The scalars \(c_i\) are the coefficients. The set of all linear combinations of a list of vectors is their span.

Linear combinations appear everywhere in AI. A linear layer \(\mathbf{W}\mathbf{x}\) computes one. A weighted average of embeddings is one. The attention output in Chapter 30 is one.

b1, b2 = np.array([1.0, 0.0]), np.array([0.0, 1.0])
v = 3 * b1 + 2 * b2        # a linear combination of b1 and b2
print(v)
[3. 2.]

3.5 Basis and coordinates

A list of numbers describes a vector only relative to something. The list \((3, 2)\) means “three steps along \(\mathbf{b}_1\) and two steps along \(\mathbf{b}_2\)”. Here, \(\mathbf{b}_1 = (1, 0)\) and \(\mathbf{b}_2 = (0, 1)\) are the standard basis.

A basis of a space is a list of vectors with two properties:

  1. Spanning. Every vector in the space is a linear combination of the list.
  2. Independence. No vector in the list is a linear combination of the others.

These two properties together guarantee that every vector has exactly one list of coefficients. This list is its coordinates in that basis.

\[ \mathbf{v} = c_1 \mathbf{b}_1 + c_2 \mathbf{b}_2 \quad\Longleftrightarrow\quad [\mathbf{v}]_B = (c_1, c_2) \tag{3.5}\]

The number of vectors in a basis is the dimension of the space. All bases of \(\mathbb{R}^d\) have exactly \(d\) vectors.

TipDerivation: coordinates in a skew basis

Let \(\mathbf{v} = (3, 2)\). Choose the basis \(\mathbf{b}_1 = (1, 0)\) and \(\mathbf{b}_2 = (1, 1)\). We look for \(c_1, c_2\) such that

\[ c_1 \begin{pmatrix}1\\0\end{pmatrix} + c_2 \begin{pmatrix}1\\1\end{pmatrix} = \begin{pmatrix}3\\2\end{pmatrix}. \]

Write one equation per component:

\[ c_1 + c_2 = 3, \qquad c_2 = 2. \]

The second equation gives \(c_2 = 2\). The first gives \(c_1 = 1\). So \([\mathbf{v}]_B = (1, 2)\).

The vector did not change. Only the description changed.

v = np.array([3.0, 2.0])
B = np.array([[1.0, 1.0],      # columns are the basis vectors b1, b2
              [0.0, 1.0]])
coords = np.linalg.solve(B, v)  # solve B @ c = v
assert np.allclose(B @ coords, v)

std = np.eye(2)                    # columns: the standard basis
bases = [(std, "standard basis:  (3, 2)"),
         (B, f"skew basis:  ({coords[0]:.0f}, {coords[1]:.0f})")]

fig, axes = plt.subplots(1, 2, figsize=(9, 3.8))
for ax, (basis, title) in zip(axes, bases):
    setup_2d(ax, xlim=(-0.5, 5), ylim=(-0.5, 3.5))
    draw_basis_grid(ax, basis[:, 0], basis[:, 1])
    for k, (name, col) in enumerate([("$\\mathbf{b}_1$", PALETTE["data"]),
                                     ("$\\mathbf{b}_2$", PALETTE["prob"])]):
        draw_arrow(ax, basis[:, k], color=col, label=name)
    draw_arrow(ax, v, color=PALETTE["model"], lw=3)
    ax.set_title(title, fontsize=11)
plt.tight_layout(); plt.show()

Two facts will return in later chapters.

  1. Change of basis is a matrix operation. The solve call above finds coordinates in a new basis. Chapter 5 shows this as a matrix.
  2. A good basis makes a problem simple. PCA (Chapter 7) searches for the best basis for a dataset.
NoteLooking ahead

In an orthonormal basis, each coordinate is a dot product. We develop the dot product in Chapter 4.

3.6 Images as vectors

Now we apply the idea to System A. An image is a grid of brightness values. A grayscale image of \(8 \times 8\) pixels has 64 numbers. Read the grid row by row. The result is a vector in \(\mathbb{R}^{64}\).

\[ \text{image} \in \mathbb{R}^{8\times 8} \;\xrightarrow{\text{flatten}}\; \mathbf{x} \in \mathbb{R}^{64} \tag{3.6}\]

from sklearn.datasets import load_digits
digits = load_digits()
images, labels = digits.images, digits.target       # (1797, 8, 8), (1797,)

img = images[3]                                      # (8, 8)
x_img = img.reshape(-1)                              # (64,)
print("image shape:", img.shape, "-> vector shape:", x_img.shape)

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(9, 3),
                               gridspec_kw={"width_ratios": [1, 2.4]})
ax1.imshow(img, cmap="gray_r")
ax1.set_title(f"digit {labels[3]}, 8×8")
ax1.set_xticks([]); ax1.set_yticks([]); ax1.grid(False)
ax2.bar(np.arange(64), x_img, color=PALETTE["data"])
ax2.set_xlabel("component index $i$"); ax2.set_ylabel("$x_i$")
plt.tight_layout(); plt.show()
image shape: (8, 8) -> vector shape: (64,)

The flatten operation loses the layout of the image. The vector does not store which pixels are neighbors. Chapter 6 (tensors) and Chapter 12 (convolution) recover this structure.

3.6.1 Vector arithmetic on images

Vector operations now have a visual meaning. The mean of many digit-0 vectors is the “average zero”. A linear combination of two class means blends them.

X = images.reshape(len(images), -1)                  # (1797, 64)
mean0 = X[labels == 0].mean(axis=0)                  # (64,)
mean1 = X[labels == 1].mean(axis=0)                  # (64,)

ts = np.linspace(0, 1, 6)
fig, axes = plt.subplots(1, 6, figsize=(9, 1.9))
for ax, t in zip(axes, ts):
    blend = (1 - t) * mean0 + t * mean1              # linear combination
    ax.imshow(blend.reshape(8, 8), cmap="gray_r", vmin=0, vmax=16)
    ax.set_title(f"t = {t:.1f}", fontsize=9)
    ax.set_xticks([]); ax.set_yticks([]); ax.grid(False)
plt.tight_layout(); plt.show()

3.7 Words as vectors

Now we turn to System B. A word is not a number. We must choose a vector for it. There are two basic choices.

3.7.1 One-hot vectors

Give each word in a vocabulary an index. The one-hot vector for word number \(t\) has a 1 at position \(t\) and 0 everywhere else.

\[ \mathbf{o}_t = (0, \dots, 0, \underbrace{1}_{\text{position } t}, 0, \dots, 0) \in \mathbb{R}^{V} \tag{3.7}\]

Here \(V\) is the vocabulary size. One-hot vectors are simple and exact. They have two weaknesses.

  1. They are very long: \(V\) can be 50,000 or more.
  2. They contain no meaning. Every pair of different words is equally far apart. “cat” is no closer to “kitten” than to “tax”.

3.7.2 Embeddings

An embedding gives each word a short, dense vector, with \(d \ll V\) components. A model learns the numbers. Words with similar roles receive nearby vectors.

All the embeddings are rows of one table, the embedding matrix \(\mathbf{E} \in \mathbb{R}^{V \times d}\). Getting the embedding for token \(t\) is a table lookup:

\[ \mathbf{e}_t = \mathbf{E}[t, :] \tag{3.8}\]

vocab = ["the", "cat", "sat", "on", "mat"]
V, d = len(vocab), 3
rng = np.random.default_rng(0)
E = rng.normal(size=(V, d))                  # (V, d)  one row per word

t = vocab.index("cat")
one_hot = np.zeros(V); one_hot[t] = 1.0      # (V,)

lookup = E[t]                                # table lookup, (d,)
matmul = one_hot @ E                         # one-hot times matrix, (d,)
assert np.allclose(lookup, matmul)
print("lookup == one_hot @ E :", np.allclose(lookup, matmul))
lookup == one_hot @ E : True

A lookup is the same as multiplying a one-hot vector by \(\mathbf{E}\). Chapter 5 explains this product. Real systems use the lookup form because it is much faster.

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(8.5, 3.2),
                               gridspec_kw={"width_ratios": [5, 3]})
ax1.imshow(np.eye(V), cmap="Blues", vmin=0, vmax=1)
ax1.set_title("one-hot  (V × V)"); ax1.set_xlabel("position")
ax2.imshow(E, cmap="RdBu", vmin=-2.5, vmax=2.5)
ax2.set_title("embedding  (V × d)"); ax2.set_xlabel("feature")
for ax in (ax1, ax2):
    ax.set_yticks(range(V)); ax.set_yticklabels(vocab); ax.grid(False)
plt.tight_layout(); plt.show()

3.7.3 A hand-built embedding

A trained embedding has hundreds of features that no person can name. To see the geometry, we build a tiny embedding by hand. Each feature has a clear meaning.

WarningImportant

This embedding is constructed, not learned. It illustrates a property that learned embeddings show only approximately. We study learned embeddings in Chapters 13 and 38.

The three features are royalty, gender (+1 male, −1 female), and adult.

# features:   royalty, gender (+1 male, -1 female), adult
table = {"man":   (0,  1, 1),   "woman":    (0, -1, 1),
         "king":  (1,  1, 1),   "queen":    (1, -1, 1),
         "boy":   (0,  1, 0),   "girl":     (0, -1, 0),
         "prince": (1, 1, 0),   "princess": (1, -1, 0)}
emb = {w: np.array(v, dtype=float) for w, v in table.items()}

target = emb["king"] - emb["man"] + emb["woman"]       # vector arithmetic
print("king - man + woman =", target)

# nearest word by straight-line distance (Chapter 4 defines distance)
dists = {w: np.sqrt(np.sum((v - target) ** 2)) for w, v in emb.items()}
print("nearest word:", min(dists, key=dists.get))
king - man + woman = [ 1. -1.  1.]
nearest word: queen

The answer is “queen”. The direction from “man” to “woman” is the same as the direction from “king” to “queen”. Vector subtraction extracts this direction. Vector addition applies it.

p = {w: emb[w][:2] for w in ["man", "woman", "king", "queen"]}   # royalty, gender
fig, ax = plt.subplots(figsize=(5.2, 4))
setup_2d(ax, xlim=(-0.5, 1.7), ylim=(-1.6, 1.6),
         xlabel="royalty", ylabel="gender")
for w, pt in p.items():
    ax.scatter(*pt, color=PALETTE["data"], zorder=3, s=50)
    ax.text(pt[0] + 0.07, pt[1] + 0.1, w, fontsize=11)
orange, purple = PALETTE["model"], PALETTE["prob"]
draw_arrow(ax, p["woman"] - p["man"], origin=p["man"], color=orange)
draw_arrow(ax, p["queen"] - p["king"], origin=p["king"], color=orange)
dash = dict(color=purple, ls="--", lw=1.2)
draw_arrow(ax, p["king"] - p["man"], origin=p["man"], **dash)
draw_arrow(ax, p["queen"] - p["woman"], origin=p["woman"], **dash)
plt.show()

3.8 The representation pipeline

We can now state the whole mechanism of this chapter. Every AI system starts with the same step.

labels = ["world object\n(photo, text)", "encode\n(features, lookup)",
          "vector  x ∈ ℝᵈ", "model"]
colors = [PALETTE[k] for k in ["neutral", "data", "model", "prob"]]

The encode step is a design choice. It decides what information the model can use. If the encoding loses a fact, no later step can recover it.

3.9 From first principles to production

We built the lookup in NumPy. PyTorch provides the same operation as a learnable layer.

import torch
import torch.nn as nn

torch.manual_seed(0)
E_t = torch.tensor(E, dtype=torch.float32)               # (V, d)
layer = nn.Embedding(num_embeddings=V, embedding_dim=d)  # holds E
with torch.no_grad():
    layer.weight.copy_(E_t)

ids = torch.tensor([0, 1, 2])            # tokens: the, cat, sat   (3,)
out = layer(ids)                         # (3, d)
print("output shape:", tuple(out.shape))
assert torch.allclose(out, E_t[ids])
print("PyTorch lookup matches NumPy lookup.")
print("trainable parameters:", sum(q.numel() for q in layer.parameters()))
output shape: (3, 3)
PyTorch lookup matches NumPy lookup.
trainable parameters: 15

Note the last line. The embedding table is part of \(\theta\). The entries of \(\mathbf{E}\) are parameters. The model changes them during training, exactly as it changed \(a\) and \(b\) in Chapter 1. A language model with a 50,000-word vocabulary and \(d = 4096\) has \(50{,}000 \times 4{,}096 \approx 2 \times 10^{8}\) parameters in this one table.

3.10 Failure modes and edge cases

Vectors are simple. Mistakes with them are common and often silent.

3.10.1 Shape errors that do not raise an error

A vector of shape (3,) and a column of shape (3, 1) look the same when printed. They behave differently.

a = np.array([1.0, 2.0, 3.0])        # (3,)
b = a.reshape(3, 1)                  # (3, 1)

print("a + a shape:", (a + a).shape)    # (3,)   element-wise, as intended
print("a + b shape:", (a + b).shape)    # (3, 3) broadcasting — usually a bug
a + a shape: (3,)
a + b shape: (3, 3)

The second sum has nine numbers, not three. NumPy and PyTorch broadcast silently. Use assert x.shape == (d,) where a wrong shape is likely.

3.10.2 Features on different scales

Take two features: area in square meters (about 50–300) and rooms (about 1–6). A model that uses straight-line distance will see area as 50 times more important only because its numbers are larger. We fix this by standardizing each feature to zero mean and unit spread.

rng = np.random.default_rng(1)
area  = rng.uniform(50, 300, size=100)
rooms = rng.integers(1, 7, size=100).astype(float)
H = np.column_stack([area, rooms])                     # (100, 2)

Hs = (H - H.mean(axis=0)) / H.std(axis=0)              # (100, 2) standardized
print("raw spread     :", np.round(H.std(axis=0), 2))
print("standardized   :", np.round(Hs.std(axis=0), 2))
raw spread     : [71.76  1.73]
standardized   : [1. 1.]

3.10.3 Limited precision

Computers store real numbers with finite precision. Half-precision (float16) is common in deep learning. It cannot represent small differences near 1.

print("float16: 1 + 0.0004 =", np.float16(1.0) + np.float16(0.0004))
print("float32: 1 + 0.0004 =", np.float32(1.0) + np.float32(0.0004))
print("float16: 2049 is stored as", float(np.float16(2049)))
float16: 1 + 0.0004 = 1.0
float32: 1 + 0.0004 = 1.0004
float16: 2049 is stored as 2048.0

A small change to an embedding can disappear. Training in low precision needs care. Chapter 34 returns to this.

3.10.4 High dimension changes geometry

Many features are not always better. In high dimension, the straight-line distances between random points become almost equal. The nearest point is barely nearer than the farthest.

rng = np.random.default_rng(0)
dims = np.unique(np.logspace(0, 3, 15).astype(int))
contrast = []
for dim in dims:
    P = rng.uniform(size=(500, dim))       # (500, dim) random points
    q = rng.uniform(size=(1, dim))         # (1, dim)   query point
    dist = np.sqrt(((P - q) ** 2).sum(axis=1))
    contrast.append((dist.max() - dist.min()) / dist.min())

fig, ax = plt.subplots()
ax.loglog(dims, contrast, "o-", color=PALETTE["loss"])
ax.set_xlabel("dimension $d$")
ax.set_ylabel("(farthest − nearest) / nearest")
plt.show()

Real data often lies near a structure of much lower dimension. This reduces the problem. We study this in Chapter 7.

3.11 Where this appears in modern AI

System Object Vector Typical \(d\)
Image classifier image flattened pixels, then feature vector \(10^3\) – \(10^6\) pixels → \(10^2\) – \(10^3\) features
Semantic search sentence sentence embedding 384 – 1536
Language model token token embedding (row of \(\mathbf{E}\)) 768 – 12,288
Recommender user, item user / item embedding 32 – 512
Image generator image latent vector \(10^3\) – \(10^5\)
CLIP-style model image, text joint-space embeddings 512 – 1024

Every row has the same shape: object → vector in \(\mathbb{R}^d\). The rest of the book computes on those vectors.

3.12 System connection

NoteWhat the system gained in this chapter

The system can now hold any object as a vector. It has addition and scaling, so it can blend, compare directions, and change coordinates.

It cannot yet answer “how similar are two vectors?” or “how big is this vector?”. These questions need length, angle, and distance. Chapter 4 adds them.

Chapter summary

  • A vector is an ordered list of numbers: a list, a point, or an arrow.
  • Features are the components. The choice of features is a design decision.
  • Addition and scaling define a vector space. A linear combination uses both.
  • A basis gives unique coordinates. Coordinates depend on the basis. The vector does not.
  • Images flatten to vectors. Words become one-hot vectors or learned embeddings.
  • An embedding table \(\mathbf{E}\) is a set of parameters. Lookup equals one-hot times \(\mathbf{E}\).
  • Common failures: silent shape errors, mixed scales, low precision, and high dimension.

  2. Compute. Find the coordinates of \(\mathbf{v} = (5, 3)\) in the basis \(\mathbf{b}_1 = (1, 1)\), \(\mathbf{b}_2 = (1, -1)\).

  6. Code. Blend digit 3 and digit 8 with a coefficient \(t\). At which \(t\) does the image first look more like an 8?
  7. Code. Add the feature “capital letter?” to the toy embedding. Add the words “King” and “Queen” and check the analogy.
  8. Diagnose. A function should return a vector of shape (d,). It returns shape (d, d). Find the likely cause in this chapter.
  9. Explain. Why is a one-hot vector a poor representation when the task needs word similarity?
