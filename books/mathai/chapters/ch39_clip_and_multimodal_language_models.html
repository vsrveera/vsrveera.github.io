39  CLIP and Multimodal Language Models

NoteKey ideas
  • CLIP trains an image encoder and a text encoder so that matching image–text pairs have a high cosine similarity and mismatched pairs a low one: a symmetric InfoNCE loss on a \(B\times B\) similarity matrix.
  • Zero-shot classification is retrieval: embed the class names as text and pick the nearest one to the image embedding.
  • A multimodal LLM feeds image features into a language model by a projector that maps them to the model’s token-embedding space.
  • Cross-attention lets text queries read from image keys and values. A resampler compresses many image tokens into few.
  • Two modalities do not fully overlap in the shared space (the modality gap).

39.1 The system problem

Chapters 36–38 gave us image representations, text representations (Chapters 3, 31), and a way to learn representations from paired views. An image and its caption are two views of the same thing.

How do an image and a sentence land in one space, and how can a language model “see”?

This chapter joins Systems A (images), B (retrieval), and C (language).

39.3 The CLIP objective

Take a batch of \(B\) matched pairs \((\text{image}_i,\text{text}_i)\). The encoders give unit vectors \(\mathbf{z}_I^{(i)},\mathbf{z}_T^{(i)}\in\mathbb{R}^d\). The similarity matrix is

\[ S_{ij}=\frac{\mathbf{z}_I^{(i)}\cdot\mathbf{z}_T^{(j)}}{\tau}. \tag{39.1}\]

The diagonal holds the true pairs. Row \(i\) asks: which text belongs to image \(i\)? Column \(j\) asks: which image belongs to text \(j\)? Each is a \(B\)-way classification (Chapter 24) and the loss is the average of the two cross-entropies, the symmetric InfoNCE of Chapter 38:

\[ \mathcal{L}=\tfrac12\Bigl[\text{CE}(S,\ \mathbf{I})+\text{CE}(S^{\intercal},\ \mathbf{I})\Bigr], \tag{39.2}\]

where the targets are the diagonal, \(0,1,\dots,B-1\). The temperature \(\tau\) is itself learned, as \(\tau=e^{-s}\) with \(s\) a trainable scalar.

39.3.1 A synthetic image–caption problem

Real CLIP trains on hundreds of millions of web image–text pairs. We use a synthetic version that fits in seconds. The images are the \(8\times8\) digits. The caption is two words: an attribute (thin or thick, from the total ink of the image) and the digit name. So “thick seven” describes a seven with a lot of ink. The text encoder embeds the words and averages them (Chapter 3). The data is synthetic and the language trivial: the aim is to see the mechanism, not to reproduce CLIP’s quality.

import torch, torch.nn as nn, torch.nn.functional as F
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
D = load_digits(); X, y = D.data / 16.0, D.target
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)

names = ["zero", "one", "two", "three", "four", "five", "six", "seven", "eight", "nine"]
vocab = names + ["thin", "thick"]                              # token ids 0..9 digit names, 10 thin, 11 thick
thr = np.median(Xtr.sum(1))
def captions(Xs, ys):                                          # (N, 2) token ids: attribute, name
    attr = np.where(Xs.sum(1) > thr, 11, 10)
    return torch.tensor(np.stack([attr, ys], 1))
Ttr, Tte = captions(Xtr, ytr), captions(Xte, yte)
Xt, Xe = torch.tensor(Xtr, dtype=torch.float32), torch.tensor(Xte, dtype=torch.float32)
print("example captions:", [" ".join(vocab[t] for t in Ttr[i].tolist()) for i in range(4)])
print("distinct captions in the data:", len({tuple(r) for r in Ttr.tolist()}))
example captions: ['thin seven', 'thick three', 'thick six', 'thick six']
distinct captions in the data: 20

Only 20 distinct captions exist for 1,347 images. In a batch of 128, many images share the same caption. Plain InfoNCE treats those matching texts as negatives: a false-negative problem (Chapter 38). A standard remedy is a multi-positive target: all texts identical to text \(i\) count as correct, and the target is spread equally over them.

class ImageEncoder(nn.Module):
    def __init__(self, d=32):
        super().__init__(); self.net = nn.Sequential(nn.Linear(64, 128), nn.ReLU(), nn.Linear(128, d))
    def forward(self, x): return F.normalize(self.net(x), dim=-1)

class TextEncoder(nn.Module):
    def __init__(self, V=12, d=32):
        super().__init__()
        self.emb = nn.Embedding(V, 64)                         # token lookup (Chapter 3)
        self.mlp = nn.Sequential(nn.Linear(64, 64), nn.ReLU(), nn.Linear(64, d))
    def forward(self, tok):                                    # tok: (B, T) ids
        return F.normalize(self.mlp(self.emb(tok).mean(1)), dim=-1)     # bag of words, then MLP

def clip_loss(zi, zt, logit_scale, tok, multi_positive):
    S = logit_scale.exp().clamp(max=100) * zi @ zt.T           # (B, B)
    if multi_positive:
        same = (tok[:, None, :] == tok[None, :, :]).all(-1).float()    # texts identical to text i
        target = same / same.sum(1, keepdim=True)
        li = -(target * S.log_softmax(1)).sum(1).mean()
        lt = -(target * S.T.log_softmax(1)).sum(1).mean()
    else:
        t = torch.arange(len(S))
        li, lt = F.cross_entropy(S, t), F.cross_entropy(S.T, t)
    return (li + lt) / 2

def train_clip(multi_positive, steps=800, B=128, seed=0):
    torch.manual_seed(seed)
    ie, te = ImageEncoder(), TextEncoder()
    ls = nn.Parameter(torch.tensor(math.log(1 / 0.07)))
    opt = torch.optim.AdamW(list(ie.parameters()) + list(te.parameters()) + [ls], lr=3e-3)
    for _ in range(steps):
        i = torch.randint(0, len(Xt), (B,))
        loss = clip_loss(ie(Xt[i]), te(Ttr[i]), ls, Ttr[i], multi_positive)
        opt.zero_grad(); loss.backward(); opt.step()
    return ie, te, ls

def zero_shot_accuracy(ie, te):
    """Class text embedding = mean of the 'thin' and 'thick' captions of that digit."""
    with torch.no_grad():
        cls_tok = torch.tensor([[a, c] for c in range(10) for a in (10, 11)])        # (20, 2)
        zt = te(cls_tok).view(10, 2, -1).mean(1)
        zt = F.normalize(zt, dim=-1)
        pred = (ie(Xe) @ zt.T).argmax(1)
    return (pred.numpy() == yte).mean()

for mp in (False, True):
    ie, te, ls = train_clip(mp)
    print(f"multi-positive targets = {mp!s:5s}: zero-shot accuracy {zero_shot_accuracy(ie, te):.3f}   "
          f"learned temperature τ = {math.exp(-ls.item()):.3f}")
multi-positive targets = False: zero-shot accuracy 0.987   learned temperature τ = 0.059
multi-positive targets = True : zero-shot accuracy 0.987   learned temperature τ = 0.058

Both variants reach the same accuracy here. In this synthetic problem the “false negatives” share the same class, so they pull the embeddings in the same direction as the true positives, and little harm is done. The issue matters more when texts that are treated as negatives are in fact good descriptions of the image but differ from it in some important detail. We keep the multi-positive form as the more careful default.

Zero-shot classification used no class labels as such. It only used the caption text of each class, embedded by the text encoder, and the nearest one in the joint space. A new class could be added by writing a new caption.

39.3.3 The modality gap

Reported analyses of large trained CLIP models find that image embeddings and text embeddings occupy different regions of the sphere, even though matched pairs are close relative to mismatched ones. A measure is the distance between the centroids of the two groups, relative to the spread within each. In our small synthetic model the gap is small, as the numbers below show.

with torch.no_grad():
    Zt_all = te(torch.tensor(Tte.numpy())).numpy()               # one caption per test image
    Zi_all = ie(Xe).numpy()
cen_i, cen_t = Zi_all.mean(0), Zt_all.mean(0)
gap = np.linalg.norm(cen_i - cen_t)
spread_i = np.linalg.norm(Zi_all - cen_i, axis=1).mean()
spread_t = np.linalg.norm(Zt_all - cen_t, axis=1).mean()
print(f"centroid distance {gap:.2f};  average distance to own centroid: images {spread_i:.2f}, texts {spread_t:.2f}")
print(f"mean cosine of matched image–text pairs {np.mean(np.sum(Zi_all * Zt_all, 1)):.2f}")
centroid distance 0.19;  average distance to own centroid: images 0.98, texts 0.97
mean cosine of matched image–text pairs 0.79

39.4 From CLIP to multimodal language models

A CLIP model compares an image with text. A multimodal language model conditions text generation on an image: it answers questions and describes. The usual design reuses a pre-trained vision encoder and a pre-trained language model, and connects them with a small projector:

fig = box_flow(["image", "vision encoder\n(ViT)\nN × d_v", "projector\nN × d_LM", "[visual tokens ; text tokens]\n(N + T) × d_LM", "decoder-only\nLLM", "next-token\ndistribution"],
               colors=[PALETTE["data"], PALETTE["model"], PALETTE["prob"], PALETTE["data"], PALETTE["model"], PALETTE["loss"]],
               figsize=(11, 2.0), fontsize=7.8)
plt.show()

The projector is a linear map or a small MLP: \(\mathbf{H}_{\text{vis}}=\mathbf{V}\mathbf{W}_p\), with \(\mathbf{V}\in\mathbb{R}^{N\times d_v}\) and \(\mathbf{W}_{p}\in\mathbb{R}^{d_{v}\times d_{\text{LM}}}\). The result lives in the same space as word embeddings (Chapter 3), so the language model treats image patches as if they were unusual tokens.

d_v, d_lm, N_vis, T_txt = 1024, 4096, 576, 32
torch.manual_seed(0)
V = torch.randn(1, N_vis, d_v)                                  # vision-encoder output
Wp = nn.Linear(d_v, d_lm)                                       # projector
text_emb = torch.randn(1, T_txt, d_lm)                          # embedded text prompt
seq = torch.cat([Wp(V), text_emb], dim=1)
print("visual tokens:", tuple(Wp(V).shape), "  full sequence:", tuple(seq.shape))
print(f"projector parameters: {sum(p.numel() for p in Wp.parameters()):,}")
print(f"attention score matrix per head and layer: {seq.shape[1]}² = {seq.shape[1] ** 2:,} entries "
      f"(vs {T_txt ** 2:,} for text alone)")
visual tokens: (1, 576, 4096)   full sequence: (1, 608, 4096)
projector parameters: 4,198,400
attention score matrix per head and layer: 608² = 369,664 entries (vs 1,024 for text alone)

Each image adds hundreds of tokens, and attention cost grows with the square of the sequence (Chapters 30, 34).

39.4.1 Cross-attention and resamplers

An alternative to concatenation keeps the language model’s input as text only and lets its layers read the image through cross-attention (Chapter 30): queries come from the text states, keys and values from the image tokens.

A resampler reduces the number of image tokens first. A fixed set of \(M\) learned query vectors attends over the \(N\) image tokens (the same device as the detection queries of Chapter 37), and the \(M\) outputs are passed on:

\[ \mathbf{H}_{\text{vis}}=\text{softmax}\!\Bigl(\frac{\mathbf{Q}_{\text{learned}}\,\mathbf{K}_{\text{img}}^{\intercal}}{\sqrt{d}}\Bigr)\mathbf{V}_{\text{img}}\in\mathbb{R}^{M\times d},\qquad M\ll N. \tag{39.3}\]

class Resampler(nn.Module):
    def __init__(self, d_in, d, n_queries):
        super().__init__()
        self.q = nn.Parameter(torch.randn(n_queries, d) * 0.02)          # learned queries
        self.k, self.v = nn.Linear(d_in, d, bias=False), nn.Linear(d_in, d, bias=False)
    def forward(self, tokens):                                            # (B, N, d_in)
        K, Vv = self.k(tokens), self.v(tokens)
        A = (self.q @ K.transpose(1, 2) / math.sqrt(K.shape[-1])).softmax(-1)   # (B, M, N)
        return A @ Vv, A

res = Resampler(d_v, 512, n_queries=32)
out, A = res(V)
print(f"image tokens {V.shape[1]} -> {out.shape[1]} tokens of width {out.shape[2]}")
print("attention rows sum to 1:", torch.allclose(A.sum(-1), torch.ones(1, 32)))
print(f"cost of the language model's attention per layer: {(32 + T_txt) ** 2:,} entries "
      f"instead of {(N_vis + T_txt) ** 2:,}")
image tokens 576 -> 32 tokens of width 512
attention rows sum to 1: True
cost of the language model's attention per layer: 4,096 entries instead of 369,664

39.5 Training recipes

A common recipe has stages:

  1. Pre-train the vision encoder (CLIP-style, Chapter 38, or self-supervised).
  2. Start from a pre-trained language model.
  3. Train the projector only, on image–caption pairs, with the next-token loss (Chapter 33) on the caption.
  4. Then train projector and language model (often with LoRA, Chapter 7) on instruction data with images.

The loss throughout is the language-model cross-entropy on text tokens, computed with the image tokens as part of the conditioning prefix. Nothing new is added to the mathematics of Chapters 32–33.

39.7 Failure modes

False negatives. Images and texts that match are treated as mismatches (@code-clip). In large datasets, duplicates and near-duplicates are frequent.

Batch size. The loss compares each item with \(B-1\) others. The mutual-information bound is at most \(\ln B\). Real CLIP training uses very large batches (tens of thousands).

Bag-of-words behaviour. With a mean-pooled text encoder, word order is lost: “thick seven” and “seven thick” give the same embedding. Many CLIP-style models are weak at relations (“a dog chasing a cat” versus the reverse).

with torch.no_grad():
    a = te(torch.tensor([[11, 7]])); b = te(torch.tensor([[7, 11]]))
print("embedding of 'thick seven' equals that of 'seven thick':", torch.allclose(a, b, atol=1e-6))
embedding of 'thick seven' equals that of 'seven thick': True

Modality gap. In large models the two groups stay apart on the sphere (not seen in our toy model). This affects the use of image and text embeddings interchangeably, for example mixing image–text similarity with image–image similarity.

Hallucination. A language model with weak grounding generates fluent text that is not supported by the image. The image is one prefix among many and may be underweighted.

Cost of visual tokens. Hundreds of tokens per image dominate the context. Resamplers and token pruning reduce them at some loss of detail.

Prompt sensitivity of zero-shot. The class text matters. Averaging several prompts (as we did with thin and thick) improves robustness.

39.9 System connection

NoteWhat the system gained in this chapter

The three running systems are now one. Images and text share an embedding space (System B’s retrieval works across modalities), a language model can read image tokens (System C sees), and a classifier can be specified in words. All of it uses equations from earlier chapters: normalised dot products, softmax cross-entropy, linear projections, and attention.

We have understood models and their training for discriminative and language tasks. The remaining chapters treat generation of images: latent-variable models (Chapter 40), diffusion (Chapters 41–42), and flow matching (Chapter 43).

Chapter summary

  • CLIP: \(S_{ij}=\mathbf{z}_I^{(i)}\cdot\mathbf{z}_T^{(j)}/\tau\); loss \(\frac12[\text{CE}(S,\mathbf{I})+\text{CE}(S^{\intercal},\mathbf{I})]\).
  • Zero-shot classification: the nearest class-text embedding to the image embedding.
  • Duplicated captions create false negatives. Multi-positive targets fix it.
  • A multimodal LLM: vision encoder, projector into the token-embedding space, concatenation with text, decoder.
  • Resamplers compress many image tokens into few via learned-query cross-attention.
  • The modality gap (in large models) and bag-of-words behaviour are known limitations.
