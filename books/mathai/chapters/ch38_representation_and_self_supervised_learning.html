38  Representation and Self-Supervised Learning

NoteKey ideas
  • Self-supervised learning creates its own training signal from unlabelled data, so that the model learns useful vectors without labels.
  • A linear autoencoder learns exactly the PCA subspace. Nonlinear ones go beyond it.
  • Contrastive learning pulls two views of the same example together and pushes different examples apart. InfoNCE is a \(K\)-way classification loss, and a lower bound on mutual information.
  • Collapse is the trivial solution (all inputs mapped to one point). Negatives, or sharpening and centering, prevent it.
  • Representations are judged by a linear probe: a linear classifier on frozen embeddings.

38.1 The system problem

Labels are expensive. Unlabelled data is plentiful. A model can still learn what in the data is important if we give it a task that needs no labels: reconstruct the input, predict a hidden part, or recognise that two views come from the same source.

How can a model learn useful vectors from data without labels?

def probe(Ztr, Zte, n_labels=100, seed=0):

    return LogisticRegression(max_iter=3000).fit(Ztr[idx], ytr[idx]).score(Zte, yte)

38.3 Autoencoders

An autoencoder compresses the input to a short code \(\mathbf{z}=f(\mathbf{x})\in\mathbb{R}^k\) and reconstructs it, \(\hat{\mathbf{x}}=g(\mathbf{z})\). The loss is the reconstruction error \(\lVert\mathbf{x}-\hat{\mathbf{x}}\rVert^2\). The label is the input itself.

With linear \(f,g\), the optimum is exactly the PCA solution of Chapter 7: the best rank-\(k\) approximation of the data (Eckart–Young) is obtained by projecting onto the top \(k\) principal directions. The autoencoder may use any basis of that subspace, but it must span the same one.

from scipy.linalg import subspace_angles
k = 8
torch.manual_seed(0)
enc, dec = nn.Linear(64, k), nn.Linear(k, 64)
opt = torch.optim.Adam(list(enc.parameters()) + list(dec.parameters()), lr=1e-2)
for _ in range(3000):
    i = torch.randint(0, len(Xt), (256,))
    loss = F.mse_loss(dec(enc(Xt[i])), Xt[i]); opt.zero_grad(); loss.backward(); opt.step()
with torch.no_grad():
    mse_ae = F.mse_loss(dec(enc(Xt)), Xt).item()
pca = PCA(k).fit(Xtr)
mse_pca = np.mean((pca.inverse_transform(pca.transform(Xtr)) - Xtr) ** 2)
angles = np.degrees(subspace_angles(dec.weight.detach().numpy(), pca.components_.T))
print(f"reconstruction MSE (k = {k}): linear autoencoder {mse_ae:.5f},  PCA {mse_pca:.5f}")
print(f"largest angle between the decoder subspace and the PCA subspace: {angles.max():.1f}°")

# nonlinear autoencoder with the same code size
torch.manual_seed(0)
nenc = nn.Sequential(nn.Linear(64, 64), nn.ReLU(), nn.Linear(64, k))
ndec = nn.Sequential(nn.Linear(k, 64), nn.ReLU(), nn.Linear(64, 64))
opt = torch.optim.Adam(list(nenc.parameters()) + list(ndec.parameters()), lr=3e-3)
for _ in range(3000):
    i = torch.randint(0, len(Xt), (256,))
    loss = F.mse_loss(ndec(nenc(Xt[i])), Xt[i]); opt.zero_grad(); loss.backward(); opt.step()
with torch.no_grad():
    print(f"nonlinear autoencoder, same code size: MSE {F.mse_loss(ndec(nenc(Xt)), Xt).item():.5f}")
reconstruction MSE (k = 8): linear autoencoder 0.02388,  PCA 0.02375
largest angle between the decoder subspace and the PCA subspace: 9.0°
nonlinear autoencoder, same code size: MSE 0.01134

The linear autoencoder reaches the PCA error (to within 0.6%), and its decoder spans nearly the same subspace (largest principal angle 9°, the remainder being finite training). A nonlinear one does about twice as well at the same code size, because it can follow curved structure (the failure of PCA in Chapter 7).

Reconstruction has a weakness as a representation objective. To reconstruct pixels, the code must preserve everything, including noise and details irrelevant to meaning. Contrastive objectives avoid this.

38.4 Contrastive learning

Take an example \(\mathbf{x}\). Create two views by random augmentation (shift, crop, noise, intensity change): \(\mathbf{v}_1,\mathbf{v}_2\). They show the same underlying object. Their embeddings should be similar. Views of different examples should be different.

For a batch of \(K\) examples, embed both views and normalise to unit length (Chapter 4). Let \(s_{ij}=\mathbf{z}_i^{(1)}\cdot\mathbf{z}_j^{(2)}\) be the cosine similarity between view 1 of example \(i\) and view 2 of example \(j\). The InfoNCE loss for example \(i\) is

\[ \ell_i=-\ln\frac{\exp(s_{ii}/\tau)}{\sum_{j=1}^{K}\exp(s_{ij}/\tau)}. \tag{38.1}\]

Look at it carefully. It is the cross-entropy loss (Chapter 14) of a \(K\)-way classification: given view 1 of example \(i\), which of the \(K\) view-2 embeddings is its partner? The logits are the similarities divided by the temperature \(\tau\), and the softmax is that of Chapter 24. The true class is \(j=i\).

38.4.1 Why this learns something

TipInfoNCE bounds mutual information (sketch)

Let the “true” partner be drawn from the joint distribution and the \(K-1\) others from the marginal. Using the optimal critic, which is proportional to the density ratio \(p(\mathbf{z}^{+}\mid\mathbf{z})/p(\mathbf{z}^{+})\), one can show \[ I(\mathbf{z};\mathbf{z}^{+})\;\ge\;\ln K-\mathcal{L}_{\text{InfoNCE}}. \] Minimising the loss therefore maximises a lower bound on the mutual information (Chapter 15) between the two views. The bound cannot exceed \(\ln K\): a larger batch (more negatives) allows a tighter bound. \(\blacksquare\)

The temperature \(\tau\) controls how sharply the loss focuses on the hardest negatives: a small \(\tau\) amplifies differences in similarity (Chapter 24).

38.4.2 A small contrastive learner

The encoder is an MLP from 64 pixels to a 32-dimensional embedding. Augmentation: a random one-pixel shift, random intensity scaling, and Gaussian noise. The loss is symmetrised InfoNCE.

def augment(x):
    B = len(x); im = x.view(B, 1, 8, 8)
    dy, dx = torch.randint(-1, 2, (2,)).tolist()
    im = torch.roll(im, (dy, dx), (2, 3))
    im = im * (0.7 + 0.6 * torch.rand(B, 1, 1, 1)) + 0.1 * torch.randn_like(im)
    return im.view(B, 64)

def make_encoder(out=32):
    return nn.Sequential(nn.Linear(64, 128), nn.ReLU(), nn.Linear(128, out))

def train_contrastive(tau=0.2, use_negatives=True, steps=600, seed=0):
    torch.manual_seed(seed)
    f = make_encoder(); opt = torch.optim.AdamW(f.parameters(), lr=3e-3)
    for _ in range(steps):
        i = torch.randint(0, len(Xt), (128,))
        a = F.normalize(f(augment(Xt[i])), dim=1); b = F.normalize(f(augment(Xt[i])), dim=1)
        if use_negatives:
            logits = a @ b.T / tau; t = torch.arange(len(a))
            loss = (F.cross_entropy(logits, t) + F.cross_entropy(logits.T, t)) / 2
        else:
            loss = -(a * b).sum(1).mean()                     # pull positives together only
        opt.zero_grad(); loss.backward(); opt.step()
    with torch.no_grad():
        return f(Xt).numpy(), f(Xe).numpy(), loss.item()

def mean_pair_cosine(Z):
    Zn = Z / np.linalg.norm(Z, axis=1, keepdims=True)
    S = Zn @ Zn.T
    return (S.sum() - len(Z)) / (len(Z) * (len(Z) - 1))

torch.manual_seed(7)
rand_f = make_encoder()
with torch.no_grad():
    Z_rand = (rand_f(Xt).numpy(), rand_f(Xe).numpy())
Z_nce = train_contrastive(0.2, True)
Z_pos = train_contrastive(0.2, False)
rows = {"raw pixels": (Xtr, Xte), "random encoder": Z_rand, "contrastive (InfoNCE)": Z_nce[:2],
        "positives only (no negatives)": Z_pos[:2]}
print(f"{'representation':30s} {'10 labels':>10s} {'30':>7s} {'100':>7s}   mean cosine between random pairs")
for name, (a, b) in rows.items():
    accs = [probe(a, b, n) for n in (10, 30, 100)]
    print(f"{name:30s} {accs[0]:10.3f} {accs[1]:7.3f} {accs[2]:7.3f}   {mean_pair_cosine(a):+.3f}")
representation                  10 labels      30     100   mean cosine between random pairs
raw pixels                          0.398   0.678   0.896   +0.689
random encoder                      0.189   0.129   0.653   +0.789
contrastive (InfoNCE)               0.236   0.578   0.851   +0.009
positives only (no negatives)       0.098   0.104   0.124   +1.000

Read the table with care.

  • Collapse. Training with only positive pairs finds a trivial solution: every input mapped to the same direction. The loss is \(-1\) (perfect agreement), the average cosine between random pairs is \(+1\), and the probe is at chance. Without negatives nothing stops the representation from ignoring its input.
  • Contrastive learning works, far above a random encoder.
  • Raw pixels are a very strong baseline here. The digits are tiny, clean, and almost linearly separable in pixel space. Self-supervised learning pays when labels are scarce and the raw input is a poor representation: photographs, audio, text. Here the 32-dimensional learned embedding does not beat the 64 raw pixels at any of the three label budgets (for example 0.85 against 0.90 with 100 labels). It is far above a random encoder, which shows that something useful was learned, and below the baseline, which shows that on this data there was little left to learn.

38.5 Teacher–student methods and DINO

Contrastive learning needs many negatives. A different family needs none: a student network is trained to match the output of a teacher network on a different view. The teacher is not trained by gradient descent. It is an exponential moving average (EMA) of the student:

\[ \theta_{\text{teacher}}\leftarrow m\,\theta_{\text{teacher}}+(1-m)\,\theta_{\text{student}},\qquad m\approx0.99\text{–}0.999. \tag{38.2}\]

In DINO, both networks output a vector of \(K\) scores. The loss is the cross-entropy between the teacher’s softmax (a target) and the student’s softmax:

\[ \mathcal{L}=-\sum_kp^{\text{teacher}}_k\,\ln p^{\text{student}}_k, \qquad p^{\text{teacher}}=\text{softmax}\!\Bigl(\frac{\mathbf{o}_t-\mathbf{c}}{\tau_t}\Bigr),\quad p^{\text{student}}=\text{softmax}\!\Bigl(\frac{\mathbf{o}_s}{\tau_s}\Bigr). \tag{38.3}\]

Two operations prevent the two ways a method without negatives can collapse:

Collapse Cause Prevented by
One output dimension always wins all inputs get the same one-hot target centering: subtract a running mean \(\mathbf{c}\) of teacher outputs
Uniform output for every input softmax of a constant sharpening: low teacher temperature \(\tau_t\)

The two are balanced. Centering pushes towards uniform. Sharpening pushes away from it.

def train_dino(center=True, sharpen=True, steps=600, seed=0, K=32):
    torch.manual_seed(seed)
    student = make_encoder(K); teacher = copy.deepcopy(student)
    for p in teacher.parameters():
        p.requires_grad_(False)
    opt = torch.optim.AdamW(student.parameters(), lr=3e-3)
    c = torch.zeros(K)
    for _ in range(steps):
        i = torch.randint(0, len(Xt), (128,))
        va, vb = augment(Xt[i]), augment(Xt[i])
        with torch.no_grad():
            o_t = teacher(va)
            target = F.softmax((o_t - (c if center else 0)) / (0.04 if sharpen else 0.5), dim=-1)
        loss = -(target * F.log_softmax(student(vb) / 0.1, dim=-1)).sum(-1).mean()
        opt.zero_grad(); loss.backward(); opt.step()
        with torch.no_grad():
            for pt, ps in zip(teacher.parameters(), student.parameters()):
                pt.mul_(0.99).add_(ps, alpha=0.01)                 # EMA update
            c = 0.9 * c + 0.1 * o_t.mean(0)                       # centering statistic
    with torch.no_grad():
        return teacher(Xt).numpy(), teacher(Xe).numpy(), loss.item()

print(f"uniform-collapse loss would be ln K = {math.log(32):.3f}")
print(f"{'variant':26s} {'final loss':>10s} {'probe (100 labels)':>19s}")
for name, kw in [("centering + sharpening", dict()), ("no centering", dict(center=False)),
                 ("no sharpening", dict(sharpen=False))]:
    a, b, l = train_dino(**kw)
    print(f"{name:26s} {l:10.3f} {probe(a, b, 100):19.3f}")
uniform-collapse loss would be ln K = 3.466
variant                    final loss  probe (100 labels)
centering + sharpening          1.974               0.571
no centering                    0.000               0.311
no sharpening                   3.466               0.104

Without sharpening, the loss sits at exactly \(\ln K\): the teacher’s output is uniform for every input, a total collapse, and the probe is at chance. With both operations, training avoids the two collapses, but in 600 steps on this tiny dataset the representation is not good: its probe accuracy (about 0.57) is below that of a random encoder (0.65). We do not claim that DINO-style learning works well at this scale. The experiment shows the two collapse modes, which are real, and which the two operations control.

38.6 Masked modelling

A third route hides part of the input and predicts it from the rest. BERT masks tokens of a sentence. Masked autoencoders (MAE) mask a large fraction (about 75%) of image patches (Chapter 36) and reconstruct them. Language models are the same idea in one direction: the hidden part is the next token (Chapter 33). The signal is again the data itself, and the loss is cross-entropy or squared error.

38.7 Evaluating representations

The standard test is the linear probe: freeze the encoder, train only a linear classifier on top, and report accuracy for several numbers of labels (as above). A representation is good if a simple classifier suffices with few labels. Other tests: \(k\)-NN accuracy (Chapter 13), transfer to other tasks, and fine-tuning.

38.8 Production

PyTorch has everything used here. The one detail to check is that our InfoNCE equals a library cross-entropy over a similarity matrix.

torch.manual_seed(0)
a = F.normalize(torch.randn(6, 8), dim=1); b = F.normalize(torch.randn(6, 8), dim=1)
tau = 0.2
S = a @ b.T / tau
manual = torch.stack([-(S[i, i] - torch.logsumexp(S[i], 0)) for i in range(6)]).mean()
print("InfoNCE equals cross_entropy over the similarity matrix:",
      torch.allclose(manual, F.cross_entropy(S, torch.arange(6))))
print(f"ln K = {math.log(6):.3f}; the loss of random embeddings is about this: {F.cross_entropy(S * tau, torch.arange(6)).item():.3f}")
InfoNCE equals cross_entropy over the similarity matrix: True
ln K = 1.792; the loss of random embeddings is about this: 1.746

38.9 Failure modes

Collapse. All inputs map to one point (@code-simclr) or to a uniform output (@code-dino). The loss looks excellent while the representation is useless. Always monitor the variance of embeddings and a probe, not just the loss.

Dimensional collapse. Embeddings occupy a few dimensions of the available space. They are not constant, but they are low-rank. Check the singular values of the embedding matrix (Chapter 7).

False negatives. Two different images of the same class are treated as negatives and pushed apart. Larger batches make this more frequent for categories with few classes.

Augmentation is the supervision. The representation becomes invariant to exactly the transformations used, and sensitive to what they preserve. A bad augmentation (colour jitter that destroys the signal, or none that hides a shortcut such as image borders) gives a bad representation.

Batch size. InfoNCE’s bound is at most \(\ln K\). Small batches limit it.

Temperature. Needs tuning (Figure 38.3).

Probe protocol. A probe trained on many labels hides weaknesses. Report several label budgets.

38.11 System connection

NoteWhat the system gained in this chapter

The system can now learn representations from unlabelled data. It has three objectives: reconstruction (autoencoders, equal to PCA when linear), contrast (InfoNCE, a classification of partners, a bound on mutual information), and teacher–student matching (DINO, with centering and sharpening against collapse). It also has a way to judge them: the linear probe.

These were all trained on one modality. The next step is to put two modalities in one space: images and text. That is the subject of Chapter 39.

Chapter summary

  • A linear autoencoder spans the PCA subspace. Nonlinear ones go further.
  • InfoNCE is \(K\)-way cross-entropy on similarities. \(I\ge\ln K-\mathcal{L}\).
  • Without negatives, representation learning collapses. DINO uses an EMA teacher, centering, and sharpening.
  • Evaluate with a linear probe at several label budgets.
  • Raw pixels are a strong baseline on easy data: here neither contrastive nor DINO-style embeddings beat them. Self-supervision pays where raw inputs are poor and labels scarce.

Exercises

  1. Compute. For a batch of \(K=256\), what is the maximum mutual information the InfoNCE bound can certify, in nats and bits?
  2. Derive. Show that for \(\tau\to\infty\) the InfoNCE loss tends to \(\ln K\), and describe the gradient.
  3. Derive. Show that the output of the EMA update is a weighted average of all past student weights, with weights \((1-m)m^{t-s}\).
  4. Derive. Show that for a linear autoencoder with tied weights and orthonormal rows, the reconstruction error is \(\sum_{i>k}\lambda_i\) (the discarded variance) when the rows are the top eigenvectors.
  5. Code. Compute the singular values of the contrastive embedding matrix. Is there dimensional collapse?
  6. Code. Increase the contrastive batch size from 32 to 512 and measure the probe accuracy.
  7. Code. Remove the shift augmentation, then the noise, then the intensity scaling, each in turn. Which matters most?
  8. Code. Train a denoising autoencoder (add noise to the input, reconstruct the clean input). Compare its probe accuracy with the plain autoencoder.
  9. Diagnose. A contrastive model has training loss 0.01 and a linear probe at 10% on a 10-class problem. List two possible causes.
