33  Autoregressive Generation and Sampling

NoteKey ideas
  • A language model is a machine for one quantity: \(P(x_{t}\mid x_{<t})\). The chain rule turns it into a distribution over whole sequences.
  • Training (teacher forcing) maximises the likelihood of real text: the loss is the average negative log-probability of each next token, and its exponential is the perplexity.
  • Generation samples one token at a time and feeds it back. The decoding rule (greedy, temperature, top-\(k\), top-\(p\)) is a choice made after training.
  • Lower temperature gives less entropy and more repetition. Higher temperature gives more diversity and more errors.
  • Scoring a sequence is one parallel pass. Generating it is sequential.

33.1 The system problem

Chapter 32 gave an architecture that outputs a probability distribution over the next token. A sentence is a long chain of such tokens. Two questions remain: how is this machine trained, and how does it produce text?

33.2 The factorisation

The probability of a text \(x_1,\dots,x_n\) is, by the chain rule (Chapter 22):

\[ P_\theta(x_1,\dots,x_n)=\prod_{t=1}^{n}P_\theta(x_{t}\mid x_{<t}). \tag{33.1}\]

This is exact: no independence assumption is made. The model \(f_\theta\) computes each factor from the prefix: its softmax output (Chapter 24) is the categorical distribution \(P_\theta(\cdot\mid x_{<t})\).

33.2.1 Training: maximum likelihood

Maximum likelihood (Chapter 25) maximises \(\ln P_\theta\) of the training text. Taking the negative log of Equation 33.1 and averaging over positions gives the cross-entropy loss:

\[ \mathcal{L}(\theta)=-\frac1n\sum_{t=1}^{n}\ln P_\theta(x_{t}\mid x_{<t}). \tag{33.2}\]

This is the same cross-entropy as in Chapter 14. The only difference is that the “label” at each position is the next token of the text itself. All \(n\) factors are computed in one forward pass, thanks to the causal mask (Chapter 30). This is called teacher forcing: the model is always fed the true prefix.

The exponential of the loss is the perplexity (Chapter 15). It is the effective number of tokens the model hesitates between.

33.3 A small language model

We train a character-level Transformer (Chapter 31) on a text of 300,000 characters: the documentation shipped with Python, lower-cased, using 29 symbols (letters, space, ., ,, newline). The model is small (3 blocks, width 96) so that it trains in under a minute on a CPU.

import torch, torch.nn as nn, torch.nn.functional as F
from pydoc_data import topics

raw = " ".join(topics.topics[k] for k in sorted(topics.topics)).lower()

chars = sorted(set(text)); V = len(chars)

n_train = int(0.9 * len(data))
train_data, val_data = data[:n_train], data[n_train:]
print(f"{len(text):,} characters; vocabulary {V}: {''.join(chars)!r}")
print("sample:", repr(text[:100]))

T_ctx, d_model, n_heads, n_layers = 64, 96, 4, 3

class Block(nn.Module):
    def __init__(self):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d_model), nn.LayerNorm(d_model)
        self.qkv, self.o = nn.Linear(d_model, 3 * d_model), nn.Linear(d_model, d_model)
        self.mlp = nn.Sequential(nn.Linear(d_model, 4 * d_model), nn.GELU(),
                                 nn.Linear(4 * d_model, d_model))
    def forward(self, x):
        B, T, _ = x.shape
        q, k, v = self.qkv(self.ln1(x)).chunk(3, dim=-1)
        sp = lambda t: t.view(B, T, n_heads, d_model // n_heads).transpose(1, 2)
        a = F.scaled_dot_product_attention(sp(q), sp(k), sp(v), is_causal=True)
        x = x + self.o(a.transpose(1, 2).reshape(B, T, d_model))
        return x + self.mlp(self.ln2(x))

class CharLM(nn.Module):
    def __init__(self):
        super().__init__()
        self.E, self.P = nn.Embedding(V, d_model), nn.Embedding(T_ctx, d_model)
        nn.init.normal_(self.E.weight, std=0.02); nn.init.normal_(self.P.weight, std=0.02)
        self.blocks = nn.ModuleList([Block() for _ in range(n_layers)])
        self.ln = nn.LayerNorm(d_model)
    def forward(self, idx):
        x = self.E(idx) + self.P(torch.arange(idx.shape[1]))
        for b in self.blocks:
            x = b(x)
        return self.ln(x) @ self.E.weight.T            # tied output head: logits = h Eᵀ

def get_batch(src, B=64):
    starts = torch.randint(0, len(src) - T_ctx - 1, (B,))
    return torch.stack([src[s:s + T_ctx + 1] for s in starts])

torch.manual_seed(0)

opt = torch.optim.AdamW(lm.parameters(), lr=3e-3, weight_decay=0.01)

33.4 Scoring versus generating

Scoring a given text needs one forward pass: the causal mask lets every position compute its next-token distribution at once. Generating needs one pass per token, because each token depends on the previous one. We check that the two give the same log-probability.

@torch.no_grad()
def seq_logprob_parallel(ids):
    logits = lm(ids[None, :-1])[0]                                # one pass
    lp = F.log_softmax(logits, dim=-1)
    return lp[torch.arange(len(ids) - 1), ids[1:]].sum().item()

@torch.no_grad()
def seq_logprob_sequential(ids):
    total = 0.0
    for t in range(1, len(ids)):                                   # one pass per token
        lp = F.log_softmax(lm(ids[None, :t])[0, -1], dim=-1)
        total += lp[ids[t]].item()
    return total

ids = val_data[:40]
print(f"parallel (teacher-forcing) log P: {seq_logprob_parallel(ids):.4f}")
print(f"sequential, token by token     : {seq_logprob_sequential(ids):.4f}")
parallel (teacher-forcing) log P: -51.3990
sequential, token by token     : -51.3990

33.5 Decoding

The model fixes \(P_\theta(\cdot\mid x_{<t})\). A decoding rule chooses the next token from it. The rule is not part of the model, and has a large effect on the text.

Rule Next token
Greedy \(\arg\max_xp(x)\)
Temperature \(T\) sample from \(p_T(x)\propto p(x)^{1/T}\) (softmax of \(\mathbf{z}/T\), Chapter 24)
Top-\(k\) keep the \(k\) most likely tokens, renormalise, sample
Top-\(p\) (nucleus) keep the smallest set whose probability sums to at least \(p\), renormalise, sample

Temperature changes the shape: low \(T\) sharpens, high \(T\) flattens. Top-\(k\) and top-\(p\) cut off the unreliable tail, since sampling from the tail produces nonsense tokens with small but non-zero probability at every step.

def next_token_probs(logits, temperature=1.0, top_k=None, top_p=None):
    z = logits / max(temperature, 1e-8)
    p = F.softmax(z, dim=-1)
    if top_k is not None:
        kth = torch.topk(p, top_k).values[-1]
        p = torch.where(p >= kth, p, torch.zeros_like(p))
    if top_p is not None:
        sp, si = torch.sort(p, descending=True)
        cum = torch.cumsum(sp, dim=-1)
        keep = cum - sp < top_p                         # keep tokens until mass >= top_p
        mask = torch.zeros_like(p, dtype=torch.bool); mask[si[keep]] = True
        p = torch.where(mask, p, torch.zeros_like(p))
    return p / p.sum()

@torch.no_grad()
def generate(prompt, n=300, greedy=False, **kw):
    ids = torch.tensor([ix[c] for c in prompt])
    for _ in range(n):
        logits = lm(ids[None, -T_ctx:])[0, -1]
        if greedy:
            nxt = logits.argmax()
        else:
            nxt = torch.multinomial(next_token_probs(logits, **kw), 1)[0]
        ids = torch.cat([ids, nxt.view(1)])
    return "".join(chars[i] for i in ids.tolist())

Greedy decoding falls into a loop (here, “the same as the same as the same as…”). Pure sampling at \(T=1\) is varied and often garbled. Truncation methods give a middle ground. This is typical, and it is why chat models use temperature around 0.7 with nucleus sampling.

33.5.1 Measuring it

We quantify two things over 20 samples of 300 characters for each rule: the fraction of repeated 8-grams (repetition) and the average log-probability the model assigns to its own text (how “likely” the output is).

def stats(kw, n_samples=20, n=300):
    reps, lps = [], []
    for _ in range(n_samples):
        s = generate("the function ", n, **kw)
        grams = [s[i:i + 8] for i in range(len(s) - 8)]
        seen, rep = set(), 0
        for g in grams:
            rep += g in seen; seen.add(g)
        reps.append(rep / len(grams))
        ids = torch.tensor([ix[c] for c in s])
        lps.append(seq_logprob_parallel(ids[-(T_ctx + 1):]) / T_ctx)
    return np.mean(reps), np.mean(lps)

33.5.2 Entropy and temperature on real model output

Chapter 24 showed that entropy rises with \(T\) for a fixed set of logits. We confirm it for the model’s actual next-token distribution, and look at how many tokens a nucleus of \(p=0.9\) actually contains.

@torch.no_grad()
def ent_bits(p):
    p = p[p > 0]; return -(p * p.log2()).sum().item()

ctx = val_data[:T_ctx]
logits = lm(ctx[None])[0, -1]
Ts = np.linspace(0.1, 3.0, 30)
ents = [ent_bits(F.softmax(logits / t, -1)) for t in Ts]

with torch.no_grad():
    b = get_batch(val_data, 32)
    P = F.softmax(lm(b[:, :-1]), dim=-1).reshape(-1, V)[:2000]
sp, _ = torch.sort(P, dim=-1, descending=True)
sizes = (torch.cumsum(sp, -1) < 0.9).sum(-1).numpy() + 1

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10, 3.4))
ax1.plot(Ts, ents, color=PALETTE["model"], lw=2); ax1.set_xlabel("temperature T"); ax1.set_ylabel("entropy (bits)")
ax2.hist(sizes, bins=np.arange(0.5, sizes.max() + 1.5), color=PALETTE["data"])
ax2.set_xlabel("tokens in the top-p = 0.9 nucleus"); ax2.set_ylabel("number of positions")
plt.tight_layout(); plt.show()

33.6 Production

PyTorch provides torch.topk, torch.multinomial, and torch.cumsum. We check our nucleus implementation against a direct, slower one.

def nucleus_reference(p, top_p):
    order = np.argsort(-p); cum = 0.0; keep = []
    for j in order:
        keep.append(j); cum += p[j]
        if cum >= top_p:
            break
    out = np.zeros_like(p); out[keep] = p[keep]
    return out / out.sum()

ok = True
for _ in range(100):
    z = torch.randn(V) * 3
    mine = next_token_probs(z, top_p=0.8).numpy()
    ref = nucleus_reference(F.softmax(z, -1).numpy(), 0.8)
    ok &= np.allclose(mine, ref, atol=1e-6)
print("top-p implementation matches the reference on 100 random distributions:", ok)
print("temperature 1 and no truncation leaves the distribution unchanged:",
      torch.allclose(next_token_probs(logits), F.softmax(logits, -1)))

temperature 1 and no truncation leaves the distribution unchanged: True

In production, generation uses the KV cache (Chapter 32), so each new token costs one attention step over the cache and not a full recomputation.

33.7 Failure modes

Repetition loops. Greedy and low-temperature decoding return to the same high-probability continuation (see above). Remedies are sampling, repetition penalties, and nucleus truncation.

Exposure bias. In training the model always sees the true prefix. At generation it sees its own samples. An early mistake puts it in a context it never saw. The mismatch can compound over long outputs.

Tail sampling. At \(T=1\) without truncation, each step has a small chance of sampling a bad token. Over hundreds of tokens, this accumulates.

Degenerate settings. \(T\to0\) is greedy. Top-\(p\) near 0 keeps one token. \(T=0\) exactly divides by zero: implementations clamp it.

Miscalibration. A language model’s probabilities need not be calibrated (Chapter 24). A sequence with a high probability is not necessarily a good one: the most probable text is often generic or repetitive.

Likelihood is not quality. Perplexity measures prediction of held-out text. It does not measure truthfulness, helpfulness, or safety.

Cost. Each token needs a forward pass. Generating \(n\) tokens takes \(n\) sequential steps, which cannot be parallelised across time for one sequence.

33.9 System connection

NoteWhat the system gained in this chapter

System C is complete as a language model: it is trained by maximum likelihood with the chain rule, evaluated by perplexity, and used to generate text by sampling from its next-token distribution under a chosen decoding rule. The central equation \(P(x_{1:n})=\prod_tP(x_{t}\mid x_{<t})\) connects probability (Part VI), the architecture (Chapters 30–32), and learning (Part V).

Next we ask what limits such models: how parameters, data, and compute scale, how to add parameters without adding compute (mixtures of experts), and how numerical precision constrains training. That is Chapter 34.

Chapter summary

  • \(P(x_{1:n})=\prod_tP(x_{t}\mid x_{<t})\) is exact. The model supplies each factor.
  • Training minimises \(-\frac1n\sum_{t}\ln P_\theta(x_{t}\mid x_{<t})\) with teacher forcing. Perplexity is its exponential.
  • Scoring is one parallel pass. Generation is sequential, one token per pass.
  • Decoding: greedy, temperature, top-\(k\), top-\(p\). Entropy rises with temperature.
  • Greedy repeats. Pure sampling is noisy. Truncated sampling balances them.
  • Exposure bias, tail sampling, and the difference between likelihood and quality are the main caveats.
