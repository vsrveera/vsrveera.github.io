47  Performance Characterisation: The Paradigm

NoteKey ideas
  • A single accuracy number on a single data set says little. A characterisation states how the output behaves as a function of the input conditions and the tuning parameters.
  • The paradigm has four steps: model the ideal input and its perturbation, define the algorithm as a mapping with parameters, derive or measure the output distribution, and validate the model on real data.
  • Performance has more than one face: detection (does it find it?), false alarm (does it invent it?), localisation (how far off?).
  • An analytic model that predicts the measured behaviour is worth more than a table of measurements, because it says what to expect in conditions we did not test.

47.1 The system problem

In the 1980s and 1990s, computer vision had many algorithms for edges, corners, lines, regions and motion. Each paper showed a few images where the new method looked better. R. M. Haralick pointed out that this is not engineering. A bridge builder gives a load limit and a safety factor. An algorithm designer gave a picture.

How well does this algorithm work, under which conditions, with which settings, and how do we know?

The work of Haralick and of V. Ramesh and co-authors answers with a method: performance characterisation. This chapter presents the method in its simplest setting, one component and one number of noise. Chapters 48 to 50 extend it to pipelines, to confidence statements and to experimental protocols.

NoteSources

The ideas in Part IX follow the programme described in R. M. Haralick, “Performance characterization in computer vision”, CVGIP: Image Understanding 60(2), 1994, and in the papers of V. Ramesh and R. M. Haralick on random perturbation models, covariance propagation and parameter tuning for vision algorithm sequences (early 1990s to the late 1990s). The examples in this book are my own small constructions in that spirit, not reproductions of their experiments. Check details against the original papers before citing them.

47.2 The paradigm in four steps

box_flow(["Input +\nperturbation\nmodel", "Algorithm\n+ parameters", "Output\ndistribution", "Validate on\nreal data"],
         colors=[PALETTE["data"], PALETTE["model"], PALETTE["prob"], PALETTE["grad"]], figsize=(9, 1.9))
plt.show()
  1. Model the input. State an ideal input \(\mathbf x_0\) (the clean world: a step edge of height \(h\) at position \(s\)). State how the real input differs: \(\mathbf x=\mathbf x_0+\boldsymbol\epsilon\), with \(\boldsymbol\epsilon\) drawn from a perturbation model, for example independent Gaussian noise with standard deviation \(\sigma\). This is a random perturbation model.
  2. Define the algorithm as a mapping \(\mathbf y=A(\mathbf x;\boldsymbol\theta)\) with tuning parameters \(\boldsymbol\theta\) (a window size, a threshold).
  3. Describe the output. The output \(\mathbf y\) is a random variable because \(\mathbf x\) is. Find its distribution, or its relevant moments, as a function of \((h,\sigma,\boldsymbol\theta)\). Do it by derivation where possible and by simulation otherwise.
  4. Validate. Compare the predicted behaviour with the behaviour on real, labelled data. If they differ, the perturbation model is wrong, not the data.

The result is an operating characteristic: a table, curve or formula that says what the algorithm does for each condition.

47.3 A worked component: a step-edge detector

We take a one-dimensional signal with a step of height \(h\) at position \(s\), plus independent noise of standard deviation \(\sigma\). The algorithm has one structural parameter, the window width \(w\), and one threshold \(\tau\). For each position \(i\) it computes the mean of the \(w\) samples after \(i\) minus the mean of the \(w\) samples before \(i\):

\[ D_i=\frac1w\sum_{j=0}^{w-1}x_{i+j}-\frac1w\sum_{j=1}^{w}x_{i-j}. \tag{47.1}\]

It reports an edge where \(|D_i|\) is the largest value and exceeds \(\tau\).

47.3.1 What theory predicts

For a clean step, the filter peaks at the step with value exactly \(h\). For noise only, \(D_i\) is a difference of two window means, so it is Gaussian with variance

\[ \sigma_D^2=\sigma^2\Bigl(\frac1w+\frac1w\Bigr)=\frac{2\sigma^2}{w}. \tag{47.2}\]

Larger windows reduce noise by \(\sqrt{2/w}\). At one sample, a threshold \(\tau\) gives a false alarm probability

\[ P_{\text{FA}}^{(1)}(\tau)=2\,Q\!\left(\frac{\tau}{\sigma_D}\right), \tag{47.3}\]

where \(Q\) is the upper tail of the standard normal. So we can set the threshold from a required false alarm rate: \(\tau=\sigma_D\,Q^{-1}\!\bigl(P_{\text{FA}}^{(1)}/2\bigr)\). This is the central benefit of an analytic model.

At the true edge, \(D=h+\text{noise}\) with standard deviation \(\sigma_D\). The probability that it exceeds \(\tau\) is \(Q\bigl((\tau-h)/\sigma_D\bigr)\) (plus a negligible term for the other side). It depends on the signal-to-noise ratio \(h/\sigma_D\) and the threshold only.

47.3.2 Measuring

We now measure the detector, to test the prediction. A detection is a trial where the largest response exceeds \(\tau\) and lies within \(\pm2\) samples of the true edge. A false alarm is a response above \(\tau\) at a place far from the edge. We use \(\sigma=1\) and set \(\tau\) for a per-sample false alarm probability of \(0.001\).

rng = np.random.default_rng(47)
Ls, s0 = 200, 100

def diff_filter(x, w):
    c = np.concatenate([[0.0], np.cumsum(x)])
    i = np.arange(w, len(x) - w + 1)
    return i, (c[i + w] - c[i]) / w - (c[i] - c[i - w]) / w

def run_trials(h, sigma, w, tau, n=3000):
    det = loc = 0
    errs = []
    for _ in range(n):
        x = rng.normal(0, sigma, Ls); x[s0:] += h
        i, d = diff_filter(x, w)
        a = np.abs(d); k = a.argmax()
        if a[k] > tau and abs(i[k] - s0) <= 2:
            det += 1; errs.append(i[k] - s0)
    return det / n, (np.std(errs) if errs else np.nan)

sigma, pfa1 = 1.0, 1e-3
print(" w  sigma_D   tau   per-sample FA (measured)")
for w in (3, 5, 9):
    sD = sigma * np.sqrt(2 / w)
    tau = sD * norm.isf(pfa1 / 2)
    fa = np.mean([(np.abs(diff_filter(rng.normal(0, sigma, Ls), w)[1]) > tau).mean() for _ in range(3000)])
    print(f"{w:2d}   {sD:.3f}  {tau:.3f}   {fa:.5f}")
 w  sigma_D   tau   per-sample FA (measured)
 3   0.816  2.687   0.00102
 5   0.632  2.081   0.00090
 9   0.471  1.551   0.00097

The measured false alarm rate matches the design value \(0.001\) within noise. The model predicted a number and the experiment confirmed it. Now the detection probability as a function of the edge height, with the theory curve \(Q\bigl((\tau-h)/\sigma_D\bigr)\) for comparison.

hs = np.linspace(0.5, 5, 10)
fig, ax = plt.subplots(figsize=(6.6, 3.7))
cols = {3: PALETTE["loss"], 5: PALETTE["model"], 9: PALETTE["grad"]}
table = {}
for w in (3, 5, 9):
    sD = sigma * np.sqrt(2 / w); tau = sD * norm.isf(pfa1 / 2)
    meas = np.array([run_trials(h, sigma, w, tau, n=1500)[0] for h in hs])
    theo = norm.sf((tau - hs) / sD)
    table[w] = (meas, theo)
    ax.plot(hs, theo, color=cols[w], lw=1.8, label=f"w = {w}")
    ax.plot(hs, meas, "o", color=cols[w], ms=4)
ax.set_xlabel("edge height h (noise σ = 1)"); ax.set_ylabel("P(detect)")
ax.legend(); plt.show()
w = 5
print("w=5: largest |measured - theory| =", np.abs(table[w][0] - table[w][1]).max().round(3))
w=5: largest |measured - theory| = 0.07

The theory is the one-sample formula. It ignores competing noise peaks elsewhere in the signal and it is therefore slightly optimistic at low heights. The largest gap between measurement and theory for \(w=5\) is \(0.07\), near the knee of the curve. A characterisation reports both: the clean formula for design, and the measured curve for the truth.

47.3.3 Localisation

A detector must also say where the edge is. We measure the standard deviation of the position error over correct detections.

print("edge height 4, sigma 1:  window  P(detect)  location std (samples)")
for w in (3, 5, 9, 15):
    sD = sigma * np.sqrt(2 / w); tau = sD * norm.isf(pfa1 / 2)
    p, s = run_trials(4.0, sigma, w, tau, n=3000)
    print(f"                         {w:6d}  {p:9.3f}  {s:9.2f}")
edge height 4, sigma 1:  window  P(detect)  location std (samples)
                              3      0.960       0.35
                              5      0.996       0.39
                              9      0.999       0.37
                             15      0.995       0.37

At height 4 the detection probability rises from \(0.960\) (\(w=3\)) to about \(0.995\) or more, and the location error stays near \(0.4\) samples for every window. We counted only detections within \(\pm2\) samples, so this number is truncated. The window width does not matter much for one clean edge. It matters when a second edge is near.

def two_edge_resolution(gap, w, n=1500, h=4.0):
    """P(both edges of a bar of width `gap` are detected, each within +-2 samples)."""
    sD = sigma * np.sqrt(2 / w); tau = sD * norm.isf(pfa1 / 2)
    ok = 0
    for _ in range(n):
        x = rng.normal(0, sigma, Ls); x[s0:s0 + gap] += h
        i, d = diff_filter(x, w); a = np.abs(d)
        found = lambda c: a[np.abs(i - c) <= 2].max() > tau
        ok += found(s0) and found(s0 + gap)
    return ok / n
print("both edges of a bar found, P(resolve) by window w and bar width (samples):")
print("bar width:   " + "  ".join(f"{g:5d}" for g in (3, 6, 12, 24)))
for w in (3, 9, 15):
    print(f"w = {w:2d}:      " + "  ".join(f"{two_edge_resolution(g, w):5.2f}" for g in (3, 6, 12, 24)))
both edges of a bar found, P(resolve) by window w and bar width (samples):
bar width:       3      6     12     24
w =  3:       0.92   0.92   0.93   0.91
w =  9:       0.21   1.00   1.00   1.00
w = 15:       0.02   0.85   1.00   1.00

A bar of width 3 is found by \(w=3\) in 92% of trials, by \(w=9\) in 21%, and by \(w=15\) in 2%. A wide window averages across a narrow bar, so the response at each edge is weak. In the other direction, \(w=3\) has a lower detection probability at the single edge (Figure 47.2), and it never reaches 1.00 on the wider bars, because its threshold is higher. The window width is a tuning parameter with a trade-off: noise rejection against resolution. A characterisation shows the trade-off. It does not hide it behind one “accuracy” number.

47.4 What to report

A characterisation report for a component states:

Item Content
Input domain the ideal inputs and the perturbation model, with ranges
Parameters each tuning parameter and its tested range
Measures detection, false alarm, localisation, with the definition of each
Results the measure as a function of condition and parameter, with confidence (Chapter 49)
Validation agreement between the model and real data, and where it fails
Operating rule for a stated requirement, which parameters to use (Chapter 50)

47.5 Failure modes

Wrong perturbation model. Real noise is correlated, heavy-tailed or signal-dependent. The formula is exact for the model and wrong for the world. Chapter 50 tests this by deliberately mismatching the model.

One number for a function. The detector has a curve, not a score.

Definition drift. “Detection” must be defined (how near is near enough?). A different definition changes the curve.

Condition coverage. The test set contains only easy inputs. The operating characteristic is silent about the hard ones.

Tuning on the test set. The parameters were selected on the data used to report performance (Chapter 27).

47.6 Where this appears in modern AI

Place Characterisation question
Object detection recall at fixed false positives per image, as a function of object size and occlusion
Speech recognition word error rate against signal-to-noise ratio and accent
Language models accuracy against prompt perturbation, length, language
Medical AI sensitivity at fixed specificity, per scanner and per population
Anomaly detection detection delay at fixed false alarm rate
Robustness benchmarks accuracy against corruption severity level

47.7 System connection

NoteWhat the system gained in this chapter

The system can now say what a component does in a way that supports design. We have the four-step paradigm, an analytic route from noise level and threshold to false alarm rate, a measurement route to detection and localisation, and a report format.

One component is rarely the whole system. The output of the edge detector goes to a line fitter, which goes to a measurement stage. How does the error of the first stage appear in the last? Chapter 48 propagates the perturbation through a pipeline.

Chapter summary

  • Characterisation describes behaviour as a function of input condition and parameters.
  • The four steps: input and perturbation model, algorithm and parameters, output distribution, validation.
  • For the step-edge detector: \(\sigma_D^2=2\sigma^2/w\), \(P_{\text{FA}}=2Q(\tau/\sigma_D)\), detection depends on \(h/\sigma_D\).
  • Window width trades noise rejection for resolution.
  • Report the whole curve, with definitions, ranges and confidence.

  2. Compute. With \(\sigma_D=0.5\) and \(\tau=1.5\), give the probability that an edge of height \(2\) is detected at its true position.
  3. Derive. Prove Equation 47.2. State the independence assumption you used.
  4. Derive. For a signal of \(N\) samples and per-sample false alarm probability \(p\), give the probability of at least one false alarm if samples were independent. Why is this an upper bound for the filter output?
  5. Code. Repeat Figure 47.2 with Laplace noise of the same variance. Does the false alarm rate still match the Gaussian design value?
  6. Code. Add the median filter (window \(w\)) before Equation 47.1. Measure the detection curve at the same false alarm rate.
  7. Code. Plot the detection probability against \(w\) for a fixed height \(h=2\) and fixed false alarm rate. Is there a best \(w\)?
  8. Diagnose. A team reports “98% edge detection accuracy”. List four items needed before the number can be compared with another team’s.
  9. Explain. Why is it better to set the threshold from a false alarm requirement than to set it by maximising accuracy on a test image set?
