14  Loss Functions

NoteKey ideas
  • The loss is the only definition of “good” that the model ever sees. The model minimises it exactly, not what we meant.
  • Squared error is minimised by the mean. Absolute error is minimised by the median, and is robust to outliers. Huber blends the two.
  • Cross-entropy is the standard loss for classes. Its gradient with respect to the logit is \(p-y\), and it does not saturate when the model is confidently wrong.
  • Contrastive and triplet losses shape a space so that distance means similarity.
  • A low loss is not the same as a good metric. Check both.

14.1 The system problem

The model has parameters \(\theta\). Learning changes them to make one number smaller. That number is the loss. Chapter 13 measured how similar two inputs are. We now measure how wrong a prediction is.

A loss is the only definition of “good” that the model sees. How do we write one that matches what we actually want?

14.2 Regression losses

Let \(e=\hat{y}-y\) be the error. Three standard choices:

Absolute (MAE) \(\lvert e\rvert\) \(\text{sign}(e)\) every error pulls equally

14.2.1 What each loss estimates

For data \(y_1,\dots,y_N\) and a constant prediction \(c\), the loss is \(\sum_{i}\ell(c-y_i)\). The minimiser reveals what each loss “wants”.

TipDerivation: MSE gives the mean, MAE gives the median

Squared error. \(\frac{d}{dc}\sum_i(c-y_i)^2=2\sum_i(c-y_i)=0\) gives \(c=\frac1N\sum_iy_i\): the mean.

Absolute error. \(\frac{d}{dc}\sum_i|c-y_i|=\#\{y_i<c\}-\#\{y_i>c\}\). The derivative is zero when as many points lie below \(c\) as above it: \(c\) is the median. \(\blacksquare\)

The mean moves with every outlier. The median hardly moves. We test this.

rng = np.random.default_rng(0)
y = rng.normal(10.0, 1.0, size=99)
y_out = np.append(y, 1000.0)                    # one huge outlier

for name, data in [("clean", y), ("with one outlier", y_out)]:
    c = np.linspace(8, 25, 6801)
    mse_best = c[np.argmin([np.sum((ci - data) ** 2) for ci in c])]
    mae_best = c[np.argmin([np.sum(np.abs(ci - data)) for ci in c])]
    print(f"{name:18s} MSE minimiser {mse_best:6.2f}  (mean {data.mean():6.2f})   "
          f"MAE minimiser {mae_best:6.2f}  (median {np.median(data):6.2f})")
clean              MSE minimiser  10.10  (mean  10.10)   MAE minimiser  10.10  (median  10.09)
with one outlier   MSE minimiser  20.00  (mean  20.00)   MAE minimiser  10.10  (median  10.10)

14.2.2 Quantile (pinball) loss: the loss says what you care about

Costs are often asymmetric. Running out of stock costs more than holding extra. The pinball loss with level \(\tau\in(0,1)\) is

\[ \ell_\tau(e)=\begin{cases}\tau\,|e|&e<0\ \text{(under-prediction)}\\(1-\tau)\,|e|&e\ge0\ \text{(over-prediction)}\end{cases} \tag{14.1}\]

Its minimiser is the \(\tau\)-quantile of the data. For \(\tau=\frac12\) it is the median.

def pinball(c, data, tau):
    e = c - data                                   # prediction minus truth
    return np.sum(np.where(e < 0, tau * -e, (1 - tau) * e))

data = rng.exponential(2.0, size=2000)
cs = np.linspace(0, 10, 2001)
for tau in [0.1, 0.5, 0.9]:
    best = cs[np.argmin([pinball(c, data, tau) for c in cs])]
    print(f"tau = {tau}: minimiser {best:5.2f}   empirical quantile {np.quantile(data, tau):5.2f}")
tau = 0.1: minimiser  0.21   empirical quantile  0.21
tau = 0.5: minimiser  1.38   empirical quantile  1.38
tau = 0.9: minimiser  4.59   empirical quantile  4.60

Choosing \(\tau=0.9\) gives a forecast that is too high only 10% of the time. The loss encodes the cost structure.

14.2.3 Outliers in a line fit

We fit a line to data with 6 corrupted points. We use SciPy’s generic optimiser. (We study optimisation in Chapter 19.)

from scipy.optimize import minimize

rng = np.random.default_rng(3)
x = rng.uniform(-2, 2, 40)
y = 2 * x + 1 + rng.normal(0, 0.3, 40)
y[:6] += rng.uniform(8, 12, 6)                         # outliers

def fit(loss):
    f = lambda t: np.sum(loss(t[0] * x + t[1] - y))
    return minimize(f, x0=[0.0, 0.0], method="Nelder-Mead",
                    options={"xatol": 1e-6, "fatol": 1e-9, "maxiter": 4000}).x

hub = lambda e, d=1.0: np.where(np.abs(e) <= d, 0.5 * e ** 2, d * (np.abs(e) - d / 2))
fits = {"squared": fit(lambda e: e ** 2), "absolute": fit(np.abs), "Huber": fit(hub)}
for k, (a, b) in fits.items():
    print(f"{k:9s} slope {a:5.2f}  intercept {b:5.2f}   (truth 2.00, 1.00)")

fig, ax = plt.subplots(figsize=(6, 4))
ax.scatter(x[6:], y[6:], s=14, color=PALETTE["data"]); ax.scatter(x[:6], y[:6], s=30, color="black", label="outliers")
xs = np.linspace(-2, 2, 50)
for (k, (a, b)), col in zip(fits.items(), [PALETTE["loss"], PALETTE["data"], PALETTE["grad"]]):
    ax.plot(xs, a * xs + b, color=col, lw=2, label=k)
ax.legend(); ax.set_xlabel("x"); ax.set_ylabel("y")

14.3 Classification losses

For classes, the natural loss is the 0–1 loss: 1 if wrong, 0 if right. Its gradient is zero almost everywhere, so it cannot guide learning. We need a smooth stand-in.

14.3.1 Margin view

For a binary label \(y\in\{-1,+1\}\) and a score \(z\), the margin is \(m=yz\). Positive margin means correct. Common surrogates are functions of \(m\):

Loss Formula
0–1 \(\mathbb{1}[m\le0]\)
Hinge \(\max(0,1-m)\)
Logistic (cross-entropy) \(\ln(1+e^{-m})\)
Squared \((1-m)^2\) 
m = np.linspace(-2, 3, 400)
fig, ax = plt.subplots(figsize=(6, 3.4))
ax.plot(m, (m <= 0).astype(float), label="0–1", color="black")
ax.plot(m, np.maximum(0, 1 - m), label="hinge", color=PALETTE["data"])
ax.plot(m, np.log1p(np.exp(-m)) / np.log(2), label="logistic (bits)", color=PALETTE["model"])
ax.plot(m, (1 - m) ** 2, label="squared", color=PALETTE["loss"])
ax.set_ylim(-0.1, 4); ax.set_xlabel("margin m = y·z"); ax.legend()

14.3.2 Cross-entropy

For \(K\) classes, the model outputs scores (logits) \(\mathbf{z}\), which become probabilities \(\mathbf{p}\) by the softmax (Chapter 24). The cross-entropy loss for true class \(c\) is

\[ \ell_{\text{CE}}=-\ln p_c. \tag{14.2}\]

It is small when the model gives the correct class a high probability, and it grows without bound as that probability goes to \(0\). The justification comes in two steps: Chapter 15 defines cross-entropy as a measure of coding cost, and Chapter 25 shows that minimising it is maximum likelihood.

For one logit \(z\) and a binary label \(y\in\{0,1\}\), with \(p=\sigma(z)\), its gradient with respect to the logit is

\[ \frac{\partial\ell_{\text{CE}}}{\partial z}=p-y. \tag{14.3}\]

This was derived in Chapter 18. It is the key to why cross-entropy trains well. We compare with squared error applied to the probability.

z = np.linspace(-8, 6, 500)
p = 1 / (1 + np.exp(-z))
grad_ce = np.abs(p - 1)                              # |p - y| with y = 1
grad_mse = np.abs(2 * (p - 1) * p * (1 - p))         # d/dz (p - y)^2
fig, ax = plt.subplots(figsize=(6, 3.4))
ax.plot(z, grad_ce, color=PALETTE["grad"], lw=2, label="cross-entropy")
ax.plot(z, grad_mse, color=PALETTE["loss"], lw=2, label="squared error on p")
ax.axvspan(-8, -3, color="#00000010"); ax.text(-7.5, 0.7, "confidently wrong", fontsize=9)
ax.set_xlabel("logit z  (true label y = 1)"); ax.set_ylabel("|∂ℓ/∂z|"); ax.legend()
plt.show()
print(f"at z = -6: cross-entropy gradient {grad_ce[np.argmin(np.abs(z + 6))]:.3f}, "
      f"squared-error gradient {grad_mse[np.argmin(np.abs(z + 6))]:.4f}")
at z = -6: cross-entropy gradient 0.998, squared-error gradient 0.0049

14.4 Losses that shape a space

Sometimes there are no labels for single inputs. We only know which items are similar and which are different. The loss must then act on a distance in an embedding space.

Contrastive loss (a pair, with \(y=1\) for similar and \(0\) for different, and margin \(m\)):

\[ \ell=y\,d^2+(1-y)\,\max(0,\,m-d)^2. \tag{14.4}\]

Triplet loss (an anchor \(a\), a positive \(p\) of the same class, a negative \(n\) of another class):

\[ \ell=\max\bigl(0,\ d(a,p)^2-d(a,n)^2+m\bigr). \tag{14.5}\]

The triplet loss is zero when the positive is closer than the negative by at least the margin \(m\). Otherwise it pulls \(a\) and \(p\) together and pushes \(a\) and \(n\) apart.

14.4.1 An experiment: learning to ignore noise

Each example has four features. Two are informative (class centres differ). Two are pure noise with a large spread. A linear map \(\mathbf{W}:\mathbb{R}^{4}\to\mathbb{R}^2\) is learned with the triplet loss.

import torch
from sklearn.neighbors import KNeighborsClassifier

rng = np.random.default_rng(0)
def make(n):
    centres = np.array([[0, 0], [3, 0], [1.5, 2.6]])
    y = rng.integers(0, 3, n)
    signal = centres[y] + rng.normal(0, 0.7, (n, 2))
    noise = rng.normal(0, 4.0, (n, 2))               # large, uninformative
    return np.hstack([signal, noise]).astype(np.float32), y

Xtr, ytr = make(600); Xte, yte = make(600)
raw_acc = KNeighborsClassifier(5).fit(Xtr, ytr).score(Xte, yte)

def sample_triplets(y, m, gen):
    a = gen.integers(0, len(y), m); p = np.empty(m, int); n = np.empty(m, int)
    for i, ai in enumerate(a):
        p[i] = gen.choice(np.where(y == y[ai])[0])
        n[i] = gen.choice(np.where(y != y[ai])[0])
    return a, p, n

torch.manual_seed(0); gen = np.random.default_rng(1)
W = torch.nn.Parameter(torch.randn(4, 2) * 0.3)
Xt = torch.tensor(Xtr); loss_hist = []
opt = torch.optim.SGD([W], lr=0.02)
for step in range(1500):
    a, p, n = sample_triplets(ytr, 128, gen)
    Z = Xt @ W
    d_ap = ((Z[a] - Z[p]) ** 2).sum(1)
    d_an = ((Z[a] - Z[n]) ** 2).sum(1)
    loss = torch.relu(d_ap - d_an + 1.0).mean()      # margin m = 1
    opt.zero_grad(); loss.backward(); opt.step()
    loss_hist.append(loss.item())

Wn = W.detach().numpy()
learned_acc = KNeighborsClassifier(5).fit(Xtr @ Wn, ytr).score(Xte @ Wn, yte)
print(f"5-NN test accuracy, raw 4-D features : {raw_acc:.3f}")
print(f"5-NN test accuracy, learned 2-D space: {learned_acc:.3f}")
print("rows of W (features 1-4):\n", np.round(Wn, 2))
5-NN test accuracy, raw 4-D features : 0.927
5-NN test accuracy, learned 2-D space: 0.958
rows of W (features 1-4):
 [[ 0.47  0.45]
 [-0.48  0.45]
 [-0.01 -0.01]
 [-0.   -0.02]]
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(9, 3.2))
ax1.plot(loss_hist, color=PALETTE["loss"]); ax1.set_xlabel("step"); ax1.set_ylabel("triplet loss")

14.5 A good loss is not a good metric

The loss is what we optimise. The metric is what we care about. They differ, and the difference matters. Imbalanced data shows it.

from sklearn.linear_model import LogisticRegression
from sklearn.datasets import make_classification
from sklearn.metrics import accuracy_score, recall_score, log_loss

X, y = make_classification(n_samples=4000, n_features=6, n_informative=3,
                           weights=[0.95, 0.05], class_sep=1.0, random_state=0)
Xa, Xb = X[:2000], X[2000:]; ya, yb = y[:2000], y[2000:]

majority = np.zeros_like(yb)                                    # always predict "negative"
plain = LogisticRegression(max_iter=500).fit(Xa, ya)
weighted = LogisticRegression(max_iter=500, class_weight="balanced").fit(Xa, ya)

print(f"{'model':24s} {'accuracy':>9s} {'recall of rare class':>21s}")
print(f"{'always predict majority':24s} {accuracy_score(yb, majority):9.3f} "
      f"{recall_score(yb, majority):21.3f}")
for name, m in [("logistic, unweighted", plain), ("logistic, class-weighted", weighted)]:
    pr = m.predict(Xb)
    print(f"{name:24s} {accuracy_score(yb, pr):9.3f} {recall_score(yb, pr):21.3f}")
model                     accuracy  recall of rare class
always predict majority      0.949                 0.000
logistic, unweighted         0.949                 0.000
logistic, class-weighted     0.723                 0.794

A model that ignores the rare class scores about 95% accuracy. The class-weighted loss gives a lower accuracy and a far higher recall for the rare class. Which one is “better” depends on the task, such as fraud or disease detection. The loss should match the cost of each kind of mistake.

14.6 Production

PyTorch has these losses ready. We check that they match our formulas.

import torch.nn as nn
import torch.nn.functional as F

rng = np.random.default_rng(0)
yh = torch.tensor(rng.normal(size=20)); yt = torch.tensor(rng.normal(size=20))
e_t = yh - yt
print("MSE   :", np.allclose(nn.MSELoss()(yh, yt).item(), (e_t ** 2).mean().item()))
print("MAE   :", np.allclose(nn.L1Loss()(yh, yt).item(), e_t.abs().mean().item()))
hub_t = torch.where(e_t.abs() <= 1, 0.5 * e_t ** 2, e_t.abs() - 0.5)
print("Huber :", np.allclose(nn.HuberLoss(delta=1.0)(yh, yt).item(), hub_t.mean().item()))

logits = torch.tensor(rng.normal(size=(8, 5))); target = torch.tensor(rng.integers(0, 5, 8))
p = torch.softmax(logits, dim=1)
manual = -torch.log(p[torch.arange(8), target]).mean()
print("CE    :", np.allclose(nn.CrossEntropyLoss()(logits, target).item(), manual.item()))

a, pp, nn_ = (torch.tensor(rng.normal(size=(6, 3))) for _ in range(3))
dist = lambda u, v: (u - v).norm(dim=1)               # Euclidean, not squared
manual_t = torch.relu(dist(a, pp) - dist(a, nn_) + 1.0).mean()
lib_t = nn.TripletMarginLoss(margin=1.0, p=2)(a, pp, nn_)
print("Triplet:", np.allclose(lib_t.item(), manual_t.item(), atol=1e-4),
      " (PyTorch uses the unsquared distance)")
MSE   : True
MAE   : True
Huber : True
CE    : True
Triplet: True  (PyTorch uses the unsquared distance)

Note that nn.CrossEntropyLoss takes logits and applies the log-softmax internally. Passing probabilities is a common bug.

14.7 Failure modes

Optimising the wrong objective. The model satisfies the number, not the intent. A loss that rewards the average can hide failures on a rare group.

Class imbalance. Accuracy and an unweighted loss favour the majority class (shown above).

Saturating gradients. A loss that is flat where the model is wrong gives no signal. Squared error on a sigmoid output is the classic case.

Label noise. Squared error and cross-entropy punish a mislabelled point heavily. Robust losses (MAE, Huber, label smoothing) limit the damage.

Scale of the loss. The loss scale interacts with the learning rate. Multiplying the loss by 100 multiplies all gradients by 100. Compare losses after normalising by batch size.

Reduction. Averaging over a batch and summing over a batch differ by a factor of the batch size. Libraries expose this as reduction="mean" or "sum".

14.9 System connection

NoteWhat the system gained in this chapter

The system can now state what “wrong” means as a number. Different losses encode different goals: mean, median, quantile, class probability, or relative distance. It also learned that the loss is a specification, and that a poor specification gives a model that does the wrong thing very well.

Cross-entropy was used here before it was explained. Chapter 15 gives it a precise meaning, and the same ideas link measurement to probability.

Chapter summary

  • The loss is the model’s only definition of good.
  • MSE gives the mean, MAE the median, pinball the \(\tau\)-quantile. Huber blends MSE and MAE.
  • Cross-entropy is \(-\ln p_c\). Its logit gradient is \(p-y\), which stays large when the model is confidently wrong.
  • Contrastive and triplet losses shape a space by relative distances.
  • A loss is not a metric. Imbalanced data makes this visible.
  • Check scale, reduction, and robustness to noise.
