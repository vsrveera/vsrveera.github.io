5  Matrices: Representing Transformations

NoteKey ideas
  • A matrix is a linear transformation written as a table of numbers.
  • The columns of \(\mathbf{A}\) are the images of the basis vectors. \(\mathbf{A}\mathbf{x}\) is a linear combination of the columns.
  • A matrix product is the composition of transformations. Order matters.
  • The rank counts how many independent directions survive. A rank-deficient matrix collapses space.
  • To solve \(\mathbf{A}\mathbf{x}=\mathbf{b}\), do not form \(\mathbf{A}^{-1}\).

5.1 The system problem

A model must turn one representation into another. A pixel vector becomes a feature vector. A feature vector becomes class scores. We need a general tool that does this in one step and that can be learned.

How does a model turn one vector into another in a single step, and what can that step never do?

The tool is the matrix. A learned matrix is the main kind of parameter in a neural network.

5.2 Intuition: a matrix moves space

Imagine a rubber sheet with a square grid drawn on it. A linear transformation stretches, rotates, shears, or flips the sheet. It obeys two rules:

  • The origin stays where it is.
  • Grid lines stay straight, parallel, and evenly spaced.

Every such transformation is fully described by where it sends the basis vectors. If we know where \(\mathbf{e}_1=(1,0)\) and \(\mathbf{e}_2=(0,1)\) go, we know where every point goes. We write those two images as the columns of a matrix.

th = np.pi / 6
mats = {
    "scale  diag(2, 0.5)":  np.array([[2.0, 0.0], [0.0, 0.5]]),
    "rotate 30°":            np.array([[np.cos(th), -np.sin(th)],
                                       [np.sin(th),  np.cos(th)]]),
    "shear":                 np.array([[1.0, 0.8], [0.0, 1.0]]),
    "reflect over x₂ axis":  np.array([[-1.0, 0.0], [0.0, 1.0]]),
    "project onto x₁":       np.array([[1.0, 0.0], [0.0, 0.0]]),
    "rank 1":                np.array([[1.0, 0.5], [2.0, 1.0]]),
}
fig, axes = plt.subplots(2, 3, figsize=(9, 6))
for ax, (name, A) in zip(axes.ravel(), mats.items()):
    warp_grid(ax, A, title=f"{name}\nrank {np.linalg.matrix_rank(A)}")
plt.tight_layout(); plt.show()

5.3 The mathematical object

A matrix \(\mathbf{A}\in\mathbb{R}^{m\times n}\) is a table with \(m\) rows and \(n\) columns. It defines a function from \(\mathbb{R}^n\) to \(\mathbb{R}^m\):

\[ \mathbf{y}=\mathbf{A}\mathbf{x}, \qquad y_i=\sum_{j=1}^{n}A_{ij}x_j. \tag{5.1}\]

The function is linear: \(\mathbf{A}(a\mathbf{x}+b\mathbf{z})=a\mathbf{A}\mathbf{x}+b\mathbf{A}\mathbf{z}\).

5.3.1 Two ways to read \(\mathbf{A}\mathbf{x}\)

Column view. Write \(\mathbf{A}=[\mathbf{a}_1\ \mathbf{a}_2\ \cdots\ \mathbf{a}_n]\) with columns \(\mathbf{a}_j\). Then

\[ \mathbf{A}\mathbf{x}=x_{1}\mathbf{a}_1+x_{2}\mathbf{a}_2+\dots+x_{n}\mathbf{a}_n. \tag{5.2}\]

The output is a linear combination of the columns, with the input components as coefficients. This is why the columns are “where the basis vectors go”.

Row view. Each output component is a dot product of one row with \(\mathbf{x}\): \(y_i=\mathbf{A}_{i,:}\cdot\mathbf{x}\). Each row measures one feature of the input.

A = np.array([[2.0, 1.0],
              [0.0, 3.0],
              [1.0, -1.0]])             # (3, 2): maps R^2 -> R^3
x = np.array([4.0, 2.0])                # (2,)

col_view = x[0] * A[:, 0] + x[1] * A[:, 1]          # combination of columns
row_view = np.array([A[i] @ x for i in range(3)])   # one dot product per row
print("A @ x      :", A @ x)
print("column view:", col_view)
print("row view   :", row_view)
A @ x      : [10.  6.  2.]
column view: [10.  6.  2.]
row view   : [10.  6.  2.]

5.3.2 Rotation matrices

The column view lets us write down a matrix for any transformation by asking where \(\mathbf{e}_1\) and \(\mathbf{e}_2\) go. For a counter-clockwise rotation by angle \(\phi\):

\[ \mathbf{e}_{1}\mapsto(\cos\phi,\ \sin\phi), \qquad \mathbf{e}_{2}\mapsto(-\sin\phi,\ \cos\phi). \]

Put these two images in the columns:

\[ \mathbf{R}_\phi=\begin{pmatrix}\cos\phi&-\sin\phi\\ \sin\phi&\cos\phi\end{pmatrix}. \tag{5.3}\]

Rotations return in Chapter 32: rotary position embeddings rotate pairs of coordinates by an angle that depends on the token position.

5.4 Operations

5.4.1 Matrix product is composition

Apply \(\mathbf{B}\) first, then \(\mathbf{A}\). The combined map is one matrix, \(\mathbf{A}\mathbf{B}\):

\[ \mathbf{A}(\mathbf{B}\mathbf{x})=(\mathbf{A}\mathbf{B})\mathbf{x}, \qquad (\mathbf{A}\mathbf{B})_{ik}=\sum_jA_{ij}B_{jk}. \tag{5.4}\]

The shapes must chain: \((m,n)\,(n,p)\to(m,p)\). The inner sizes must match.

The product is not commutative. Rotating then shearing differs from shearing then rotating.

R = mats["rotate 30°"]; S = mats["shear"]
fig, axes = plt.subplots(1, 2, figsize=(7.5, 3.6))
warp_grid(axes[0], S @ R, title="shear ∘ rotate   (S @ R)")
warp_grid(axes[1], R @ S, title="rotate ∘ shear   (R @ S)")
plt.tight_layout(); plt.show()
print("S @ R == R @ S :", np.allclose(S @ R, R @ S))
S @ R == R @ S : False

5.4.2 Transpose

The transpose swaps rows and columns: \((\mathbf{A}^{\intercal})_{ij}=A_{ji}\). For a product, the order reverses:

\[ (\mathbf{A}\mathbf{B})^{\intercal}=\mathbf{B}^{\intercal}\mathbf{A}^{\intercal}. \tag{5.5}\]

TipDerivation: the transpose of a product

Take one entry. By the definition of the product and the transpose:

\[ \bigl((\mathbf{A}\mathbf{B})^{\intercal}\bigr)_{ki}=(\mathbf{A}\mathbf{B})_{ik}=\sum_jA_{ij}B_{jk}=\sum_j(\mathbf{B}^{\intercal})_{kj}(\mathbf{A}^{\intercal})_{ji}=(\mathbf{B}^{\intercal}\mathbf{A}^{\intercal})_{ki}. \qquad\blacksquare \]

The transpose is also the way to move a matrix across a dot product: \(\mathbf{a}\cdot(\mathbf{A}\mathbf{b})=(\mathbf{A}^{\intercal}\mathbf{a})\cdot\mathbf{b}\). This is why \(\mathbf{W}^{\intercal}\) appears in backpropagation (Chapter 18).

5.4.3 Inverse

The inverse \(\mathbf{A}^{-1}\) undoes \(\mathbf{A}\): \(\mathbf{A}^{-1}\mathbf{A}=\mathbf{I}\). It exists only for square matrices that do not collapse space.

5.4.4 Rank

The rank of \(\mathbf{A}\) is the number of independent columns. It is the dimension of the set of all outputs. The last panel of Figure 8.6 has rank 1: its second column is a multiple of the first, so the whole plane lands on a line. Information is lost, and no inverse exists.

A_full = np.array([[1.0, 0.0], [0.0, 1.0]])
A_def  = np.array([[1.0, 0.5], [2.0, 1.0]])
for name, M in [("full rank", A_full), ("rank deficient", A_def)]:
    rank, det = np.linalg.matrix_rank(M), np.linalg.det(M)
    print(f"{name:15s} rank = {rank}   det = {det:.2f}")
full rank       rank = 2   det = 1.00
rank deficient  rank = 1   det = 0.00

The determinant of a \(2\times2\) matrix is the signed area of the image of the unit square. A zero determinant means the area collapsed.

5.4.5 Change of basis

In Chapter 3 we solved for coordinates in a skew basis. The basis vectors are the columns of a matrix \(\mathbf{B}\), and the coordinates are

\[ \mathbf{c}=\mathbf{B}^{-1}\mathbf{v}. \tag{5.6}\]

This is the same equation \(\mathbf{B}\mathbf{c}=\mathbf{v}\), solved for \(\mathbf{c}\). Changing the basis is a matrix operation.

5.4.6 Lookup is a matrix product

We can also close the loop on embeddings. The product of a one-hot vector with the embedding matrix selects one row:

rng = np.random.default_rng(0)
V, d = 6, 3
E = rng.normal(size=(V, d))               # embedding matrix (V, d)
t = 4
one_hot = np.eye(V)[t]                    # (V,)
print("one_hot @ E == E[t] :", np.allclose(one_hot @ E, E[t]))
one_hot @ E == E[t] : True

5.5 Computation: from first principles

We write the product with loops. Then we compare with NumPy. The loop version is the definition. The NumPy version is the one we use.

def matmul_loops(A, B):
    m, n = A.shape
    n2, p = B.shape
    assert n == n2, f"inner sizes differ: {n} vs {n2}"
    C = np.zeros((m, p))
    for i in range(m):
        for k in range(p):
            for j in range(n):
                C[i, k] += A[i, j] * B[j, k]
    return C

rng = np.random.default_rng(1)
A, B = rng.normal(size=(40, 50)), rng.normal(size=(50, 30))
assert np.allclose(matmul_loops(A, B), A @ B)
print("loops == NumPy: True")
loops == NumPy: True
sizes = [8, 16, 32, 64, 96]
t_loop, t_np = [], []
for n in sizes:
    A, B = rng.normal(size=(n, n)), rng.normal(size=(n, n))
    t0 = time.perf_counter()
    matmul_loops(A, B)
    t_loop.append(time.perf_counter() - t0)
    t0 = time.perf_counter()
    for _ in range(200): A @ B
    t_np.append((time.perf_counter() - t0) / 200)

fig, ax = plt.subplots()
ax.loglog(sizes, t_loop, "o-", color=PALETTE["loss"], label="Python loops")
ax.loglog(sizes, t_np, "o-", color=PALETTE["grad"], label="NumPy  A @ B")
ax.set_xlabel("matrix size n"); ax.set_ylabel("seconds"); ax.legend()
plt.show()
print(f"speed-up at n={sizes[-1]}: {t_loop[-1] / t_np[-1]:,.0f}x")
speed-up at n=96: 25,631x

A product of \((m,n)\) and \((n,p)\) needs \(mnp\) multiplications and about the same number of additions. Counting these is how we estimate the cost of a model: \(2mnp\) floating-point operations (FLOPs).

5.5.1 Batched products

A matrix product applies the same transformation to many vectors at once. If the rows of \(\mathbf{X}\) are \(B\) input vectors, then \(\mathbf{X}\mathbf{W}^{\intercal}\) transforms all of them in one call. This is the form used in every framework:

B_, n_in, n_out = 4, 5, 3
X = rng.normal(size=(B_, n_in))           # (B, n_in)   rows are inputs
W = rng.normal(size=(n_out, n_in))        # (n_out, n_in)
b = rng.normal(size=n_out)                # (n_out,)

Y = X @ W.T + b                           # (B, n_out)
per_row = np.array([W @ X[i] + b for i in range(B_)])
print("batched == one by one:", np.allclose(Y, per_row), "  shape:", Y.shape)
batched == one by one: True   shape: (4, 3)

5.6 Solving, not inverting

To find \(\mathbf{x}\) in \(\mathbf{A}\mathbf{x}=\mathbf{b}\), the equation suggests \(\mathbf{x}=\mathbf{A}^{-1}\mathbf{b}\). Do not compute it this way. Forming the inverse is slower and less accurate than a direct solver. The problem becomes severe when \(\mathbf{A}\) is nearly singular.

We test this on the Hilbert matrix, a standard ill-conditioned example. The condition number measures how much errors are amplified.

from scipy.linalg import hilbert
ns = list(range(2, 13))
err_solve, err_inv, cond = [], [], []
for n in ns:
    H = hilbert(n)
    x_true = np.ones(n)
    rhs = H @ x_true
    err_solve.append(np.linalg.norm(np.linalg.solve(H, rhs) - x_true))
    err_inv.append(np.linalg.norm(np.linalg.inv(H) @ rhs - x_true))
    cond.append(np.linalg.cond(H))

fig, ax = plt.subplots()
ax.semilogy(ns, err_solve, "o-", color=PALETTE["grad"], label="solve(A, b)")
ax.semilogy(ns, err_inv, "o-", color=PALETTE["loss"], label="inv(A) @ b")
ax.semilogy(ns, [c * 1e-16 for c in cond], "--", color=PALETTE["neutral"],
            label="cond(A) × 1e-16  (expected scale)")
ax.set_xlabel("matrix size n"); ax.set_ylabel("error in x")
ax.legend(fontsize=8)
plt.show()
print(f"n=12: cond = {cond[-1]:.1e}")
n=12: cond = 1.7e+16

The rule of thumb: with condition number \(\kappa\) and machine precision \(\varepsilon\), expect a relative error of about \(\kappa\,\varepsilon\).

5.7 Production: PyTorch

PyTorch uses the same shapes. nn.Linear stores \(\mathbf{W}\) with shape (out, in) and computes \(\mathbf{X}\mathbf{W}^{\intercal}+\mathbf{b}\).

import torch
import torch.nn as nn

lin = nn.Linear(n_in, n_out)
lin = lin.double()                         # match NumPy's float64
with torch.no_grad():
    lin.weight.copy_(torch.tensor(W)); lin.bias.copy_(torch.tensor(b))

Y_t = lin(torch.tensor(X))
print("nn.Linear == X @ W.T + b :", np.allclose(Y_t.detach().numpy(), Y))
print("weight shape:", tuple(lin.weight.shape))
print("bias shape  :", tuple(lin.bias.shape))
print("parameters  :", sum(p.numel() for p in lin.parameters()))
nn.Linear == X @ W.T + b : True
weight shape: (3, 5)
bias shape  : (3,)
parameters  : 18

Note: \(\mathbf{W}\) has \(n_{\text{out}}\times n_{\text{in}}\) entries, and the bias adds \(n_{\text{out}}\) more. A layer of \(4096\to4096\) has \(16.8\) million weights.

5.8 Failure modes

Singular or ill-conditioned matrices. Rank-deficient matrices have no inverse. Nearly rank-deficient ones have a huge condition number and amplify errors. Learned weight matrices can become close to this.

Wrong order or transpose. \(\mathbf{A}\mathbf{B}\ne\mathbf{B}\mathbf{A}\). For square matrices both orders run, and only one is right. Check the shapes of every product (Chapter 2).

Information loss by projection. A layer with \(n_{\text{out}}<n_{\text{in}}\) has rank at most \(n_{\text{out}}\). Whatever lies in the null space is lost. This is intentional in compression and harmful when it removes needed features.

Floating-point accumulation. Summing many products in low precision loses accuracy. Libraries accumulate in higher precision internally. Chapter 34 returns to this.

5.10 System connection

NoteWhat the system gained in this chapter

The system can now move vectors: rotate, stretch, project, and change basis, all in one learnable step. A matrix is the basic parameter of a model. The cost of a model is the cost of its matrix products.

A single matrix is still limited. It cannot bend space. Chapter 6 gathers many vectors into tensors, and Chapter 7 studies the structure inside a matrix: eigenvalues and low rank.

Chapter summary

  • A matrix is a linear transformation. Its columns are the images of the basis vectors.
  • \(\mathbf{A}\mathbf{x}\) is a combination of columns, or one dot product per row.
  • The matrix product is composition. It is not commutative. Shapes chain as \((m,n)(n,p)\to(m,p)\).
  • \((\mathbf{A}\mathbf{B})^{\intercal}=\mathbf{B}^{\intercal}\mathbf{A}^{\intercal}\).
  • Rank counts independent directions. A rank-deficient matrix loses information.
  • Coordinates in a basis are \(\mathbf{B}^{-1}\mathbf{v}\). Lookup is one-hot × table.
  • Solve linear systems. Do not form inverses.
  • A matrix product of \((m,n)(n,p)\) costs \(2mnp\) FLOPs.
